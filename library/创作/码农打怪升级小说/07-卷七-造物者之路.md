## 第十九章 造物者试炼场：手写一个 JVM

大陆禁地深处有一座**造物者试炼场**。规则只有一条：**用过的每一样神器，都要亲手造一遍，才算真正拥有。**

第一场试炼：**造 JVM**。

### 第一步：当"识货人"——解析字节码

造 JVM 的第一课不是执行，是**验货**。

"Java 源码编译出来的 .class 文件，是一张**极严谨的表格**。"试炼官说，"开头四个字节必须是魔数 `0xCAFEBABE`——'咖啡宝贝'，认不出这四个字节，一切免谈。接着是版本号、**常量池（这张类的'户口本'：类名、方法名、字符串常量全在里面）**、字段表、方法表、属性表……每一项都有固定的排布。"

林一码照着规范逐字节解析，当 `javap` 验证输出和自己解析的结果一致时——**他能'读懂'字节码了**。再进一步，把字节码指令集实现一遍（加载、存储、运算、跳转、调用、返回），就是一台**解释器**的心脏。

### 第二步：造"人事部"——类加载器

"类从哪来？**收破烂的活儿交给类加载器**。"试炼官说，"但收之前要**层层上报**：先问父加载器收没收过——这就是你在 Java 大陆学过的**双亲委派**。现在亲手实现它：启动加载器管核心库，扩展加载器管扩展库，应用加载器管你的 classpath。**核心类永远由祖上发放，假冒品进不了门。**"

加载之后是**链接与初始化**：验证（验魔数、验语义）→ 准备（静态变量分配内存给默认值）→ 解析（把符号引用换成真地址）→ 初始化（执行 `<clinit>` 静态块）。

### 第三步：造"楼盘"——运行时数据区

五大分区亲手划出来：堆（对象仓库）、虚拟机栈（栈帧叠盘）、程序计数器（书签）、方法区（档案室）、本地方法栈。**栈帧**要亲手装：局部变量表、操作数栈、动态链接、返回地址。

"操作数栈是 JVM 的灵魂。"试炼官说，"`int a = 1 + 2` 在字节码层面是：把 1 压栈、把 2 压栈、弹两个数相加、结果压栈、赋给 a。**所有运算都是栈上戏法。**"

### 第四步（最难一关）：执行引擎 + GC

**执行引擎**是试炼场公认的最难关：逐条翻译字节码，让第一个 `HelloWorld` 真正跑起来——**方法调用怎么找到目标、栈帧怎么切换、异常表怎么跳转**，三件事打通，才算通关。

然后是**清洁工 GC**：先实现引用计数（发现循环引用清不掉），再改可达性分析（从 GC Roots 顺藤摸瓜），最后上**分代**（Eden 幼儿园 + 晋升机制）。

"最后一问，也是真宗师的问题："试炼官说，"**业务线程跑着的时候，GC 怎么安全地标记和搬移对象、不踩脏数据？** 答案是各种'停顿-标记-恢复'的协议（安全点、三色标记……）。你能把这个问题回答清楚，JVM 试炼就毕业了。"

### 毕业奖励

走出 JVM 试炼场，林一码获得称号：**【知其所以然】**——从此看到 `OutOfMemoryError`、Full GC 日志、类加载异常，不再只有恐惧，而能拆到字节码与内存布局层面。

## 第二十章 手写 Web 容器：从一声铃响到一座写字楼

### 第一夜：一声铃响（BIO）

试炼第二场：**造一个 Tomcat**。

起点朴素得令人发笑——**一行 `ServerSocket`**：

> 监听 8080 端口 → 有人连进来 → accept → **派一个线程**去处理 → 读请求、回响应、关门。

"这就是 **BIO**：一个电话派一个员工。"试炼官说，"先别嫌弃它——**先让它能跑，再让它优雅，最后让它快**。你现在有一个'能处理 HTTP 的服务器'了，虽然它同时只能伺候几十个客人。"

### 第二夜：换前厅（NIO）

客人多了，员工雇不起了——**升级 NIO**：

> 一个 **Selector 前台**盯一整墙监控屏（Channel），哪扇门亮灯（事件就绪）去哪扇。**主从 Reactor**分工：主 Reactor 接客，从 Reactor 干活，业务丢线程池。

这一夜要打三个小 BOSS：**半包粘包**（客人说一半挂断/两句话连成一句——HTTP 解析要做成**状态机**，攒够字节才解析）、**Selector 空轮询**（著名的 NIO 幽灵 bug）、**读写事件与业务线程的边界**。

"**能用**与**生产可用**之间隔着的，就是这些坑。"

### 第三夜：造写字楼（Connector + Container）

有了前厅，开始盖楼：

- **Connector（连接器）**：Endpoint 收连接、Processor 解析 HTTP、Adapter 把请求翻译成规范对象——**接电话的部门**；
- **Container 四层写字楼**：**Engine（总引擎）→ Host（按域名分楼）→ Context（按应用分层）→ Wrapper（每个 Servlet 一间办公室）**——请求顺着管道逐层下沉，每层配 **Pipeline-Valve 管道阀门**（拦截处理）。

### 第四夜：签契约（Servlet 规范）

"容器和应用的握手协议叫 **Servlet**："

> **init**（应用加载时初始化一次）→ **service**（每个请求进来，按 GET/POST 分流 doGet/doPost）→ **destroy**（下线时收尾）。
> 配套设施：**Filter 责任链**（安检层层过）、**Session/Cookie**（餐厅储物柜：Cookie 是客人手上的柜号牌，Session 是柜台里的储物格）。

### 第五夜：隔离术（类加载 + 热部署）

最后一场戏最惊艳：**WebApp 类加载器**。

"两个应用都依赖同一个类的**不同版本**，怎么办？——**每个应用发一个专属类加载器**。同一个类名，A 楼和 B 楼各自加载各自的——**类相等的前提是'同一个类+同一个加载器'**，所以互不串门。"

"**热部署**也水到渠成：应用要重载？**扔掉旧加载器、换新的**——旧类连同旧对象一起被 GC 回收。不重启服务器，版本切换。"

## 第二十一章 手写数据库：听懂 SQL 的第一句话

### 一、听懂人话（协议→词法→语法）

试炼第三场：**造一个迷你 MySQL**。

第一幕是**通信**：TCP 上自定义报文——**3 字节长度 + 1 字节序号**，超长分包。"密信每封标页码，防丢页防插队。"

第二幕是**听懂 SQL**：

> **词法分析**：把 `SELECT name FROM user WHERE age > 18` 切成 Token——SELECT 是关键字、name 是标识符、18 是数字——**先切词**；
> **语法分析**：用**递归下降**把 Token 按文法拼成 **AST（抽象语法树）**——一颗"SELECT 树"，根是查询语句，枝是字段表、来源表、条件——**再画出家谱树**。

当第一句 `SELECT * FROM user` 被正确解析并返回数据时——里程碑达成：**你的数据库听懂人话了。**

### 二、存得住（页、行、B+ 树、缓冲池）

第三幕是**存储引擎**：

- **页（16KB）**为最小装订单位，**行格式**决定一行数据在页里怎么排；
- **B+ 树索引**亲手实现——**最难的一关是节点分裂**：满员车厢半路一分为二、连带父层连锁上裂，**还不能丢一名乘客**；
- **缓冲池**：办公桌（LRU 链表）太小只放热页，**改过的脏页走前必须抄进保险柜**。

### 三、丢不了（WAL 与崩溃恢复）

第四幕是**可靠性**——先记日志再干活：

> **WAL（Write-Ahead Logging）**：先在小本本记下"转一百万给 B"，**凭小本本先落盘**，再去改数据页——停电了，**凭账本重来**。
> **Redo** 保证已提交的重演，**Undo** 保证没提交的撤销。

最后一幕是**崩溃恢复三幕剧**：重启后**分析**（确定恢复范围）→ **重做**（Redo 把已完成的重演）→ **回滚**（Undo 把未完成的撤销）——**像停电后凭账本逐页补账，补完分毫不差。**

再把 **MVCC 版本链**、**锁与死锁检测**补上，一个能 ACID 的迷你数据库就成型了。最后给它配一个**命令行客户端**（类似 mysql CLI 的 REPL），就有了产品形态。

## 第二十二章 手写浏览器与手写消息中间件

### 手写浏览器：把光影机器造出来

试炼第四场：**造浏览器**。七夜工程：

1. **拿网页回家**：Socket 发 HTTP + 实现**强缓存/协商缓存**（304 空手省行李那一课的实物化）；
2. **长出 DOM**：HTML 词法切 Token → 语法树 → **DOM 树**（页面的户口本）；再解析 CSS 造 **CSSOM**，合体成渲染树；
3. **布局（最难一关）**：**盒模型**逐个量尺寸——改一个 width，祖先层层连坐重算，**回流的多米诺骨牌**必须算得又准又快；
4. **绘制与合成**：分层、GPU 拼贴上屏；
5. **跑起 JS**：实现**事件循环**（先清微任务再取宏任务）、DOM 操作接口；
6. **拆分进程**：每标签页一艘水密舱 + IPC 通信——**一个 Tab 崩了，浏览器不倒**；
7. **设门禁**：**同源策略**（协议+域名+端口差一个字都算外人）+ XSS 消毒。

### 手写消息中间件：造一座邮政总局

试炼第五场：**造 MQ**。工程主线：

> **定消息结构**（信封：ID/路由键/TTL/优先级 + 信纸 payload）
> → **CommitLog 追加落盘**（里程碑：消息死不了——只追加不修改，顺序写）
> → **Exchange + Binding 路由**（里程碑：信分对门——direct/fanout/topic 三种分信规则）
> → **ACK 签收**（签收才销单）+ **重投与幂等**（最难一关：指数退避+去重登记本）
> → **死信队列**（失物仓库，信封上贴死因）
> → **主从复制**（司令部备份名册）
> → **心跳与脑裂仲裁**（终点：**砍断一半网络，集群仍活着**——数人头，过半者胜，少数派缴械）。

"亲手造一遍 MQ，你在 Kafka 之谷学的一切就长在了骨头里。"试炼官说。

## 第二十三章 最古老的试炼：手写操作系统 + 手写游戏引擎

### 从一粒电火花开始

终极试炼：**造一个操作系统**——用最古老的方式，体验代码大陆的创世。

> **第 0 天**：上电。BIOS 大钟敲响，管家自检完毕，去硬盘第一个扇区找接班人。
> **第 1 天**：写 MBR——**510 字节**，末尾刻上 `0x55AA` 暗号。黑屏上打出你自己的第一个 "Hello OS"——**世界因你而亮**。
> **第 2 天**：MBR 交棒 Loader：查内存地图（E820）、开 A20 地址线、建 **GDT**，然后纵身一跃（far jump）——**进入保护模式**：从 1MB 小县城搬进 4GB 大京城，Ring0 王座与 Ring3 平民证分权而立。
> **第 3 天**：建 **IDT 中断表**——256 个门牌，钟声（时钟中断）、敲门声（键盘中断）各有去处；**主厨颠勺时服务员随时拍肩：'3 号桌催单！'**
> **第 4 天**：**进程**——PCB 档案袋装下寄存器快照，**时间片轮转调度**：班主任每 10 分钟收走一个学生的课本并记好页码，发给下一位。**上下文切换**是最难一关——把 CPU 的'灵魂'原样封存再唤醒另一个，**错一字节，当场崩溃**。
> **第 5 天**：**文件系统**与 **VFS** 统一接口；**syscall** 窗口开张——平民终于能合法递单子。
> **终章**：跑起你的第一个用户程序。

"造完 OS，你再看 Linux 山脉的一切——进程、虚拟内存、中断、文件——**全都不再是名词，而是你亲手拧过的螺丝。**"

### 附场：手写游戏引擎（时间的心跳）

造物者的附场试炼是**游戏引擎**——它教的是"**如何让世界按时运转**"：

- **游戏循环是心跳**：`处理输入 → update → render` 循环往复；物理用**固定时间步长**+插值渲染，并**钳制最大帧时间**防"死亡螺旋"（越卡越追帧、越追越卡）——**不管世界多卡，心脏的节拍不能乱**；
- **ECS 架构**：Entity 只是 ID（空盒子）、Component 是纯数据（零件）、System 是纯逻辑（说明书）——**别造"会飞的鱼"这种继承怪，把"会飞""会游"当零件随插随拔**；
- **渲染管线是后厨**：CPU 备菜（裁剪/排序/合批）、GPU 炒菜（着色器）、摆盘出餐（深度测试/混合）；
- **网络同步两条路**：**状态同步**——服务器权威只发位置速度，客户端插值（看直播画面）；**帧同步**——只互发输入、各家本地确定性模拟（各摆棋盘、只传棋谱）。

"你会发现：**游戏引擎的帧循环、浏览器的消息循环、操作系统的调度循环、Redis 的事件循环——是同一个思想在不同世界的化身：事件驱动 + 分时复用。**"老码说，"造物者之境的最后一步，是**看见这种跨领域的同构**。"

## 特别篇 · 终极答辩：混沌先遣队来袭

> 造物者试炼场的最终考题，从来不是"你造了什么"，
> 而是——"**当它被打的时候，会发生什么**"。
> ——试炼场石碑背面

### 考题：七件神器，一夜合体

七场试炼全部通关的那晚，试炼官没有颁发证书，而是拉下了试炼场的天幕——**混沌先遣队**提前来了。

"最终考题：把你在试炼场造的七件神器——**Web 容器、JVM、数据库、缓存、消息中间件、限流闸机、监控台**——组装成一个完整系统。"试炼官指着远处逼近的黑雾，"然后，用自己的系统，**挡住混沌先遣队的攻击**。造物者证书，黑雾散尽之日颁发。"

### 第一波：DDoS 洪流

第一波攻击来得毫无花巧——**百万级无意义请求**，直扑 Web 容器。

"有限流闸机！"小蝶喊。

"闸机是造了——"林一码盯着监控，脸色发白，"**但我把它放在了业务代码里！** 攻击流量已经先一步打穿了 NIO 前厅——Selector 线程全在解析攻击者的畸形报文，业务根本没到限流那一层！"

"**记住这一课：限流必须放在流量进门的第一个阀门**——容器层、网关层，而不是业务层。"老码抢过操作台，把限流器挂上 Connector 前面，漏桶收口，"**防御的位置错了，再好的防御也是马奇诺防线**。"

### 第二波：慢查询毒药

洪流被挡住，先遣队换了打法——**少量请求，每个都携带最毒的查询**：全表扫描、深分页、LIKE 前置通配。

数据库的缓冲池办公桌瞬间被"毒页"占满，LRU 链表被搅成一锅粥。

"我们的手写数据库**没有查询超时**！"老龟魂飞魄散地冲进来（他来试炼场观摩），"毒查询可以跑一整晚！"

"上**查询执行预算**！"林一码吼回去，"执行器每跑一步检查一次预算——**超预算就杀**！再给 B+ 树扫描加上'单查询触达页数上限'——**这是数据库给自己的保命符：任何请求，都不许无限占用公共资源**。"

防线重启。毒查询一只只撞在预算墙上碎掉。

### 第三波：内鬼

最难防的一波，从内部来——先遣队伪装成正常用户，**只发合法请求，但频率极高**，专打系统的**隐含假设**：

- 打爆**无界队列**：日志队列、通知队列疯狂堆积——上界，满了就丢弃+计数告警；
- 打爆**重试风暴**：让下游假死，触发全量用户重试——**退避重试 + 重试预算**（超预算直接失败，**别让每个用户都成为压垮自己的最后一根稻草**）;
- 打爆**缓存击穿**：精准过期所有热点 key——**互斥重建 + 逻辑过期**（Redis 国学的招，第一次真刀真枪用上）。

凌晨四点，第七波攻击退去。试炼场的天空露出一线晨光——**系统还活着**。

### 颁证

试炼官走进大殿，手里拿着的却不是证书，而是一面镜子。

"造物者证书，就是**你能从自己的系统里看见什么**。"他说，"看吧。"

林一码走上前。镜子里，不再是那一台台孤立的"神器"——而是一个**活着的、有呼吸节律的系统**：心跳（时钟与时序）、呼吸（缓冲池与缓存）、血脉（消息队列）、免疫（限流熔断）、记忆（存储与日志）……

"**造物者的最高境界，不是造出器官，而是造出生命**——器官们会互相拖累，生命却能自我修复。"试炼官把刻着"LV25"的徽章按在他肩上，"去吧。下一站，云之塔。**学习让生命学会飞行。**"

**【本场掉落】**：限流的正确位置（入口层）、查询执行预算、无界队列之殇、重试预算、击穿互斥重建、从"器官"到"生命"的系统观。

## 特别篇 二 · 分裂之夜：B+ 树的两千万分之一次考验

> 手写数据库试炼的第 39 夜，试炼官宣布了终极考题：
> **"给你的 B+ 树灌入两千万行。它活着，你毕业；
> 它在半路撒了一行数据，重新来过。"**
> ——试炼场·残酷备忘录

### 平静的崩溃前夜

前 1900 万行，风平浪静。林一码的 B+ 树三层小楼住得井井有条：索引节点指路，叶子串链，插入永远是"找到叶子 → 放进去"两步。

第 19,743,182 行，异变陡生——**最底层的叶子页满了**。

"分裂。"林一码深吸一口气。他早就写好了分裂逻辑：**满员车厢一分为二，中间的"分界钥匙"晋升给父节点**。

代码跑了。新行落位。看起来——**成功了**。

### 第一个隐藏关卡：父也满了

十行之后，父节点也满了。**分裂向上传染**：父一分为二，分界钥匙再晋升——**祖父也得接**。

而林一码的代码里，分裂只做了一层。祖父收不下那把钥匙——**B+ 树卡死了**。

"**递归分裂。**"试炼官在旁边淡淡提醒，"**裂的不是车厢，是整条铁路的调度表。**"

改。分裂改成**循环向上**：孩子裂了，钥匙插进父亲；父亲也满了，继续裂、继续晋升——**直到某个祖先接得住，或者一路裂到根**。**根裂了怎么办？——整棵树长高一层：老根一分为二，新根接管两把钥匙。树高+1，三层楼变四层。**

### 第二个隐藏关卡：并发之刃

递归分裂修好，灌到 2100 万行，试炼官又扔来新考题：**八个线程同时插入。**

十秒后，两片叶子同时发现自己"满了"，**各自分裂**——但它们是**同一个父节点**的两个孩子，父节点被并发改坏，**一行数据凭空蒸发**。

"**分裂不是原子操作。**"试炼官说，"**'锁定父节点 → 改孩子 → 更新父节点'三步之间，任何线程插进来，树就脏了。**"

解法是教科书级的**锁协议**：

> **1 · 螃蟹式加锁（Latch Crabbing）**：从根往下走，**先锁孩子、再放父亲**——像螃蟹横着挪，永远有一只钳子抓着稳定的一格；
> **2 · 分裂路径保守锁**：走的路径若"可能引发分裂"，**提前把父亲也锁上**（保守但正确）；检测到"确实不需要分裂"再放宽——**悲观锁保正确，乐观检测保性能**；
> **3 · 记住术语分寸**：保护内存结构的短锁叫 **Latch（闩）**，保护事务的长锁叫 **Lock（锁）**——**两套体系，两种寿命，别混着用**。

### 第三个隐藏关卡：崩溃的那一瞬

最后一夜，试炼官直接**拔电源**。

重启后检查：2100 万行，**每一行都在，一行不多，一行不少**。

林一码愣了三秒才反应过来——**WAL 在护体**：分裂的每一步"结构性改动"也写进了日志，重启后**按日志重放或回滚**，树的结构和数据的账本一样，**先记账、再动工**。

"你通过了。"试炼官第一次露出笑意，"**灌数据只是走个形式。今晚真正毕业的，是你对三个问题的回答：
> 数据怎么排？（分裂与递归）
> 并发怎么活？（锁协议）
> 断电怎么办？（WAL 护体）**
> 这三个问题，就是所有存储引擎——MySQL、Redis、Kafka、你的数据库——**共同的灵魂三问。**"

### 尾声

走出试炼场时天已蒙蒙亮。林一码回头看着那棵自己亲手种下的、四层楼高的 B+ 树，忽然明白了一件事：

> **课本上的"B+ 树"是一个名词。
> 你手上的 B+ 树，是两千多万次"放进去、裂开来、锁住它、记下账"的总和。
> 知识只有变成肌肉记忆，才算是你的。**

**【本场掉落】**：递归分裂与树高生长、Latch Crabbing 锁协议、Latch 与 Lock 之辨、结构改动的 WAL 记账、存储引擎灵魂三问。
