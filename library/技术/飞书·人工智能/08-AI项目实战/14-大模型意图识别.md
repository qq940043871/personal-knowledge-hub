# 企业大模型平台客户意图识别落地方案（快+准）
## 一、方案目标
1. 速度目标：常规意图识别≤30ms，规则命中≤5ms，大模型兜底≤300ms，满足企业内部高频问答响应需求；
2. 精度目标：常规业务意图识别准确率≥95%，模糊口语/省略句≥90%，意图路由错误率≤3%；
3. 成本目标：大模型意图识别调用占比≤10%，大幅节省Token与算力消耗；
4. 落地目标：7天完成基础部署，14天完成样本迭代，30天实现稳定运行，适配企业多部门、多知识库、多权限场景。

## 二、核心架构落地（四层分层识别，必落地）
### 架构整体链路
用户输入 → 输入预处理 → 规则引擎拦截 → 轻量小模型识别 → 大模型兜底 → 意图路由（RAG/业务系统）→ 结果返回
（全程闭环，每一层均有拦截、校验、降级机制，优先保证快和准）

### （一）第一层：输入预处理模块（落地优先级：最高，1天完成）
#### 1. 部署范围
集成在用户输入入口，作为意图识别的前置环节，毫秒级完成清洗归一。

#### 2. 核心落地内容
| 功能 | 具体落地操作 | 工具/脚本 | 预期效果 |
| --- | --- | --- | --- |
| 文本归一 | 1. 去除多余空格、标点、换行、语气词（哦、呢、啊等）；2. 繁体转简体、大写转小写；3. 过滤特殊符号、乱码、纯表情 | Python脚本（正则匹配+字符串处理） | 统一输入口径，减少意图识别干扰 |
| 企业词库映射 | 1. 梳理企业内部简称、行话、口语，建立《企业意图同义词典》；2. 配置自动替换规则，例：打不上卡→考勤异常、OA→办公系统、请假→申请休假、报销→费用报销 | 自定义词典（JSON格式）+ 词库匹配脚本 | 相同意图的不同话术，收敛为统一句式，提升后续识别准确率 |

+ 词库需同步企业各部门，收集行政、人事、IT、财务等核心业务的常用简称，避免遗漏；
+ 脚本部署在本地服务器，无需调用外部接口，保证毫秒级响应。

### （二）第二层：规则引擎模块（落地优先级：高，2天完成）
#### 1. 部署范围
预处理之后，轻量模型之前，作为高频、固定意图的核心拦截层。

#### 2. 核心落地内容
##### （1）规则分类及配置（按企业业务场景定制）
| 规则类型 | 适用意图 | 配置方式 | 示例 |
| --- | --- | --- | --- |
| 关键词组合规则 | 明确业务意图（请假、报销、考勤、密码重置） | 关键词+逻辑判断（AND/OR） | 请假：包含“请假”“休假”“请事假”“请病假”；报销：包含“报销”“费用”“报账”+ 包含“发票”“单据” |
| 正则匹配规则 | 指令类、系统操作类意图 | 正则表达式匹配 | 密码重置：匹配“重置密码”“密码找回”“修改密码”；退出对话：匹配“退出”“结束”“关闭对话” |
| 白名单规则 | 固定问候、闲聊意图 | 白名单话术匹配 | 问候：“你好”“您好”“在吗”；闲聊：“今天天气”“吃饭了吗”（直接拦截，返回标准回复） |
| 权限关联规则 | 敏感意图、部门专属意图 | 结合用户权限+关键词 | 董事长薪资查询：包含“董事长”+“薪资”+ 用户角色为“高管”（非高管直接拦截） |

##### （2）规则引擎部署
+ 工具选型：优先选用轻量规则引擎（如Redis Rules、Easy Rules），适配本地私有化部署，无需复杂配置；
+ 规则存储：规则统一存入本地数据库，按业务模块分类（行政、人事、IT等），支持在线编辑、实时生效；
+ 拦截逻辑：命中任意规则，直接返回意图结果+路由指令，不进入后续模型链路。

#### 3. 落地注意事项
+ 优先覆盖60%以上的高频固定意图，减少模型调用；
+ 规则需定期更新（每月1次），同步业务流程变更（如新增审批类型）。

### （三）第三层：轻量小模型意图分类模块（落地优先级：中，3天完成）
#### 1. 部署范围
规则引擎未命中的模糊、口语、复杂问句，作为意图识别的核心层，兼顾快和准。

#### 2. 核心落地内容
##### （1）模型选型与部署（适配企业私有化）
| 选型维度 | 推荐方案 | 落地操作 |
| --- | --- | --- |
| 模型选择 | 优先：bert-small（中文微调版）、roberta-tiny；国产替代：华为盘古tiny、百度ERNIE 3.0 tiny | 1. 下载预训练模型，部署在本地GPU/CPU服务器；2. 对模型进行INT8量化压缩，降低推理耗时，提升并发能力 |

##### （2）模型训练与优化（核心：提升准确率）
1. 样本准备：收集企业近3个月历史问答数据（至少1000条），按意图标签标注，示例：

| 用户提问 | 意图标签 | 槽位信息 |
| --- | --- | --- |
| 技术部怎么申请事假3天 | apply_leave | dept=技术部，type=事假，days=3 |
| 报销发票需要哪些材料 | expense_reimbursement | type=发票，need=材料 |

2. 标签体系建立（少而精，避免泛滥）：
    - 一级标签（6个）：RAG知识查询、业务办理、系统操作、闲聊、指令、报错咨询
    - 二级标签（30个以内）：apply_leave（请假）、expense_reimbursement（报销）、attendance_abnormal（考勤异常）、password_reset（密码重置）等
3. 模型微调：用标注样本对预训练模型进行微调，迭代3-5轮，确保验证集准确率≥95%；
4. 槽位抽取：同步训练槽位抽取能力，提取提问中的关键参数（时间、部门、事项、数量），输出结构化结果。

##### （3）输出格式标准化（便于下游路由）
固定JSON输出格式，确保下游RAG、业务系统可直接调用：

```json
{
  "intent": "apply_leave",  // 意图标签（二级标签）
  "intent_level1": "business_handle",  // 一级标签
  "confidence": 0.96,  // 置信度（0-1）
  "slots": {
    "dept": "技术部",
    "type": "事假",
    "days": 3
  },
  "route": "hr_rag",  // 路由方向（HR知识库RAG）
  "is_confident": true  // 是否置信（置信度≥0.7为true）
}
```

#### 3. 落地注意事项
+ 样本标注需贴合企业真实话术，包含口语、省略句、反问句（如“我能请病假吗？”）；
+ 模型微调后，部署灰度测试，观察1-2天，优化置信度阈值（建议0.7）。

### （四）第四层：大模型兜底模块（落地优先级：中，1天完成）
#### 1. 部署范围
仅用于小模型置信度＜0.7的长尾、极复杂问题，不参与常规意图识别，控制调用成本。

#### 2. 核心落地内容
##### （1）调用场景限制（仅以下2种场景）
1. 小模型输出置信度＜0.7，且无匹配规则；
2. 跨领域、多意图混合、极复杂开放式问题（如“技术部请假流程和报销流程有什么区别，需要哪些材料”）。

##### （2）轻量化调用（节省Token+提升速度）
1. 提示词极简设计（仅聚焦意图识别，不做冗余生成）：

```plain
角色：企业意图识别助手，仅识别用户提问的核心意图，不做多余回复。
任务：根据用户提问，从以下意图标签中选择唯一最匹配的标签（无匹配则选“other”），并提取关键槽位，输出JSON格式，不添加任何多余文字。
意图标签：apply_leave（请假）、expense_reimbursement（报销）、attendance_abnormal（考勤异常）、password_reset（密码重置）、rag_query（RAG查询）、other（其他）
用户提问：{user_input}
输出格式：{"intent":"","confidence":"","slots":{}}
```

2. 输入控制：仅传入用户提问的核心内容（预处理后的文本），不携带冗余上下文；
3. 模型参数配置：温度=0.1（降低随机性）、top_p=0.8、最大生成长度=100，确保输出结构化、稳定。

##### （3）兜底处理
若大模型识别失败（输出intent=other），返回企业统一兜底回复：“抱歉，未理解您的需求，请补充具体业务场景（如请假、报销、知识库查询），我将为您精准解答。”

#### 3. 落地注意事项
+ 严格控制大模型调用占比，通过规则、小模型拦截，将其控制在10%以内；
+ 大模型调用结果需同步存入样本库，用于后续小模型迭代。

## 三、关键配套模块落地（保证快+准的核心支撑）
### （一）意图结果缓存模块（2天完成）
1. 缓存内容：标准化提问→意图识别结果（含槽位、路由）；
2. CacheKey设计（避免串数据、越权）：

```plain
cache_key = MD5(标准化提问 + 业务模块 + 用户角色 + 权限标识)
```

3. 缓存策略：
    - 高频意图（规则/小模型命中）：TTL=7天，常驻Redis高速缓存；
    - 长尾意图（大模型兜底）：TTL=1天，下沉至低成本存储；
    - 敏感意图（薪资、涉密）：禁止缓存，每次重新识别。
4. 工具选型：Redis（本地部署），配置缓存淘汰策略（LRU），防止缓存膨胀。

### （二）上下文多轮意图继承模块（1天完成）
1. 核心逻辑：同一会话中，上文已确定意图，下轮模糊问句自动继承该意图；
2. 落地操作：
    - 会话缓存中存储当前会话的“当前意图”，有效期=会话时长；
    - 下轮提问无明确意图时，自动继承上轮意图，结合槽位信息补全；
    - 示例：
第一轮：“怎么请假”→ 意图=apply_leave；
第二轮：“需要什么材料”→ 自动继承apply_leave，槽位补充“need=材料”。

### （三）意图路由联动模块（2天完成）
1. 核心目标：意图识别结果直接联动下游业务（RAG知识库、IT系统、人事系统），无需额外处理；
2. 路由规则配置：
    - 意图=rag_query（RAG查询）→ 路由至对应知识库（结合用户权限，匹配授权kb_id）；
    - 意图=apply_leave/expense_reimbursement → 路由至HR业务系统；
    - 意图=password_reset → 路由至IT运维系统；
    - 意图=闲聊/other → 直接返回标准回复，不路由。
3. 落地操作：在意图识别输出中添加“route”字段，下游系统监听该字段，实现自动路由。

## 六、优化迭代机制（长期保证快+准）
### 1. 日常监控（每日）
+ 核心监控指标：意图识别耗时、准确率、缓存命中率、大模型调用占比、错误识别case数量；
+ 异常告警：当准确率＜90%、耗时＞50ms、大模型调用占比＞10%，自动告警。

### 2. 样本迭代（每周）
+ 收集错误识别case（用户反馈、监控异常），人工标注后，增量微调轻量小模型；
+ 补充同义词典、规则，覆盖新增话术、业务场景。

### 3. 规则优化（每月）
+ 清理无效规则（低命中、过期业务）；
+ 新增高频意图规则，进一步降低模型调用占比。

### 4. 模型优化（每季度）
+ 用新增样本对轻量小模型进行全量微调，提升准确率；
+ 评估模型性能，必要时替换更轻量、更精准的模型。

## 七、风险与应对措施
| 潜在风险 | 应对措施 |
| --- | --- |
| 小模型识别准确率不达标 | 1. 补充标注样本，增加微调轮次；2. 优化同义词典，减少输入干扰；3. 调整置信度阈值 |
| 大模型调用占比过高 | 1. 补充规则，拦截更多高频意图；2. 优化小模型，提升模糊意图识别能力；3. 加强输入归一，提升缓存命中率 |
| 多轮对话意图继承错误 | 1. 优化会话缓存逻辑，明确意图继承条件；2. 增加上下文意图校验，避免误继承 |
| 权限关联意图识别错误 | 1. 强化权限标识与意图的绑定规则；2. 新增权限校验环节，在意图识别后二次校验用户权限 |

## 八、验收标准（落地闭环）
1. 速度验收：规则命中≤5ms，小模型识别≤30ms，大模型兜底≤300ms，端到端响应≤300ms；

5. 适配性验收：支持多部门、多知识库权限场景，意图识别与RAG、业务系统联动正常。
