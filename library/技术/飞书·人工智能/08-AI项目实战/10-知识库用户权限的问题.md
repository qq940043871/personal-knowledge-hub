# 知识库用户权限的问题

你这个问题是企业RAG最经典、也最容易做乱的一块：**多知识库、用户自建库、按人/按部门/按领导可见**。下面给你一套能直接落地、私有化、和MinerU解析层无缝对接的权限架构，不绕弯、直接可用。

## 一、先把概念理清楚（你们现在混乱的根源）

企业里一般有三层：

1. **系统层**：整个RAG平台（一个）
2. **租户/工作区层**：按企业/大部门隔离（比如集团、子公司）
3. **知识库层**：用户/部门自建，最小权限单元（你们的核心）

权限要做到：

- **谁能建库**
- **谁能看/查某库**
- **谁能编辑/上传某库**
- **谁能管理库的权限（库管理员）**

## 二、推荐架构：RBAC + 知识库归属 + 标签过滤 + 向量库元数据隔离

一句话：**权限在检索前就卡死，而不是查到后再过滤**。

### 1. 四层角色体系（直接套用）

- **超级管理员**：全系统所有库、所有权限（IT）
- **租户管理员**：本租户下所有库、用户、权限（部门负责人）
- **知识库管理员（重点）**：**自己创建的库**全权管理，可加成员、设可见范围
- **普通用户**：只能访问被授权的库，可在授权库内问答/上传（可选）

### 2. 知识库归属与可见范围（解决“领导才能看”）

每个知识库必须绑定：

- **创建人（owner）**：默认管理员
- **可见范围（关键）**：
  - 私有：仅owner可见
  - 指定用户：选哪些人能看（领导组）
  - 指定部门：整个部门可见
  - 全员：公司所有人可见
- **成员列表**：可读写/只读

> 示例：领导专属库 → 可见范围=“高管组”，普通员工不在组内，**检索时直接过滤掉这个库的所有向量**。

### 3. 向量库层强制隔离（防越权）

所有文档切片（Chunk）入库时，**必须带权限元数据**：

```json
{
  "kb_id": "kb_xxx",       // 所属知识库
  "owner": "user_xxx",     // 创建人
  "visible_users": ["u1", "u2"],
  "visible_depts": ["dept_leadership"]
}
```

检索时，**先根据当前用户身份，生成过滤条件**：

```plain
kb_id IN [用户有权限的库列表]
AND (
  user_id IN visible_users
  OR dept_id IN visible_depts
  OR owner == user_id
)
```

向量库（如Milvus/FAISS）直接按元数据过滤，**无权数据根本不参与检索**，安全又高效。

### 4. 多租户/工作区隔离（可选，大企业用）

如果是集团多子公司：

- 每个子公司一个**独立工作区（Workspace）**
- 工作区间数据完全隔离，用户不能跨区访问
- 工作区内再按上面的“知识库权限”执行

## 三、关键场景解决方案（直接对号入座）

### 场景1：用户自建知识库，自己管理权限

- 每个用户可创建多个私有库
- 创建人默认是**库管理员**，可：
  - 改库名、删库
  - 添加/移除成员
  - 设置成员为“只读”或“可编辑”
- 普通用户只能看到自己被加入的库

### 场景2：某些库只有领导能看

- 建一个**领导专属组（如leadership）**
- 知识库可见范围设为**仅该组可见**
- 普通员工不在组内，检索时自动过滤

### 场景3：部门共享库（如HR制度）

- 可见范围设为**整个HR部门**
- 所有HR成员自动可见，无需逐个加

### 场景4：文档级敏感（比库更细）

如果同一库里有公开文档+敏感文档：

- 文档打**安全标签**（公开/内部/机密）
- 用户绑定**安全等级**
- 检索时叠加：`doc_level <= user_level`

## 四、落地步骤（从简到繁，2周内搞定）

### 第1步：权限模型（RBAC）

- 建5张表：用户、部门、角色、用户-角色、知识库、知识库-用户/部门
- 角色：超管、租户管、库管、只读用户

### 第2步：知识库字段改造

- 每个库加：owner_id、visible_type（私有/用户/部门/全员）、visible_ids（用户/部门ID列表）

### 第3步：解析层对接MinerU

- MinerU解析后的文档/切片，入库时**自动携带kb_id和权限元数据**

### 第4步：检索前过滤（核心）

- 用户登录后，拿到其用户ID、部门ID、角色
- 查出该用户**有权访问的所有kb_id列表**
- 检索时向量库**强制过滤kb_id**，只查有权的库

### 第5步：界面控制

- 左侧知识库列表：只显示用户有权的库
- 新建库按钮：仅允许“可建库”角色（如全员或指定角色）

## 五、避坑要点（很多团队栽这里）

1. **不要在检索后过滤**：查到敏感内容再隐藏，容易泄露，且性能差
2. **不要用“目录”代替知识库**：目录难控权限，知识库才是最小权限单元
3. **不要直接对用户授权所有库**：用户多了无法管理，必须用角色+组
4. **向量库必须支持元数据过滤**：Milvus、Weaviate、PGVector都支持，选型时确认

## 六、总结一句话

**用RBAC管角色，用知识库归属管可见范围，用向量库元数据过滤做检索隔离**，三者结合，完美解决“多知识库、用户自建、领导专属”的企业级权限问题。
