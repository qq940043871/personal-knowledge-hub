# 定义自己的翻译

要动手打造属于自己的 **LibreTranslate**，可以从源码定制、功能扩展、模型替换等方向入手。以下是详细步骤，涵盖从环境搭建到二次开发的全流程：

### 一、准备基础环境（以 Linux/macOS 为例，Windows 需调整路径）

#### 1. 安装必备工具

- **Python 环境**：确保安装 Python 3.8+（推荐使用 `pyenv` 或虚拟环境管理）  `# 创建虚拟环境（可选）  
python -m venv libretranslate_env  
source libretranslate_env/bin/activate  # Windows 用 `libretranslate_env\Scripts\activate``
- **Git**：用于克隆代码  `sudo apt install git  # Ubuntu/Debian  
brew install git  # macOS`
- **Docker（可选）**：若需容器化部署  `curl -fsSL https://get.docker.com | sh`

### 二、获取 LibreTranslate 源码

#### 1. 分叉并克隆仓库

- 先在 [GitHub 仓库](https://github.com/LibreTranslate/LibreTranslate) 点击 **Fork**，将项目复制到自己的账号下。
- 克隆自己的分叉版本（替换 `your_username` 为你的 GitHub 用户名）：  `git clone https://github.com/your_username/LibreTranslate.git  
cd LibreTranslate`

#### 2. 安装依赖

```
<code>pip install -r requirements.txt</code>
```

### 三、启动开发模式（本地调试）

#### 1. 运行开发服务器

```
<code>python main.py</code>
```

- 访问 `http://localhost:5000` 即可看到默认界面，此时修改代码会自动重启服务（热加载）。

#### 2. 目录结构解析

```
<code>LibreTranslate/<br/>├── main.py          # 主程序入口（Flask 服务）<br/>├── translate.py     # 翻译核心逻辑（调用 Argos Translate 模型）<br/>├── models/          # 自定义模型或配置（可扩展）<br/>├── static/          # 前端静态资源（HTML/JS/CSS）<br/>├── templates/       # 前端模板（可选，默认用静态页面）<br/>└── requirements.txt # 依赖清单</code>
```

### 四、核心功能定制（二次开发）

#### 1. 修改翻译逻辑（关键文件：`translate.py`）

- **替换底层翻译引擎**：LibreTranslate 默认基于 [Argos Translate](https://argosopentech.com/argos-translate/)，若想接入其他引擎（如 DeepL、NLTK 或自研模型），需修改 `translate` 函数逻辑。  `# 示例：自定义翻译函数（替换原有 Argos Translate 逻辑）  
def translate(text, source, target):  
    # 这里写入你的翻译逻辑（如调用本地模型或第三方 API）  
    return custom_translation_result`

#### 2. 添加新功能

- **扩展 API 接口**：在 `main.py` 中新增路由，例如支持文件翻译（上传文本文件并翻译）：  `from flask import request, jsonify  
  
@app.route('/translate/file', methods=['POST'])  
def translate_file():  
    file = request.files['file']  
    text = file.read().decode('utf-8')  
    result = translate(text, request.form['source'], request.form['target'])  
    return jsonify({'translatedText': result})`
- **自定义前端界面**：修改 `static/index.html` 或替换为 React/Vue 等框架，通过 API 与后端交互。

#### 3. 支持更多语言或模型

- **手动添加预训练模型**：  从 [Argos Translate 模型库](https://github.com/argosopentech/argos-translate-models) 下载 `.argosmodel` 文件（如 `zh-en.argosmodel`）。
- 放入用户目录的模型缓存路径（如 Linux 的 `~/.local/share/argos-translate/packages/`，或通过环境变量 `LT_MODEL_PATH` 指定自定义路径）。
- 在代码中更新支持的语言列表（`translate.py` 中的 `LANGUAGES` 变量）。

### 五、深度定制：替换底层模型（进阶）

若想使用自研模型（如基于 Hugging Face 的 NMT 模型），需：

1. **加载自定义模型**：使用 `transformers` 库加载模型和分词器：  `from transformers import AutoTokenizer, AutoModelForSeq2SeqLM  
  
tokenizer = AutoTokenizer.from_pretrained("your-model-path")  
model = AutoModelForSeq2SeqLM.from_pretrained("your-model-path")`
1. **实现翻译函数**：基于模型编写推理逻辑，替换原有的 Argos Translate 调用：  `def translate(text, source, target):  
    inputs = tokenizer(text, return_tensors="pt")  
    outputs = model.generate(**inputs)  
    return tokenizer.decode(outputs[0], skip_special_tokens=True)`

### 六、部署自定义版本

#### 1. 容器化部署（推荐）

- **编写自定义 Dockerfile**（基于官方镜像扩展）：  `FROM libretranslate/libretranslate:latest  
COPY . /app  # 将本地修改后的代码复制到容器  
RUN pip install -r /app/requirements.txt  # 安装额外依赖`
- **启动容器**：  `docker build -t my-libretranslate .  
docker run -p 5000:5000 my-libretranslate`

#### 2. 传统部署（适合服务器）

- 安装依赖后，使用 `gunicorn` 等 WSGI 服务器优化性能：  `pip install gunicorn  
gunicorn -w 4 -b 0.0.0.0:5000 main:app`

### 七、进阶优化

1. **添加认证机制**：在 API 路由中增加 API Key 校验（参考官方文档的 `LT_API_KEYS` 配置）。
1. **性能优化**：  启用 GPU 加速（安装 PyTorch/CuPy，修改模型加载代码）。
1. 使用缓存（如 Redis）减少重复翻译请求。
1. **国际化支持**：扩展前端界面的多语言显示（修改 `static/index.html` 中的文案）。

### 八、贡献与分享（可选）

若你的修改具有通用性，可提交 Pull Request 到官方仓库，或在 GitHub 上发布自己的分支，通过 README 说明定制功能，吸引其他用户使用。
