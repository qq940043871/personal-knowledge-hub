# 推理优化

> 🚀 推理（Inference）是大语言模型（LLM）实际服务用户的过程，即将训练好的模型部署到生产环境，接受用户输入并生成响应。与训练阶段不同，推理阶段需要在延迟、吞吐量和成本之间寻找最优平衡。优化推理速度和成本是 LLM 商业化落地的关键挑战，直接影响用户体验和服务的经济可行性。本文将深入探讨推理优化的核心技术和最新进展。

## 1. 推理流程分析

LLM 推理过程可以明确分为两个截然不同的阶段，理解这两个阶段的特性是优化的基础。

### 1.1 Prefill 阶段（预填充）

Prefill 阶段处理输入 prompt，将整个输入序列并行编码。这一阶段的核心特点是：

- **计算密集型（Compute-bound）**：需要对所有输入 token 进行矩阵运算
- **高并行度**：所有输入 token 可以并行处理，充分利用 GPU 的计算能力
- **时间复杂度**：O(n²) 的注意力计算，其中 n 为序列长度
- **首 Token 延迟（TTFT, Time to First Token）**：Prefill 阶段的耗时直接影响用户感知的响应速度

### 1.2 Decode 阶段（解码）

Decode 阶段逐 token 生成输出，是自回归的过程：

- **内存带宽密集型（Memory-bandwidth-bound）**：每步只生成一个 token，但需要读取整个模型参数
- **低并行度**：每次只处理一个 token，GPU 计算单元利用率低
- **依赖 KV Cache**：需要读取之前所有 token 的 Key 和 Value 缓存
- **每 Token 延迟（TPOT, Time Per Output Token）**：决定生成速度的瓶颈

**两阶段瓶颈对比：**

| 特性 | Prefill 阶段 | Decode 阶段 |
|-|-|-|
| 瓶颈类型 | 计算密集 | 内存带宽密集 |
| 并行度 | 高（整个输入并行处理） | 低（逐 token 生成） |
| GPU 利用率 | 高 | 低 |
| 优化重点 | 减少计算量、降低首 token 延迟 | 提高内存带宽利用率、增加批处理大小 |

## 2. KV Cache

### 2.1 核心思想

KV Cache 是推理优化中最基础也是最关键的技术。在自回归生成过程中，每个新 token 的生成都需要计算注意力，涉及到与之前所有 token 的 Key 和 Value 的交互。如果每次都重新计算历史 token 的 K 和 V，会造成大量重复计算。

KV Cache 的解决方案是将已计算的 Key 和 Value 向量缓存起来，新 token 生成时只需计算当前 token 的 Q、K、V，然后从缓存中读取历史的 K、V 进行注意力计算。

### 2.2 复杂度分析

使用 KV Cache 前后的计算复杂度对比：

- **无 KV Cache**：每生成一个 token 需要 O(n²) 计算（n 为当前序列长度）
- **有 KV Cache**：每生成一个 token 只需 O(n) 计算

整体生成 m 个 token 的复杂度从 O(m·n²) 降低到 O(m·n)，这是数量级的优化。

### 2.3 内存占用计算

KV Cache 的内存占用公式为：

**KV Cache 内存 = 2 × n_layers × n_heads × d_head × seq_len × batch_size × dtype_size**

其中：

- 2 表示 Key 和 Value 两个缓存
- n_layers 是 Transformer 层数
- n_heads 是注意力头数
- d_head 是每个头的维度
- seq_len 是序列长度
- batch_size 是批处理大小
- dtype_size 是数据类型大小（FP16 为 2 字节）

**示例计算**：以 LLaMA-70B 为例，假设 80 层、64 头、维度 128、序列长度 4096、batch_size=1、FP16：

KV Cache 内存 = 2 × 80 × 64 × 128 × 4096 × 1 × 2 bytes ≈ 10.7 GB

这说明 KV Cache 是长序列推理的主要内存瓶颈，也是后续多种优化技术（如 PagedAttention、MQA、GQA）的核心动因。

## 3. 量化 (Quantization)

### 3.1 精度-速度权衡

量化是将模型权重和激活值从高精度（如 FP32/FP16）转换为低精度（如 INT8/INT4）表示的技术。这种转换带来显著的内存节省和计算加速，但会引入精度损失。

**典型量化路径**：

- **FP16 → INT8**：内存减半，计算加速约 1.5-2 倍，精度损失较小
- **FP16 → INT4**：内存减少 75%，计算加速约 2-3 倍，需要更精细的量化策略
- **FP16 → INT3/INT2**：极端压缩，通常伴随明显精度下降

### 3.2 主流量化方法

**GPTQ (GPT Quantization)**

- **类型**：训练后量化（Post-Training Quantization, PTQ）
- **核心思想**：逐层量化，通过最小化量化误差的目标函数，利用 Hessian 矩阵的逆来调整权重
- **校准数据**：需要少量校准数据（通常 128 条）来估计 Hessian 信息
- **优势**：量化速度快，支持 INT4/INT3，适合快速部署

**AWQ (Activation-Aware Weight Quantization)**

- **类型**：训练后量化
- **核心思想**：观察到少数"显著权重"通道对模型输出影响大，通过激活值分布来识别这些通道并进行保护
- **方法**：对显著权重通道缩放后再量化，减少量化误差
- **优势**：在极低比特（如 INT4）下保持更好的精度

**SmoothQuant**

- **类型**：训练后量化
- **核心思想**：平滑激活值分布。观察到激活值存在离群点（outlier），直接量化困难。通过数学等价变换，将激活的量化难度转移到权重上
- **公式**：Y = (X · diag(s)^(-1)) · (diag(s) · W)，其中 s 为平滑因子
- **优势**：支持 W8A8（权重 INT8、激活 INT8）量化，精度损失极小

**量化方法对比：**

| 方法 | 量化类型 | 典型比特数 | 精度损失 | 加速比 | 适用场景 |
|-|-|-|-|-|-|
| GPTQ | 权重量化 | INT4/INT3 | 中等 | 2-3x | 快速部署、GPU 推理 |
| AWQ | 权重量化 | INT4 | 较小 | 2-3x | 低比特高效部署 |
| SmoothQuant | 权重+激活 | INT8 | 极小 | 1.5-2x | 高精度要求场景 |
| GGUF/llama.cpp | 权重量化 | Q4_K_M 等 | 中等 | 2-4x | CPU/边缘设备推理 |

## 4. 推测解码 (Speculative Decoding)

### 4.1 核心思想

推测解码（Speculative Decoding）是一种在不改变模型输出分布的前提下显著加速推理的技术。其核心思想是：用一个小型、快速的"草稿模型"（Draft Model）快速生成多个候选 token，然后用大型"目标模型"（Target Model）一次性并行验证这些候选 token。

### 4.2 工作流程

推测解码的典型流程如下：

- **草稿生成**：小模型快速自回归生成 γ 个候选 token（γ 为推测长度）
- **并行验证**：大模型对这 γ 个候选 token 进行一次前向传播，计算每个位置的接受概率
- **接受-拒绝采样**：根据概率决定接受多少个 token，保证最终输出分布与纯大模型生成一致
- **修正**：如果某个位置被拒绝，则从该位置重新采样

### 4.3 数学保证

推测解码的关键贡献是其数学保证：通过精心设计的接受-拒绝采样策略，最终输出的 token 分布与直接使用大模型生成完全一致。这意味着推测解码是"无损"的加速方法，不会牺牲生成质量。

### 4.4 加速效果

加速比取决于草稿模型的"接受率"（acceptance rate）：

- 接受率越高，加速比越大
- 典型接受率在 70%-90% 之间
- 理论加速比约为 1/(1-α)，其中 α 为接受率
- 实际加速比通常为 2-3 倍

### 4.5 Medusa：多头并行预测

Medusa 是推测解码的一种变体，不使用独立的草稿模型，而是在大模型上添加多个"预测头"（prediction heads），每个头并行预测未来不同位置的 token。这种方法避免了维护两个模型的复杂性，但需要额外的训练来适配预测头。

## 5. PagedAttention (vLLM)

### 5.1 问题：KV Cache 的内存碎片化

在传统的推理系统中，KV Cache 的内存管理存在严重问题：

- **预分配策略**：为每个请求预先分配最大序列长度的连续内存
- **内部碎片**：实际生成长度通常远小于最大长度，造成大量内存浪费
- **外部碎片**：不同请求结束后释放的内存块大小不一，难以有效利用
- **内存利用率**：实际使用中，预分配的 KV Cache 内存利用率通常只有 20%-40%

### 5.2 思想：借鉴操作系统虚拟内存

PagedAttention 借鉴了操作系统虚拟内存的分页机制来管理 KV Cache：

- **逻辑块（Logical Block）**：将 KV Cache 在逻辑上划分为固定大小的块（如 16 个 token 一块）
- **物理块（Physical Block）**：GPU 显存也被划分为相同大小的物理块
- **块表（Block Table）**：维护逻辑块到物理块的映射关系，类似页表
- **按需分配**：只在实际生成 token 时才分配物理块，而非预先分配

### 5.3 优势

- **消除内存碎片**：固定大小的块避免了外部碎片，按需分配消除了内部碎片
- **内存利用率提升**：从 20%-40% 提升到接近 100%
- **支持更大 batch size**：节省的内存可以服务更多并发请求
- **吞吐量提升**：典型场景下吞吐量提升 2-4 倍
- **共享前缀**：支持多个请求共享相同的 prompt 前缀的 KV Cache，进一步节省内存

## 6. 连续批处理 (Continuous Batching)

### 6.1 静态批处理的问题

传统的静态批处理（Static Batching）存在严重效率问题：

- **等待问题**：一个批次中，短请求完成后必须等待最长的请求结束才能处理下一批
- **资源浪费**：已完成的请求占用的 GPU 资源被闲置
- **延迟增加**：新请求必须等待当前批次完成才能进入
- **利用率低**：GPU 利用率随批次中请求完成而逐渐下降

### 6.2 迭代级调度

连续批处理（Continuous Batching）又称迭代级调度（Iteration-level Scheduling），其核心改进是：

- **细粒度调度**：在每个 decode step（而非整个序列生成完成后）进行调度决策
- **动态插入**：当某个请求生成完毕，立即在下一个迭代插入新请求
- **独立处理**：批次中的每个请求独立推进，互不阻塞

### 6.3 与 PagedAttention 的配合

连续批处理与 PagedAttention 是天然的互补技术：

- 连续批处理确保请求级别的高效调度
- PagedAttention 确保内存级别的高效利用
- 两者结合，吞吐量可提升 6-10 倍

## 7. 推理框架对比

选择合适的推理框架对部署效率至关重要。以下是主流框架的对比：

| 框架 | 吞吐量 | 延迟 | 量化支持 | 分布式 | 特点 |
|-|-|-|-|-|-|
| vLLM | 高 | 中等 | GPTQ/AWQ/FP8 | 张量并行 | PagedAttention、连续批处理、易用性强 |
| TensorRT-LLM | 最高 | 最低 | INT8/INT4/FP8 | 张量/流水线并行 | NVIDIA 官方优化、极致性能、配置复杂 |
| SGLang | 高 | 低 | GPTQ/AWQ/FP8 | 张量并行 | RadixAttention、结构化生成优化 |
| llama.cpp | 中等 | 中等 | GGUF(Q2-Q8) | 有限 | CPU 推理、边缘设备、轻量部署 |

**选型建议**：

- **追求极致性能**：TensorRT-LLM（NVIDIA GPU 环境）
- **平衡易用性与性能**：vLLM（通用场景首选）
- **结构化生成需求**：SGLang（JSON 输出、Agent 场景）
- **CPU 或边缘设备**：llama.cpp（资源受限环境）
