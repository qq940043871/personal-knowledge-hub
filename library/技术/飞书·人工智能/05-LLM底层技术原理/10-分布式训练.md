# 分布式训练

> 🚀 当模型大到单卡放不下时，分布式训练是唯一的出路。随着大语言模型参数量从数十亿飙升到数千亿，单张 GPU 的显存早已无法容纳完整模型。分布式训练通过将计算和存储分散到多个设备上，使得训练超大规模模型成为可能。本文将深入解析各种分布式训练策略的原理、实现和适用场景。

## 1. 为什么需要分布式训练

现代深度学习模型的参数量呈指数级增长，而 GPU 显存的增长速度远远跟不上。理解分布式训练的必要性，需要先理解训练过程中的内存消耗。

**模型参数量 vs GPU 显存：**

- 一个 70B 参数的模型，以 FP16 存储需要约 **140GB** 显存（70B × 2 bytes）
- 而当前主流 GPU 的显存：A100 为 80GB，H100 为 80GB，H200 为 141GB
- 这意味着即使是最先进的单卡，也无法放下一个 70B 模型的完整参数

**训练需要 3-4 倍于参数的额外内存：**

训练过程中，除了模型参数本身，还需要存储：

- **梯度（Gradients）**：与参数同等大小，FP16 格式同样需要 140GB
- **优化器状态（Optimizer States）**：Adam 优化器需要为每个参数维护一阶动量和二阶动量，以 FP32 存储需要 4 × 参数量 = 280GB
- **激活值（Activations）**：前向传播过程中产生的中间结果，用于反向传播计算梯度

综合计算：一个 70B 模型的训练总共需要约 **560GB \~ 840GB** 的显存，这远远超出了任何单张 GPU 的容量。因此，分布式训练不是可选项，而是训练大模型的**唯一出路**。

## 2. 数据并行 (Data Parallelism)

数据并行是最简单也是最常用的分布式训练策略。其核心思想是：每张 GPU 持有完整的模型副本，但处理不同的数据批次。

**工作原理：**

- 将一个大的 mini-batch 拆分成 N 个 micro-batch，分配给 N 张 GPU
- 每张 GPU 独立进行前向传播和反向传播，计算本地梯度
- 通过 **AllReduce** 操作同步所有 GPU 上的梯度，得到全局平均梯度
- 每张 GPU 使用相同的梯度更新各自的模型参数

**通信开销与 batch size 的关系：**

AllReduce 的通信量与模型参数量成正比，而与 batch size 无关。因此，增大 batch size 可以提高计算/通信比，从而提升训练效率。但 batch size 过大会导致收敛困难，需要配合学习率 warmup 等技巧。

**局限性：**数据并行要求每张 GPU 都能放下完整模型，当模型太大时就无法使用。

## 3. ZeRO (Zero Redundancy Optimizer)

ZeRO（Zero Redundancy Optimizer）由微软 DeepSpeed 团队提出，通过消除数据并行中的冗余存储来大幅降低内存消耗。ZeRO 将优化器状态、梯度和参数分片存储在不同的 GPU 上。

**ZeRO 的三个级别：**

| 级别 | 分片内容 | 内存节省 | 通信量 |
|-|-|-|-|
| ZeRO-1 | 优化器状态 | 4x | 与 DP 相同 |
| ZeRO-2 | 优化器状态 + 梯度 | 8x | 与 DP 相同 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 | Nx（N 为 GPU 数） | 1.5x DP |

**内存节省公式（以混合精度训练为例，参数量为 Φ）：**

- 原始数据并行：需要 4Φ + 8Φ + 16Φ = 28Φ bytes（参数 + 梯度 + 优化器状态）
- ZeRO-1：4Φ + 8Φ + 16Φ/N，当 N=64 时，节省约 4x
- ZeRO-2：4Φ + (8Φ + 16Φ)/N，当 N=64 时，节省约 8x
- ZeRO-3：(4Φ + 8Φ + 16Φ)/N = 28Φ/N，当 N=64 时，节省约 64x

**DeepSpeed 实现：**DeepSpeed 是微软开源的分布式训练库，提供了 ZeRO 的高效实现。通过简单的配置文件，即可将 ZeRO 应用到现有训练代码中。DeepSpeed 还提供了 CPU offload、NVMe offload 等进一步节省显存的技术。

## 4. FSDP (Fully Sharded Data Parallel)

FSDP 是 PyTorch 原生实现的 ZeRO-3 策略，将模型参数、梯度和优化器状态完全分片存储在所有 GPU 上。

**与 DeepSpeed ZeRO-3 的异同：**

| 特性 | FSDP | DeepSpeed ZeRO-3 |
|-|-|-|
| 框架 | PyTorch 原生 | 独立库 |
| 配置复杂度 | 较高，需要手动配置分片策略 | 较低，配置文件驱动 |
| 通信优化 | 支持 overlap | 更丰富的优化选项 |
| CPU Offload | 支持 | 支持，且支持 NVMe Offload |
| 生态集成 | 与 PyTorch 生态无缝集成 | 需要额外适配 |

FSDP 的核心优势在于它是 PyTorch 原生组件，无需引入额外依赖，且与 PyTorch 的其他特性（如 torch.compile）有更好的兼容性。

## 5. 张量并行 (Tensor Parallelism)

张量并行将单个矩阵运算拆分到多张 GPU 上执行，是 Megatron-LM 提出的核心技术。

**列并行（Column Parallelism）：**

将权重矩阵按列切分，每张 GPU 计算部分列的结果。例如，对于线性层 Y = XA，将 A 按列切分为 [A1, A2]，每张 GPU 分别计算 Y1 = XA1 和 Y2 = XA2。

**行并行（Row Parallelism）：**

将权重矩阵按行切分，每张 GPU 计算部分行的结果。例如，对于线性层 Y = XA，将 A 按行切分为 [A1; A2]，将 X 也相应切分，每张 GPU 计算部分结果后通过 AllReduce 合并。

**通信模式：**

- **AllReduce**：在行并行中使用，将各 GPU 的部分结果求和得到最终结果
- **AllGather**：在列并行中使用，收集各 GPU 的部分输出以获得完整结果

**适用场景：**张量并行最适合**单机多卡**场景，因为其通信频繁（每层都需要通信），对通信带宽和延迟要求很高。通常在单个节点内使用 NVLink 连接的 GPU 之间进行张量并行。

## 6. 流水线并行 (Pipeline Parallelism)

流水线并行将模型按层切分到不同的 GPU 上，每个 GPU 只负责模型的一部分层。

**核心挑战——流水线气泡：**

朴素的流水线并行会导致严重的资源浪费：当一个 micro-batch 在某一层计算时，其他所有 GPU 都在等待，形成"气泡"（bubble）。

**调度策略：**

- **GPipe**：将 mini-batch 拆分为多个 micro-batch，依次注入流水线，减少气泡比例。气泡比例 = (p-1)/(m+p-1)，其中 p 为流水线阶段数，m 为 micro-batch 数
- **1F1B（One Forward One Backward）**：交替执行前向和反向传播，进一步减少气泡和内存峰值。被 Megatron-LM 和 PipeDream 采用
- **Interleaved 1F1B**：每个 GPU 负责多个不连续的层，进一步减少气泡比例

## 7. 3D 并行

对于超大规模模型训练，单一的并行策略往往不够。3D 并行将数据并行、张量并行和流水线并行组合使用，以充分利用大规模集群的计算资源。

**Megatron-LM 的 3D 并行策略：**

- **张量并行**：在单个节点内使用（节点内 GPU 通过 NVLink 连接，带宽高达 900GB/s）
- **流水线并行**：在节点间使用（节点间通过 InfiniBand 连接，带宽约 400Gb/s）
- **数据并行**：在剩余维度上使用，进一步扩展吞吐量

**并行策略对比：**

| 策略 | 切分维度 | 通信模式 | 适用场景 | 内存效率 |
|-|-|-|-|-|
| 数据并行 | 数据批次 | AllReduce | 小模型、大集群 | 低（每卡存完整模型） |
| ZeRO-3 | 参数/梯度/优化器 | AllGather + ReduceScatter | 中等模型 | 高 |
| 张量并行 | 矩阵维度 | AllReduce / AllGather | 单机多卡 | 高 |
| 流水线并行 | 模型层 | P2P 通信 | 多机训练 | 中等 |
| 3D 并行 | 组合 | 组合 | 超大规模训练 | 最高 |

## 8. 混合精度训练

混合精度训练是分布式训练中的重要优化技术，通过使用低精度浮点数来减少内存占用和加速计算。

**FP16/BF16 + FP32 主权重：**

- 前向和反向传播使用 FP16 或 BF16 计算，减少内存占用和计算时间
- 维护一份 FP32 的主权重副本，用于参数更新，避免精度损失
- 优化器状态也以 FP32 存储

**Loss Scaling 技术：**

FP16 的动态范围较小（最小正数约 6e-8），梯度容易下溢为零。Loss Scaling 通过在反向传播前将 loss 乘以一个缩放因子，放大梯度值，避免下溢。更新参数前再将梯度除以相同的缩放因子。

**BF16 的优势：**

- 与 FP16 相同的 16 位宽度，但拥有与 FP32 相同的 **指数位（8 位）**
- 动态范围远大于 FP16，几乎不会出现梯度下溢问题
- 因此 **BF16 不需要 Loss Scaling**，使用更加简单
- 代价是尾数位只有 7 位（FP16 有 10 位），精度略低

现代大模型训练普遍采用 BF16 混合精度，如 GPT-4、LLaMA 等均使用 BF16 训练。

## 9. 关键论文

以下是分布式训练领域的关键论文，建议深入阅读：

- **Megatron-LM**（Shoeybi et al., 2019）：提出张量并行技术，是大模型分布式训练的奠基之作
- **ZeRO**（Rajbhandari et al., 2020）：提出零冗余优化器，大幅降低数据并行的内存开销
- **GPipe**（Huang et al., 2019）：提出流水线并行的 micro-batch 调度策略
- **PyTorch FSDP**（Zhao et al., 2023）：PyTorch 原生的完全分片数据并行实现
- **Mixed Precision Training**（Micikevicius et al., 2018）：系统阐述混合精度训练的原理和实践
- **DeepSpeed**（Rasley et al., 2020）：微软的分布式训练库，集成了 ZeRO 等多种优化
- **Alpa**（Zheng et al., 2022）：自动并行化框架，可自动生成最优的并行策略
- **Megatron-LM v2/v3**（Narayanan et al., 2021）：引入 3D 并行和序列并行
