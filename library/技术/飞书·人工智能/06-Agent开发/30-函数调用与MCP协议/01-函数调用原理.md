## Function Calling：模型发起、本地执行的四步闭环

核心思路：**模型不直接执行函数——它只生成「要调哪个函数、传什么参数」，由本地代码执行后把结果喂回模型，模型再生成最终回复**。

```text
Function Calling流程：
  1. 模型生成函数调用
  2. 本地执行函数
  3. 返回结果给模型
  4. 模型生成最终回复

与MCP的关系：
  - Function Calling是通用机制
  - MCP是标准化的协议
  - MCP可以基于Function Calling实现
```

## 函数注册：从函数签名自动生成 Schema

核心思路：**注册表同时保存函数本体和 JSON Schema；不给 Schema 时用 `inspect.signature` 从参数注解自动生成，调用时兼容同步/异步函数**。

```python
# 函数注册表·注册侧（伪代码骨架；register 装饰器为真实修复实现）
# 完整实现见 ai-agent-harness 工程
import asyncio
import logging
from typing import Any, Callable, Dict, List

logger = logging.getLogger(__name__)


class FunctionRegistry:
    """同时保存函数本体与 JSON Schema；不给 schema 时自动推断"""

    _TYPE_MAP = {str: "string", int: "integer", float: "number",
                 bool: "boolean", list: "array", dict: "object"}

    def __init__(self):
        self.functions: Dict[str, Callable] = {}
        self.schemas: Dict[str, Dict] = {}

    # ── 注册：装饰器用法（核心修复：末尾必须 return func）──────
    def register(self, name: str, schema: Dict = None) -> Callable:
        """装饰器注册：必须 return func！若装饰器返回 None，被装饰的
        函数名会指向 None，之后任何调用都 TypeError——最经典的坑。"""
        def decorator(func: Callable) -> Callable:
            self.functions[name] = func
            self.schemas[name] = schema or self._generate_schema(func)
            logger.info("注册函数: %s", name)
            return func                      # 关键：把原函数返回（修复项）
        return decorator

    def add_function(self, name, func, schema=None):
        ...    # 编程式注册：不经装饰器，写同一张表

    def list_functions(self) -> List[Dict]:
        return list(self.schemas.values())   # 供 LLM 挑选的工具清单

    def _generate_schema(self, func) -> Dict:
        ...    # ★特殊点1 schema 自动推断：inspect.signature 遍历参数注解
        #   + _TYPE_MAP 映射，无默认值收进 required；未标注默认 string
        return {...}   # _python_type_to_json 的泛型/Optional 细节从略
```

```python
class FunctionRegistry:  # （续）调用侧：校验 → 审计 → 执行
    """异常包装并保留原始堆栈；失败也是结果（回传模型自愈）"""

    def _validate(self, name, arguments) -> None:
        ...    # 按注册 schema 校验：必填缺失 / 类型不符 → TypeError
        #   ★特殊点2 调用前校验防幻觉参数：模型编造的缺参/错型在进入
        #     业务函数前就被拦截；坑：bool 是 int 子类需先排除

    async def call(self, name: str, arguments: Dict) -> Any:
        func = self.functions.get(name)
        if not func:
            raise ValueError(f"Function not found: {name}")

        self._validate(name, arguments)                    # 调用前校验
        logger.info("[审计] 调用 %s(%s)", name, arguments)
        #   ★特殊点3 每次调用可审计：谁、何时、什么参数，全程留痕
        try:
            if asyncio.iscoroutinefunction(func):
                result = await func(**arguments)
            else:      # ★特殊点4 同步函数走线程池，不阻塞事件循环
                result = await asyncio.get_running_loop().run_in_executor(
                    None, lambda: func(**arguments))
            logger.info("[审计] %s 完成", name)
            return result
        except Exception as e:
            logger.exception("函数 %s 执行失败", name)   # ★特殊点5 失败留痕
            raise RuntimeError(f"调用 {name} 失败: {e}") from e
```

```python
# 使用示例：注册一个函数（装饰器返回原函数，get_weather 仍是可调用函数）
function_registry = FunctionRegistry()

@function_registry.register("get_weather", schema={
    "description": "获取天气信息",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "城市名"}
        },
        "required": ["city"]
    }
})
async def get_weather(city: str) -> Dict:
    """查询指定城市天气"""
    return {"city": city, "weather": "晴天", "temp": 25}

# await function_registry.call("get_weather", {"city": "上海"})  → 正常执行
# await function_registry.call("get_weather", {})
#   → 缺必填参数 city，被 ★特殊点2 的调用前校验以 TypeError 拦截
```

### 企业级升级要点

- **装饰器必须 return func**：注册后返回原函数，否则函数名指向 `None`——与 `ai-agent-harness/harness/tools/registry.py` 的 `@registry.tool` 同一处理（decorator 末尾 `return fn`）。
- **schema 自动推断**：`inspect` 签名 + 类型注解映射 JSON Schema——参考 `harness/tools/base.py` 的 `infer_schema`；生产建议 pydantic 强化校验。
- **调用前校验**：必填项缺失、类型不符在进入业务函数前拦截——对应 registry `dispatch` 中的 `ToolArgumentError` 分层。
- **审计日志**：每次函数调用/完成都留痕（谁、何时、什么参数），异常带原始堆栈上抛——参考 `ai-agent-harness/harness/tracer.py` 与 `main_loop.py` 的工具执行日志。
- **失败也是结果**：`call` 抛出的异常在 Agent 主循环中会被捕获并转为 tool message 回传模型自愈，而不是终止任务——见 `harness/main_loop.py` 的 `_execute_tools_parallel`。
