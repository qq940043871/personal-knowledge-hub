**上下文 = 采样时进入窗口的全部 tokens**：系统提示、工具定义、对话历史、检索结果、笔记——不只是提示词本身。上下文工程回答的是：每次调用前，如何以**可复用、可度量、可演进**的方式拼装并优化这组 tokens。

**上下文腐蚀（context rot）：tokens 越多，模型从上下文中准确回忆的能力反而下降——Transformer 注意力要在全部 token 两两建模，序列拉长后建模能力被「拉薄」。结论：上下文是有限资源且边际收益递减**，不是窗口装得下就该装。三条纪律随之而来：系统提示求**最小必要信息集**（分区组织，避开「过度硬编码 if-else」与「过于空泛」两极）；工具集求**最小可行 MVTS**（臃肿工具集让「选哪个工具」这个决策本身就含混，人都说不准别指望模型更准）；**JIT 上下文**（维护轻量引用——路径/查询/URL，运行时按需加载、渐进式披露，而非预索引全量）。

## 二、ContextPacket：统一信息单元

**核心思路：一切候选信息先封装成同构的信息包，评分选择才有统一口径。** 记忆、RAG 块、历史消息、笔记、终端输出，进流水线前都变成同一种形状；`reserve_ratio` 先为系统指令预留预算——行为根基不能被检索结果挤占。

```
<code># ContextPacket 与配置（伪代码骨架；完整实现见 hello-agents 工程 code/chapter9/）<br/>from dataclasses import dataclass<br/>from datetime import datetime<br/><br/>@dataclass<br/>class ContextPacket:<br/>    """候选信息包：记忆/RAG/历史/笔记/终端输出，进流水线前统一成这一种形状"""<br/>    content: str<br/>    timestamp: datetime<br/>    token_count: int<br/>    relevance_score: float = 0.5   # ★特殊点1 0.5 是「未评分」哨兵值：Select 阶段见到<br/>    metadata: dict | None = None   #   0.5 才现场算相关性；__post_init__ 里还需 clamp<br/>                                   #   到 [0,1]，防上游脏分污染贪心排序<br/><br/>@dataclass<br/>class ContextConfig:<br/>    """预算与评分配置"""<br/>    max_tokens: int = 3000         # 单次调用的窗口预算（硬约束，见 §三 Select）<br/>    reserve_ratio: float = 0.2     # 为系统指令预留的预算比例<br/>    min_relevance: float = 0.1     # 低于此相关性的包直接过滤<br/>    recency_weight: float = 0.3    # ★特殊点2 recency_weight + relevance_weight == 1.0<br/>    relevance_weight: float = 0.7  #   由 __post_init__ assert 校验——权重自由度收敛成<br/>                                   #   一个旋钮，A/B 调参不至于组合爆炸</code>
```

## 三、GSSC 流水线：Gather → Select → Structure → Compress

ContextBuilder 把「拼上下文」固化成四段流水线：

```
<code>Gather     多源汇集：系统指令 + 记忆检索 + RAG 检索 + 近期历史 + 自定义包（笔记/终端输出）<br/>           外部源逐个容错——单源失败记日志继续，不炸整轮<br/>Select     综合分 = 0.7×相关性 + 0.3×新近性（指数衰减，24h 内高分，下限 0.1）<br/>           系统指令先摘出占用预留预算；其余按分贪心填充到 max_tokens<br/>           相关性：Jaccard 关键词重叠起步，生产替换为向量相似度——评分函数是插槽<br/>Structure  固定骨架：[Role &amp; Policies] / [Task] / [Evidence] / [Context] / [Output]<br/>           每次形态一致——调试可定位分区，评测可 A/B<br/>Compress   兜底压缩：超限按分区截断保留结构；生产可升级为 LLM 摘要/阶梯压缩</code>
```

```
<code># GSSC 主流程（伪代码骨架；完整实现见 hello-agents 工程 code/chapter9/）<br/>class ContextBuilder:<br/>    """上下文构建器：memory_tool / rag_tool 可选注入，缺源自动降级"""<br/>    def build(self, user_query, conversation_history=None,<br/>              system_instructions=None, custom_packets=None) -&gt; str:<br/>        # ── Gather：多源汇集 ──────────────────────────────<br/>        packets = []<br/>        if system_instructions:   # score=1.0、type=system_instruction<br/>            packets.append(self._make_system_packet(system_instructions))<br/>        for source in (self.memory_tool, self.rag_tool):<br/>            try:<br/>                packets.extend(self._fetch(source, user_query))<br/>            except Exception as e:<br/>                # ★特殊点3 容错必须显式：except Exception + 源名与原因进日志，禁裸<br/>                #   except——静默吞错后上下文缺了一块，你都不知道缺的是哪块<br/>                logger.warning("[ContextBuilder] 源 %s 拉取失败: %s", source.name, e)<br/>        if conversation_history:<br/>            packets.extend(self._recent_history(conversation_history, keep=5))<br/>        packets.extend(custom_packets or [])          # 笔记/终端输出从这里进来<br/>        # ── Select：评分 + 贪心填充 ────────────────────────<br/>        sys_pkts = [p for p in packets if p.metadata.get("type") == "system_instruction"]<br/>        others = [p for p in packets if p not in sys_pkts]<br/>        for p in others:<br/>            if p.relevance_score == 0.5:              # 哨兵值 → 现场算 Jaccard 重叠<br/>                p.relevance_score = self._relevance(p.content, user_query)<br/>            p.recency = self._recency(p.timestamp)    # exp(-0.1×age_hours/24)<br/>        score = lambda p: (self.config.relevance_weight * p.relevance_score<br/>                           + self.config.recency_weight * p.recency)<br/>        selected, used = list(sys_pkts), sum(p.token_count for p in sys_pkts)<br/>        for p in sorted(others, key=score, reverse=True):<br/>            if used + p.token_count &gt; self.config.max_tokens:<br/>                # ★特殊点4 预算是硬约束：超限直接 break，宁缺毋滥——绝不「多塞点让<br/>                #   模型自己看着办」，那等于把预算决策交给 prompt 自觉<br/>                break<br/>            selected.append(p); used += p.token_count<br/>        # ── Structure + Compress ──────────────────────────<br/>        return self._compress(self._structure(selected, user_query),<br/>                              self.config.max_tokens)<br/>        # ★特殊点5 Compress 按分区截断并标注「[... 内容已压缩 ...]」，结构完整可定位；<br/>        #   但兜底压缩是下策——正道是 Select 阶段就选准，别把裁剪压力留给最后一步</code>
```

## 四、长程任务三件套：笔记、终端、子代理

窗口再大也扛不住数天的任务，三种长时程手段按任务形态取舍：**压缩整合适合长对话接力，结构化笔记适合有里程碑的迭代任务，子代理架构**适合可并行的探索分析。

### 4.1 NoteTool：结构化笔记

Markdown 正文 + YAML 前置元数据（id/title/type/tags/updated_at），一篇一个文件，外加 `notes_index.json` 索引——人类可读、Git 友好、机器可解析。类型各司其职：`task_state` 阶段进展、`conclusion` 关键结论、`blocker` 阻塞问题、`action` 下一步行动、`reference` 参考资料。

```
<code># 笔记 → 上下文包（伪代码骨架；完整实现见 hello-agents 工程 code/chapter9/）<br/>RELEVANCE_BY_TYPE = {"blocker": 0.9, "action": 0.8, "task_state": 0.75, "conclusion": 0.7}<br/># ★特殊点6 「优先级」不写进 prompt 措辞求模型自觉，而是落成相关性分数进 Select<br/>#   评分——blocker 优先靠预算倾斜实现，不靠模型「记得」去看 blocker<br/>def notes_to_packets(notes: list[dict]) -&gt; list[ContextPacket]:<br/>    return [ContextPacket(<br/>        content=f"[笔记:{n['title']}]\n{n['content']}",<br/>        timestamp=datetime.fromisoformat(n["updated_at"]),<br/>        token_count=len(n["content"]) // 4,       # 粗估即可，Compress 是兜底不是依赖<br/>        relevance_score=RELEVANCE_BY_TYPE.get(n["type"], 0.6),<br/>        metadata={"type": "note", "note_type": n["type"]},<br/>    ) for n in notes]<br/># 每轮调用前：blocker 先列(limit=2) + 按 query 搜索(limit=3) → 按 id 去重 →<br/># 转包 → build(custom_packets=…)；检索失败降级为空列表，主流程照常</code>
```

### 4.2 TerminalTool：即时上下文

代码库数万行塞不进窗口，正确姿势是按需拉取：`find`/`grep` 定位、`head`/`tail` 取样、`wc` 统计，输出直接转 ContextPacket 从 Gather 进流水线。命令执行能力必须上锁，四层安全缺一不可：**白名单**（只放行 `ls/cat/head/tail/find/grep/wc/awk` 等只读命令）；**工作目录沙箱**（新路径 `resolve()` 后与 workspace 做 `relative_to` 校验，防 `../..` 逃逸；`cd` 虽在白名单但必须特殊处理，`~` 一律指向 workspace 而非用户主目录）；**超时**（单命令 30s，防 `find /` 式全盘扫描）；**输出截断**（超 10MB 截断并显式标注——截断本身也是上下文预算保护，失控命令的输出不该吃掉整轮预算）。

### 4.3 子代理架构

主代理负责规划与综合，专长子代理在**干净的上下文窗口**里各自深挖工具调用，只回传凝练摘要（1,000–2,000 tokens）——庞杂的探索上下文留在子代理内部，主代理专注整合推理，适合可并行的复杂研究/分析。工程上每个子代理要带独立 timeout 与预算上限，防止一路探索失控拖垮全局。

## 五、长程案例：代码库维护助手

三件套 + ContextBuilder 组合成跨会话的长程智能体，三天工作流：**D1 探索**——TerminalTool 摸清结构，结论写入 `task_state` 笔记；**D2 分析**——`grep TODO|FIXME` 统计问题，自动落 `blocker` 笔记；**D3 规划**——读最近的任务/阻塞笔记排优先级，计划写回 `action` 笔记。每轮调用流程：

```
<code># 每轮 run() 主流程（伪代码骨架；完整实现见 hello-agents 工程 code/chapter9/）<br/>def run(self, user_input: str, mode: str = "auto") -&gt; str:<br/>    pre = self._preprocess_by_mode(user_input, mode)   # explore/analyze/plan 各自预取<br/>    notes = self._notes_to_packets(self._retrieve_relevant_notes(user_input))<br/>    context = self.context_builder.build(<br/>        user_query=user_input,<br/>        conversation_history=self.conversation_history[-10:],  # 历史只留近几轮<br/>        system_instructions=self._build_system_instructions(mode),<br/>        custom_packets=notes + pre)<br/>    response = self.llm.invoke(context)<br/>    self._auto_archive(user_input, response)<br/>    # ★特殊点7 自动建档（回答含「问题/bug」→ blocker，含「计划/下一步」→ action）<br/>    #   是关键词启发式：建档失败只 log 警告不影响主流程——笔记是增强，不是依赖<br/>    self._update_history(user_input, response)<br/>    return response</code>
```

跨会话连贯性来自笔记而非窗口：第一天的发现第二天还在，一周后 `summary` 一拉全量进度可见。分层分工——**即时访问（Terminal）放易变细节、会话记忆（Memory）放对话语义、持久笔记（Note）放里程碑与阻塞**——三层不重叠，是长程任务不「失忆」也不「淹死」的关键。

### 企业级升级要点

- **压缩升级为阶梯**：GSSC 的 Compress 是一刀切分区截断；生产应做阶梯压缩——SYSTEM 永不压缩 → 规范 → 工具定义 → 最近 N 轮 → 中间摘要 → 早期丢弃，阈值分级（75% 警告 / 85% 触发），与 07-记忆摘要 的增量摘要同一思想——对应 70-基准 **Agent #9 上下文阶梯压缩**。
- **预算双层熔断**：`max_tokens` 只管单次调用；整个任务的累计消耗要靠主循环 `token_budget` 熔断 + 成本追踪兜底——两层都是代码硬约束，不靠 prompt 自觉——对应 **Agent #1 主循环有界终止 / #10 成本追踪与预算熔断**。
- **子代理隔离**：并行深挖必须带 timeout + max_cost 预算、隔离级别与工具白名单，结果摘要压缩回传——对应 **Agent #13 子智能体委派与上下文隔离**。
- **单源失败降级可见**：Gather 容错要 `except Exception` + 源名/原因进日志（禁裸 except、禁静默吞错），失败分区在骨架中显式缺省而非悄悄消失——对应 **Agent #5 工具失败也是消息** 的精神。
- **密钥纪律**：LLM 与各工具的 Key 只走 `os.environ`（缺失时给可行动报错），TerminalTool 子进程透传 `os.environ.copy()` 而非自拼环境字符串——对应 **Agent #2 Provider 抽象 +****`${ENV_VAR}`****占位符展开** 的密钥口径。
