# 短期记忆

> 模块：记忆系统  
> 更新时间：2026-11-15

---

---

核心思路：**用双端队列（****`collections.deque`****）顺序保存对话消息，超过****`max_tokens`****上限时从队首（最早的消息）开始淘汰**。用 deque 而不是 list：`list.pop(0)` 是 O(n)（整体搬移），`deque.popleft()` 是 O(1)。Token 计数优先用 `tiktoken` 精确统计，未安装时退化为「字符数 ÷ 2」粗估（中文约 1 字 ≈ 0.6~1 token，粗估够用且永不失败）。

```
<code># 短期记忆（token 计数为伪代码骨架；完整实现见 ownrag/harness 工程）<br/>import logging<br/>from collections import deque<br/>from typing import Deque, Dict, List<br/><br/>logger = logging.getLogger(__name__)<br/><br/>try:    # ★特殊点1 精确计数可插拔：优先 tiktoken（cl100k_base）逐条 encode 求和<br/>    import tiktoken<br/>    _ENCODING = tiktoken.get_encoding("cl100k_base")<br/><br/>    def _count_tokens(messages: List[Dict]) -&gt; int:<br/>        return sum(len(_ENCODING.encode(m["content"])) for m in messages)<br/>except ImportError:   # ★特殊点2 估算兜底：中文约 1 字 ≈ 0.6~1 token，粗估够用且永不失败<br/>    logger.warning("tiktoken 未安装，token 计数退化为「字符数/2」粗估")<br/><br/>    def _count_tokens(messages: List[Dict]) -&gt; int:<br/>        return sum(max(1, len(m["content"]) // 2) for m in messages)<br/><br/>class ShortTermMemory:<br/>    """短期记忆：deque 双端队列 + Token 截断；淘汰的是完整消息，不截半句"""<br/><br/>    def __init__(self, max_tokens: int = 4000, max_len: int = 200):<br/>        self.max_tokens = max_tokens<br/>        self.messages: Deque[Dict] = deque(maxlen=max_len)<br/>        #   ★特殊点3 条数硬上限：deque 满后自动丢最旧，与 token 上限双保险<br/><br/>    def add(self, role: str, content: str) -&gt; None:<br/>        self.messages.append({"role": role, "content": content})<br/>        self._trim()<br/><br/>    def get_context(self) -&gt; List[Dict]:<br/>        """返回内部消息的拷贝，避免外部直接改动队列状态"""<br/>        return list(self.messages)   # ★特殊点4 不可变边界：防外部绕过 add/trim 直接改历史<br/><br/>    def _trim(self) -&gt; None:<br/>        """从队首（最早的消息）淘汰，直到 token 总量回到上限内"""<br/>        tokens = _count_tokens(list(self.messages))<br/>        while self.messages and tokens &gt; self.max_tokens:<br/>            dropped = self.messages.popleft()    # deque: O(1)（list.pop(0) 是 O(n) 整体搬移）<br/>            tokens -= _count_tokens([dropped])<br/>            logger.debug("淘汰最早消息: role=%s", dropped["role"])<br/>            #   ★特殊点5 淘汰有日志：事后可回放对话被截断的位置<br/><br/>mem = ShortTermMemory(max_tokens=50)   # 一行演示：超长早消息会在 _trim 中被淘汰<br/>mem.add("user", "帮我查一下上海的天气，顺便推荐几条适合跑步的路线。" * 5)</code>
```

注意淘汰的是「完整消息」而不是把消息截成半句——半句话会破坏对话语义；被淘汰的内容交给长期记忆/摘要层接手（见后续两篇）。

---

---

- **阶梯压缩**：短期记忆只做最简单的「丢最旧」，生产实现应先摘要再丢弃——参考 `ai-agent-harness/harness/context_compactor.py` 的 `CompactionLevel` 阶梯（system → 最近 N 轮 → 中间摘要 → 早期丢弃）。
- **预算驱动**：`max_tokens` 即上下文预算，达到阈值才触发压缩（而非每条都算）——对应 `context_compactor.py` 的 `warning_threshold` / `compaction_threshold` 双阈值。
- **精确计数可插拔**：tiktoken 缺失时降级粗估且有日志，不裸抛——参考 `harness/cost_tracker.py` 的 token 统计与预算控制。
- **不可变边界**：`get_context` 返回拷贝，防止外部绕过 add/trim 直接改历史——与 `harness/main_loop.py` 中消息历史只通过循环维护的约束一致。
- **淘汰有日志**：每次淘汰记录 debug 日志，事后可回放对话被截断的位置——参考 `harness/tracer.py`。
