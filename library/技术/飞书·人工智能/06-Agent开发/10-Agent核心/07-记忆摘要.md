## 自动摘要：把历史对话交给 LLM 压缩成要点

核心思路：**将格式化后的对话历史拼进摘要 Prompt，让 LLM 生成要点摘要，从而用一段短文本替代越来越长的消息列表**。工程要点：不能每次都对**全量** messages 重新摘要——长对话会把摘要请求本身撑爆上下文。正确做法是**增量摘要**：原文超过阈值才触发；只把「除最近 N 条之外」的溢出部分与旧摘要合并压缩；近期原文始终保留，供模型看到最新细节。

```text
raw_messages 增长 ──> len(raw) > threshold(30) ?
                        │ 否：不处理（省 token）
                        │ 是：
                        ▼
        overflow = 前 (len - keep_recent) 条溢出消息
        summary  = LLM(旧摘要 + overflow)     ← 增量合并，不重摘全量
        raw      = 只保留最近 keep_recent 条原文

调用 LLM 时：context = [system: 历史摘要] + 近期原文
```

from typing import Dict, List

logger = logging.getLogger(__name__)


class MemorySummarizer:
    """增量摘要：只压缩溢出部分，保留近 N 条原文"""

    def __init__(self, llm, keep_recent: int = 10, threshold: int = 30):
        self.llm = llm                    # LLM 门面见 01-Agent架构.md 1.1 节
        self.keep_recent = keep_recent    # 最近 N 条永远保留原文
        self.threshold = threshold        # 原文条数达到阈值才触发
        self.summary = ""                 # 累积摘要（随增量滚动合并）
        self.raw_messages: List[Dict] = []  # 尚未摘要的近期原文

    async def add(self, role: str, content: str) -> None:
        self.raw_messages.append({"role": role, "content": content})
        if len(self.raw_messages) > self.threshold:
            await self.compact()
            #   ★特殊点1 阈值触发：平时不花摘要 token，攒够溢出量才压缩

    async def compact(self) -> None:
        cut = len(self.raw_messages) - self.keep_recent
        if cut <= 0:
            return                        # 没攒够溢出量，不压缩
        overflow = self.raw_messages[:cut]
        #   ★特殊点2 只摘要溢出部分，并与旧摘要滚动合并——绝不重摘全量，
        #     否则摘要请求本身就会撑爆上下文
        self.summary = await self._summarize(self.summary, overflow)
        self.raw_messages = self.raw_messages[cut:]
        #   ★特殊点3 保留近 N 条原文：模型看得清最新细节
        logger.info("增量摘要完成，剩余原文 %s 条", len(self.raw_messages))

### 企业级升级要点

- **增量而非全量**：只摘要溢出部分并与旧摘要滚动合并，摘要请求本身不会撑爆上下文——对应 `ai-agent-harness/harness/context_compactor.py` 的 `MIXED` 策略（最近消息保留 + 远端摘要）。
- **阈值触发**：原文超过 `threshold` 才压缩，`keep_recent` 对应 compactor 的 `preserve_last_n`（保留最近 N 轮）。
- **压缩分级**：本篇的「摘要 vs 原文」是最基础的两级；生产应做阶梯降级（system 永不压缩 → 工具定义 → 近期 → 中期摘要 → 早期丢弃）——见 `context_compactor.py` 的 `CompactionLevel`。
- **可测性**：`FakeLLM` 测试桩让摘要逻辑离线可验证——参考 `ai-agent-harness/tests/` 的单测组织方式。
- **留痕可回放**：每次压缩记录日志（剩余原文条数、摘要更新），配合 `harness/tracer.py` 可回放上下文被压缩的时间点。
