# 记忆摘要

> 模块：记忆系统  
> 更新时间：2026-11-15

---

---

核心思路：**将格式化后的对话历史拼进摘要 Prompt，让 LLM 生成要点摘要，从而用一段短文本替代越来越长的消息列表**。工程要点：不能每次都对**全量** messages 重新摘要——长对话会把摘要请求本身撑爆上下文。正确做法是**增量摘要**：原文超过阈值才触发；只把「除最近 N 条之外」的溢出部分与旧摘要合并压缩；近期原文始终保留，供模型看到最新细节。

```
<code>raw_messages 增长 ──&gt; len(raw) &gt; threshold(30) ?<br/>                        │ 否：不处理（省 token）<br/>                        │ 是：<br/>                        ▼<br/>        overflow = 前 (len - keep_recent) 条溢出消息<br/>        summary  = LLM(旧摘要 + overflow)     ← 增量合并，不重摘全量<br/>        raw      = 只保留最近 keep_recent 条原文<br/><br/>调用 LLM 时：context = [system: 历史摘要] + 近期原文</code>
```

```
<code># 记忆摘要器（伪代码：重点在增量摘要策略）<br/>import logging<br/>from typing import Dict, List<br/><br/>logger = logging.getLogger(__name__)<br/><br/><br/>class MemorySummarizer:<br/>    """增量摘要：只压缩溢出部分，保留近 N 条原文"""<br/><br/>    def __init__(self, llm, keep_recent: int = 10, threshold: int = 30):<br/>        self.llm = llm                    # LLM 门面见 01-Agent架构.md 1.1 节<br/>        self.keep_recent = keep_recent    # 最近 N 条永远保留原文<br/>        self.threshold = threshold        # 原文条数达到阈值才触发<br/>        self.summary = ""                 # 累积摘要（随增量滚动合并）<br/>        self.raw_messages: List[Dict] = []  # 尚未摘要的近期原文<br/><br/>    async def add(self, role: str, content: str) -&gt; None:<br/>        self.raw_messages.append({"role": role, "content": content})<br/>        if len(self.raw_messages) &gt; self.threshold:<br/>            await self.compact()<br/>            #   ★特殊点1 阈值触发：平时不花摘要 token，攒够溢出量才压缩<br/><br/>    async def compact(self) -&gt; None:<br/>        cut = len(self.raw_messages) - self.keep_recent<br/>        if cut &lt;= 0:<br/>            return                        # 没攒够溢出量，不压缩<br/>        overflow = self.raw_messages[:cut]<br/>        #   ★特殊点2 只摘要溢出部分，并与旧摘要滚动合并——绝不重摘全量，<br/>        #     否则摘要请求本身就会撑爆上下文<br/>        self.summary = await self._summarize(self.summary, overflow)<br/>        self.raw_messages = self.raw_messages[cut:]<br/>        #   ★特殊点3 保留近 N 条原文：模型看得清最新细节<br/>        logger.info("增量摘要完成，剩余原文 %s 条", len(self.raw_messages))<br/><br/>    async def _summarize(self, prev_summary: str,<br/>                         messages: List[Dict]) -&gt; str:<br/>        ...    # prompt = 历史摘要 + 新对话 → 合并为要点摘要（保留任务<br/>        #   目标 / 已做决定 / 关键事实 / 待办；_format_messages 从略）<br/>        return (await self.llm.generate(prompt)).strip()<br/><br/>    def get_context(self) -&gt; List[Dict]:<br/>        ...    # 上下文 = [system: 历史摘要] + 近期原文——摘要在前注入<br/>        #   背景，原文在后提供最新细节<br/><br/><br/># 单测思路：注入返回固定摘要的假 LLM 即可离线验证，无需真实网络调用<br/># 完整实现见 ai-agent-harness 工程（同思想：harness/context_compactor.py）</code>
```

注意 `get_context()` 的输出顺序：摘要在前（作为 system 提示注入背景），近期原文在后——模型既能「记得很久以前的事」，又能看清最近的细节。

---

---

- **增量而非全量**：只摘要溢出部分并与旧摘要滚动合并，摘要请求本身不会撑爆上下文——对应 `ai-agent-harness/harness/context_compactor.py` 的 `MIXED` 策略（最近消息保留 + 远端摘要）。
- **阈值触发**：原文超过 `threshold` 才压缩，`keep_recent` 对应 compactor 的 `preserve_last_n`（保留最近 N 轮）。
- **压缩分级**：本篇的「摘要 vs 原文」是最基础的两级；生产应做阶梯降级（system 永不压缩 → 工具定义 → 近期 → 中期摘要 → 早期丢弃）——见 `context_compactor.py` 的 `CompactionLevel`。
- **可测性**：`FakeLLM` 测试桩让摘要逻辑离线可验证——参考 `ai-agent-harness/tests/` 的单测组织方式。
- **留痕可回放**：每次压缩记录日志（剩余原文条数、摘要更新），配合 `harness/tracer.py` 可回放上下文被压缩的时间点。
