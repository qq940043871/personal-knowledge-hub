# 任务规划

> 模块：Agent编排  
> 更新时间：2026-11-15

---

---

> 任务规划器通过 LLM 将任务分解为可执行的子任务列表，再经 refine 做顺序优化：检查依赖关系、去除冗余、优化并行度。**LLM 输出解析是规划链路最高频的失败点**——模型可能输出带 markdown 围栏的 JSON、夹带解释文字、甚至纯自然语言，因此解析必须有「重试 + 降级」兜底，绝不能让一次解析失败炸掉整个规划流程。

```
<code># 任务规划器（伪代码：重点在三层解析兜底与特殊点）<br/>from dataclasses import dataclass, field<br/>from typing import List, Optional<br/><br/><br/>@dataclass<br/>class Task:<br/>    """子任务：id 供依赖引用，depends_on 声明前置任务 id"""<br/>    id: int<br/>    description: str<br/>    depends_on: List[int] = field(default_factory=list)<br/><br/><br/>class TaskPlanner:<br/>    """任务规划器（LLM 门面见 01-Agent架构.md 1.1 节：env Key + 超时重试）"""<br/><br/>    def __init__(self, llm, max_parse_retries: int = 1):<br/>        self.llm = llm<br/><br/>    async def decompose(self, task: str) -&gt; List[Task]:<br/>        prompt = f"将任务分解为子任务，严格只输出 JSON 数组：{task}"<br/>        response = await self.llm.generate(prompt)<br/>        tasks = self._parse_tasks(response)<br/><br/>        if tasks is None:                    # ① 首次解析失败 → 带纠错提示重试<br/>            response = await self.llm.generate(<br/>                f"{prompt}\n\n你上次的输出不是合法 JSON：\n{response[:200]}")<br/>            tasks = self._parse_tasks(response)<br/>            #   ★特殊点1 LLM 输出解析是规划链路最高频失败点——重试时把<br/>            #     原输出喂回去让模型自查，而不是盲目重来<br/><br/>        if tasks is None:                    # ② 重试仍失败 → 降级为单任务<br/>            tasks = [Task(id=1, description=task)]<br/>            #   ★特殊点2 降级兜底：调用方拿到的永远是合法 List[Task]，<br/>            #     一次解析失败绝不炸掉整个规划流程<br/>        return tasks<br/><br/>    def _parse_tasks(self, raw: str) -&gt; Optional[List[Task]]:<br/>        """把 LLM 输出解析为任务列表；任何失败都返回 None（不抛异常）"""<br/>        #   ★特殊点3 解析函数永远返回值而不是抛异常，三步全是防御：<br/>        #     ① re 剥掉 markdown 围栏  ② 截取首尾 [ ] 之间内容<br/>        #     ③ json.loads + Task 字段校验，任何异常 → return None<br/>        ...<br/><br/>    async def refine(self, tasks: List[Task]) -&gt; List[Task]:<br/>        """顺序优化（纯 CPU 计算，保留 async 兼容流水线接口）：<br/>        去重 → 修复悬空依赖 → Kahn 拓扑排序（被依赖者在前）→<br/>        成环时未排入任务追加末尾——实现从略"""<br/>        ...</code>
```

*完整实现见 ai-agent-harness 工程（解析兜底与 Kahn 拓扑排序的完整实现）。*

规划链路的失败几乎都发生在「LLM 输出 → 结构化任务」这一步，兜底分三层：

```
<code>LLM 原始输出<br/>   │<br/>   ├─ ① 清洗：剥 markdown 围栏、截取首尾 [ ] 之间的内容<br/>   │<br/>   ├─ ② 解析失败 → 带纠错提示重试一次（把原输出喂回去让模型自查）<br/>   │<br/>   └─ ③ 重试仍失败 → 降级为单任务（原任务整体作为唯一步骤，流程不中断）</code>
```

要点：解析函数**永远返回值而不是抛异常**；降级路径保证 `decompose` 的调用方拿到的永远是合法的 `List[Task]`。

---

---

- **解析失败兜底**：LLM 输出解析是规划链路最高频失败点，「清洗 → 重试一次 → 降级」三层兜底对应 harness 中 Provider 层的容错思想——参考 `ai-agent-harness/harness/provider/`（重试与退避）与 `harness/main_loop.py`（错误计数不中断循环）。
- **规划产物可校验**：`Task` 用 dataclass 明确类型，依赖用 id 显式声明；生产建议用 pydantic 校验 LLM 输出——参考 `ai-agent-harness/harness/tools/base.py`（结构化定义 + infer_schema）。
- **refine 用拓扑排序真实现**：去重、悬空依赖修复、成环降级，而非空壳注释；可并行的子任务交给下游 `asyncio.gather` 执行——参考 `ai-agent-harness/harness/multi_agent.py`。
- **日志贯穿规划链路**：解析失败、重试、降级都有 `logger.warning` 留痕，便于离线评估规划质量——参考 `harness/tracer.py` 的链路追踪。
- **无 LLM 可测**：`_parse_tasks` 是纯函数，配 `if __name__ == "__main__"` 即可离线验证兜底逻辑——对应 `ai-agent-harness/tests/` 的单测思路。
