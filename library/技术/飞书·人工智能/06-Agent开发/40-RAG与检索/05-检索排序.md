## 一、混合检索

**search 契约口径（全库统一）**：`VectorStore.search` 接收「embedding 向量」，不接收原始 query 字符串（与 01-RAG原理 的向量库实现同口径）——query 文本只喂 BM25，embedding 在 retrieve 入口只算一次、向量检索复用。

```python
# 混合检索（伪代码骨架：重点在契约与 RRF；完整实现见 ownrag/harness 工程）
from collections import defaultdict
from dataclasses import dataclass
from typing import List

@dataclass
class Document:
    """检索结果块（与 01-RAG原理 的 Doc 同构；id 用于 RRF 跨路去重）"""
    id: str
    content: str
    source: str = ""
    score: float = 0.0

class HybridRetriever:
    """混合检索器。可注入组件：Embedder / VectorStore 最小实现见 01-RAG原理
    （search 契约 = 接收 embedding 向量）；BM25 用 rank_bm25；
    Reranker 用 CrossEncoder（见 06-RAG系统实战 场景4）"""

    def __init__(self, vector_store, bm25, reranker, embedder):
        self.vector_store, self.bm25 = vector_store, bm25
        self.reranker, self.embedder = reranker, embedder

    async def retrieve(self, query: str, top_k: int = 10) -> List[Document]:
        # ★特殊点1 search 契约统一：向量库只收 embedding 向量（query 文本只喂 BM25）
        query_embedding = (await self.embedder.embed(query))[0]   # 向量化一次，两路共用
        vector_results = await self.vector_store.search(query_embedding, top_k * 2)
        vector_docs = [doc for doc, _ in vector_results]
        bm25_docs = list(self.bm25.search(query, top_k * 2))   # BM25 天然按词项匹配
        fused = self._reciprocal_rank_fusion([vector_docs, bm25_docs])
        return await self.reranker.rerank(query, fused, top_k)   # 重排序

    def _reciprocal_rank_fusion(self, result_lists: List[List[Document]],
                                k: int = 60) -> List[Document]:
        """RRF 融合：score = Σ 1/(k + rank + 1)。
        修复点：同一候选可能在两路都命中——代表块取「名次最优」那一路的 doc"""
        doc_scores: dict = defaultdict(float)
        best: dict = defaultdict(lambda: (10 ** 9, None))  # doc_id -> (最优名次, doc)
        for results in result_lists:
            for rank, doc in enumerate(results):
                doc_scores[doc.id] += 1.0 / (k + rank + 1)
                if rank < best[doc.id][0]:       # ★特殊点2 RRF 按名次融合，不比原始分：
                    best[doc.id] = (rank, doc)   #   BM25 无上界、余弦在 [0,1]，量纲不同
                    #   直接加权没有意义（归一化说明见下节）；名次更优那一路作代表
        sorted_docs = sorted(doc_scores.items(), key=lambda x: x[1], reverse=True)
        return [best[doc_id][1] for doc_id, _ in sorted_docs]
```

## 二、分数归一化与权重

**为什么用 RRF 而不是分数加权**：

- BM25 分数无上界（随语料规模与查询长度变化），余弦相似度在 [0, 1]——两者量纲不同，直接加权相加没有意义。真要分数融合，必须先做归一化（min-max 或 z-score），且归一化统计量要随语料更新。
- RRF 只用名次（`1/(k + rank)`），天然免量纲问题，k=60 是社区惯用值，不需要调。
- **没有评测集之前调权重都是猜**——等权 RRF 起步，评测先行；有了评测集再谈加权、再调 ef/M/权重。

### 企业级升级要点

- **RRF 等权起步**：没有评测集之前调权重都是猜（评测先行原则），候选池宁窄勿宽——见 `ai-rag-self-engineering/ownrag/ownrag/retrieve/hybrid.py` 的 `rrf_fuse`。
- **融合结果附各路命中详情**：融合后的分数看不出通道贡献，调试要看「是哪一路把它捞上来的」——见同文件 `rrf_fuse` 返回的 `channels` 字段。
- **先过滤后召回**：metadata 过滤在检索前做，过滤责任不进 Prompt——见 `ai-rag-self-engineering/ownrag/ownrag/retrieve/hybrid.py` 的 `search` 注释。
- **重排失败降级可见**：重排服务挂了退回 RRF 顺序继续问答，日志显式记录降级原因——见 `ai-rag-self-engineering/ownrag/ownrag/retrieve/rerank.py`。
- **拒答语义落在重排分**：向量通道永远能「捞回语义邻近块」，RRF 名次分区分不了实质依据，充分性闸门按重排分下限校验——见 `ai-rag-self-engineering/ownrag/ownrag/generate/gates.py` 的 `sufficiency_check`。
