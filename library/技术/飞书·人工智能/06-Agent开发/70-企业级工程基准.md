# 企业级工程基准

> 模块：企业落地基准
> 来源：personal-ai-engineering（ownrag 自研 RAG 工程 + ai-agent-harness Agent 运行时）
> 用途：RAG 与 Agent 各篇目「企业级升级要点」的总纲，逐条给出能力定义与对应源码

---

## 一、什么是「企业级」

教程代码与企业级代码的差距不在功能，而在**故障下的行为**：

- 教程代码：快乐路径跑通即结束——没有配置管理、没有重试超时、没有降级、没有可观测性、没有评测；
- 企业级代码：**错误在启动期暴露**（配置校验）、**失败也是结果**（结构化返回而非崩溃）、**降级必须可见**（理由进日志/事件）、**预算硬约束**（token/成本/轮次在代码里熔断，不靠模型自觉）、**可回放**（每次问答有 trace）。

下面两份清单是本知识库 RAG/Agent 各篇「企业级升级要点」的统一口径，每条都对应参考工程中的真实源码。

## 二、企业级 RAG 基准（ownrag）

参考工程：`ai-rag-self-engineering/ownrag/`（FastAPI + SQLite + Chroma，不依赖 Dify/LangChain 的自研完整链路）

| # | 能力 | 模式说明 | 对应源码 |
|---|------|---------|---------|
| 1 | 配置即代码 + 启动期校验 | YAML 配置随包分发 → 环境变量覆盖 → `.env` 本地层；`get_settings()` 缓存单例；配置错误**启动期抛出**，不在运行期暴露；密钥只走环境变量不落盘 | `ownrag/config.py`、`core/registry.py` |
| 2 | 配置驱动管道 DSL | YAML 声明步骤序列（pdf_v1/av_v1/excel_v1），步骤类型必须在 `STEP_REGISTRY` 注册（`@register` 装饰器）；步骤统一 `run(ctx, params) -> StepResult` 且无状态；新数据源 = 加一段 YAML + 注册一个类，代码零改动 | `configs/pipelines.yaml`、`core/pipeline.py` |
| 3 | 状态外置 + 检查点续跑 | 每步执行前把状态 JSON 落任务表，中断后同入口 resume 按 `current_step` 续跑；重跑安全（按 doc_id 原子替换索引） | `core/tasks.py` |
| 4 | 失败入待办，绝不静默 | 解析失败/校验不过全部进待办表（人工队列），带 `[pipeline/step]` 前缀原因 + trace_id；后台线程未捕获异常也兜到任务失败 | `core/tasks.py`（`add_todo`）、`api/routes_docs.py` |
| 5 | 步骤级 fallback 降级链 | 主步骤失败按序尝试 fallback（MinerU→PyMuPDF）；依赖缺失 → 通道显式 skipped 而非静默；**降级可见**——降级理由随事件、trace、debug 接口三处可见 | `core/pipeline.py`（`_run_with_fallbacks`） |
| 6 | 三层供应商分派（同接口同异常） | chat/embed/rerank 各自按 provider 配置分派；调用方只 import 门面，换供应商零调用点改动；同层共用一个异常类，错误信息带 base_url+模型名 | `generate/client.py`、`index/embedder.py` |
| 7 | 连接级熔断 + 细粒度超时 | 只对连接级失败熔断 20s 快速失败；4xx/5xx 不熔断（配额/配置问题重试无用）并按状态码给可行动提示；httpx 分项超时（connect=5, read=300） | `index/embedder.py` |
| 8 | 结构感知切分 + 锚点即引用 | 标题树优先、表格/代码永不跨块；块首注入「文档标题 > 章节路径」短头防召回漂移；锚点（page/[mm:ss]/heading_path）在解析层固化；块 meta 记录 pipeline/chunker 参数/embed_version——换嵌入模型必须换版本全量重灌 | `index/chunker.py`、`ingest/base.py` |
| 9 | 混合检索（双通道 + RRF） | 向量+BM25 双路召回、RRF 名次融合（**没有评测集之前调权重都是猜**）；返回值带 channels（哪一路捞的）与 retrieval_path 计数；FTS5 不切 CJK 时逐字化兜底，索引/查询两侧同函数 | `retrieve/hybrid.py`、`index/store.py` |
| 10 | 上下文预算显式化 | 先算容量再拼装：预算 = num_ctx − prompt 开销（渲染探针实测）− 输出预留 − 安全余量；超预算按候选序丢尾块、丢块清单随事件上报；`est_tokens` 全工程唯一口径，切分与预算共用 | `generate/budget.py`、`api/routes_chat.py` |
| 11 | 两道纯代码闸门 | 闸门一（生成前）充分性检查：候选空或最高重排分 < 阈值 → 拒答 `no_evidence`，**零模型消耗**；闸门二（生成后）引用检查：引用块必须在候选池内、答案中数字/日期必须能在所引块原文逐字找到；违规 → 带清单反馈重答一次，仅「通过或违规更少」才采纳 | `generate/gates.py`、`api/routes_chat.py` |
| 12 | 入库前人工复核闸 | 切分后、索引前停一道人工闸；自动检查只报事实（空正文/字符密度阻断，乱码率/表格拍平提示），**刻意不把能否入库压成单一分数**；阻断项存在时审批接口返回 409（不能点通过绕过） | `review.py`、`core/db.py` |
| 13 | SSE 事件契约 + 编排分层 | 流式问答定义稳定事件序列（hit/ctx/token/gate/no_evidence/done/error，顺序是产品契约）；编排拆成可单测单元，`_stream` 只管事件顺序；右栏展示「模型真正看到的块」 | `api/routes_chat.py` |
| 14 | 全链路 trace + 问答日志回流 | 每步一行 Timer 计毫秒，失败也是一条正常记录；任何一次「答案不对」10 分钟内能回答：召回给了什么、模型看到了什么、闸门放过了什么；qa_log 是评测集扩充的唯一原料 | `core/trace.py`、`core/db.py` |
| 15 | 评测先行回归门禁 | 固定问答集三判中口径（找对/找全/该拒答的拒答），全判中退出码 0 否则 1——**任何切分/embedding/解析器变更先跑这个再合入**；本地一键 check = ruff + mypy + pytest(全程打桩零出网) + coverage 门槛 | `scripts/eval_recall.py`、`pyproject.toml` |

## 三、企业级 Agent 基准（ai-agent-harness）

参考工程：`ai-agent-harness/`（多 Provider Agent 运行时，CLI/Web/GUI 三模式）

| # | 能力 | 模式说明 | 对应源码 |
|---|------|---------|---------|
| 1 | Think→Act→Observe 主循环 + 有界终止 | 循环受三重边界约束：`max_turns` 轮次上限、`token_budget` 预算熔断（带结构化超限报告）、`stop()` 协作式取消；无工具调用 = 任务完成 | `harness/main_loop.py` |
| 2 | Provider 抽象层 + 工厂切换 | `BaseProvider` ABC 统一 complete/format_tool_result 契约，`LLMResponse/ToolCall/Usage` 数据类抹平各家差异；工厂 + YAML `${ENV_VAR}` 占位符展开；换模型只改配置 | `harness/provider/base.py`、`provider/factory.py` |
| 3 | 工具注册表 + Schema 自动推断 | `@registry.tool(description=...)` 从函数签名+类型注解自动推断 JSON Schema；dispatch 过滤无效参数；ToolGroup 实现组内白名单（权限隔离雏形） | `harness/tools/base.py`、`tools/registry.py` |
| 4 | 并发工具执行 + 并发上限 | 独立工具调用 `asyncio.gather(*tasks, return_exceptions=True)` 并发执行，单工具异常不炸整轮；`asyncio.Semaphore` 控并发数 | `harness/main_loop.py`、`tools/registry.py` |
| 5 | 工具失败也是消息 | 工具异常捕获后转 `role:tool` 消息回传历史，让模型读到错误自行调整策略；文件工具对 FileNotFoundError 返回可读错误而非抛异常；分类异常族 ToolNotFoundError/ToolArgumentError/ToolExecutionError | `harness/tools/registry.py`（`dispatch_safe`） |
| 6 | 多阶段中间件责任链 | 拦截点覆盖 PRE/POST_TOOL_CALL、PRE/POST_LLM_CALL、PRE/POST_RESPONSE 六阶段；危险命令正则表带 severity 与 approval_level 分级，命中即短路；内置敏感信息过滤与滑动窗口限速 | `harness/middleware.py` |
| 7 | 人工审批系统 | `ApprovalHandler` ABC 可插拔（控制台测试用/飞书生产用）；审批模板按操作类型与 RiskLevel 四级（LOW 自动/MEDIUM 确认/HIGH 审批/CRITICAL 多重审批）配置审批链、超时、理由必填 | `harness/middleware.py`、`integrations/approval_templates.py` |
| 8 | 会话物理隔离 + JSONL 追加持久化 | 每 Session 一个目录：元数据 + `messages.jsonl` 追加写（单行损坏不伤全库，读取跳过坏行）+ 工件目录；`cleanup_old_sessions` 自动清理 | `harness/session/manager.py` |
| 9 | 上下文阶梯压缩 | 压缩优先级：SYSTEM 永不压缩 → 规范 → 工具定义 → 最近 N 轮 → 中间摘要 → 早期丢弃；阈值分级（75% 警告 / 85% 触发）；TokenCounter Protocol + tiktoken 降级链 | `harness/context_compactor.py` |
| 10 | Token 成本追踪 + 预算熔断 | 按模型定价表（含 cache 分项计价）逐轮落 CostRecord；`should_stop()` 供主循环超预算熔断；成本细分、报告生成、JSON 持久化恢复；`@track_cost` 无侵入挂载 | `harness/cost_tracker.py` |
| 11 | 链路追踪 Span 树 | trace_id + 父子嵌套 Span（LLM_CALL/TOOL_CALL/COMPACTION/ERROR），捕获输入输出/耗时/状态，JSON 落盘可回放；`analyze_trace()` 找最慢操作 | `harness/tracer.py` |
| 12 | 死循环检测与行为干预 | 检测五类异常模式：重复执行/振荡/卡住/无进展/无限调用工具；滑动窗口记录 BehaviorRecord，触发阈值产出带 severity 与证据的 LoopWarning 并自动注入干预提示——**防死循环做成可配置组件而非 prompt 祈祷** | `harness/system_reminders.py` |
| 13 | 子智能体委派与上下文隔离 | 委派任务自带 timeout + max_cost 预算 + 优先级；隔离级别（strict/shared/merged）、allowed/denied_tools、readonly_mode；结果带 duration/cost/tokens 与文件变更清单；省 token 四策略：规划用便宜模型、上下文隔离、结果摘要压缩回传、按职责裁剪工具集 | `harness/subagent.py`、`multi_agent.py` |
| 14 | 持久记忆 + Prompt 模块化组装 | 记忆按 WORKING/EPISODIC/SEMANTIC/PROCEDURAL/TODO 分型，条目带 importance/tags；System Prompt 建造者模式分节组装（每节带 priority 可开关） | `harness/memory_manager.py`、`prompt/builder.py` |
| 15 | 多级模糊匹配编辑 + 基准评测 | 编辑工具四级匹配降级（精确→空白归一→行号→相似度≥0.85），old_str 多处命中拒绝执行；基准框架跑预设任务集产出 BenchmarkReport 并与上一份对比——**Agent 能力可量化回归** | `harness/tools/edit.py`、`benchmark.py` |

## 四、代码公共约定（全库统一口径）

升级篇目的代码块遵循参考工程的公共纪律：

1. **密钥**：只走 `os.environ`，缺失时给可行动报错；永不硬编码、不落配置文件
2. **失败也是结果**：可恢复边界返回结构化结果（`StepResult.fail` / `(success, result_or_error)` 元组 / `LoopResult(status=ERROR)`），异常只在不可恢复处抛
3. **降级必须显式**：降级理由进 trace/事件/返回说明文案，禁止静默吞错、禁止裸 `except: pass`
4. **注册表模式贯穿**：步骤注册表 / 工具注册表；新能力 = 注册一个类，不改调度代码
5. **预算硬约束**：token/成本/轮次在代码中熔断，不靠 prompt 自觉
6. **可回放**：每个 run 有 trace/session 可复盘；失败也是一条正常记录
7. **重依赖可选化**：缺依赖按接口契约显式失败进待办，绝不静默

## 六、学习路径建议

1. 先跑通本目录 `40-RAG与检索/06-RAG系统实战.md` 的场景 1-5（修复后的现行 API 教程代码）
2. 再对照本文 RAG #10/#11 理解「上下文预算 + 双闸门」为什么比「提示词里写注意幻觉」可靠
3. Agent 侧先读 `10-Agent核心/01-Agent架构.md` 的有界主循环，再对照 Agent #5 理解「工具失败也是消息」的自愈机制
4. 最终以 ownrag 的 `scripts/eval_recall.py` 口径建立自己的评测集——**企业级的分水岭是有没有回归门禁**
