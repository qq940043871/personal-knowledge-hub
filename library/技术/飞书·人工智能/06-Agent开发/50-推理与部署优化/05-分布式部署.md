```
<code># LLM API 服务（伪代码骨架：重点在四个企业级特殊点；完整实现见 ownrag/harness 工程）<br/>import logging<br/>import os<br/>from typing import List, Optional<br/><br/>from fastapi import FastAPI, Header, HTTPException<br/>from pydantic import BaseModel, Field<br/><br/>API_KEY = os.environ["API_KEY"]     # 服务鉴权 Key：环境变量注入，禁止硬编码<br/><br/>class ChatRequest(BaseModel):<br/>    """请求体（OpenAI 兼容的最小子集），字段自带校验"""<br/>    model: str = "default"<br/>    messages: List[ChatMessage]    # ChatMessage(role, content) 定义从略<br/>    max_tokens: int = Field(default=1024, ge=1, le=8192)<br/>    temperature: float = Field(default=0.7, ge=0.0, le=2.0)<br/>    #   ★特殊点1 请求体即契约：pydantic 声明字段与 ge/le 取值范围，<br/>    #     非法输入在反序列化层就被拒（与 harness 工具「签名即 schema」思想一致）<br/><br/>def create_app(llm=None) -&gt; FastAPI:<br/>    """工厂初始化：引擎依赖注入而非全局变量，测试时可注入桩引擎"""<br/>    engine = llm or LLM()          # LLM 本地推理引擎占位（可接 vLLM / TGI）<br/>    app = FastAPI(title="LLM Server")<br/><br/>    @app.post("/v1/chat/completions")<br/>    async def chat_completions(request: ChatRequest,<br/>                               api_key: Optional[str] = Header(None)):<br/>        #   ★特殊点2 鉴权前置：API-Key 请求头校验放在业务逻辑之前<br/>        if api_key != API_KEY:<br/>            raise HTTPException(status_code=401, detail="Invalid API key")<br/>        try:<br/>            content = await engine.chat(request.messages, request.max_tokens, request.temperature)<br/>        except Exception:<br/>            logging.exception("推理失败: model=%s", request.model)   # 异常有界：记堆栈转 500，worker 不被打崩<br/>            raise HTTPException(status_code=500, detail="inference failed")<br/>        #   ★特殊点3 OpenAI 兼容返回体：choices[0].message.{role, content}<br/>        #     层级严格对齐，客户端 SDK 无需适配层<br/>        return {"choices": [{"message": {"role": "assistant", "content": content}}]}<br/><br/>    return app<br/><br/>if __name__ == "__main__":<br/>    #   ★特殊点4 0.0.0.0 安全提示：会把服务暴露到所有网卡——只应在容器 /<br/>    #     有防火墙隔离的内网使用；公网部署挂网关后并叠加 TLS 与限流<br/>    uvicorn.run(create_app(), host="0.0.0.0", port=8000,<br/>                timeout_keep_alive=65)   # keep-alive 显式超时</code>
```

---

---

- **请求体即契约**：`ChatRequest` 用 pydantic 声明字段与取值范围（`Field(ge=..., le=...)`），非法输入在反序列化层就被拒——与 harness 工具「签名即 schema」的思想一致（`ai-agent-harness/harness/tools/base.py`）。
- **依赖注入而非全局变量**：`create_app(engine)` 工厂初始化，测试可注入桩引擎——参考 harness 的 Provider 抽象（`ai-agent-harness/harness/provider/`）。
- **鉴权前置**：API-Key 请求头校验放在业务逻辑之前，Key 从 `os.environ` 注入；公网部署再叠加网关限流与 TLS——对应 `harness/middleware.py` 的审批/拦截中间件思想。
- **OpenAI 兼容返回体**：`choices[0].message.{role, content}` 层级严格对齐，客户端 SDK 无需适配层——接口兼容性是分布式部署的第一约定。
- **异常有界**：推理异常记录堆栈后转 500，worker 不被打崩；keep-alive 显式超时——同 `harness/main_loop.py` 的「错误计数、循环不中断」哲学。
