```
<code>import os  # noqa: F401  （HF token 经环境变量注入，禁止硬编码）<br/><br/>import torch<br/>from transformers import AutoModelForCausalLM, BitsAndBytesConfig<br/><br/># 注意：meta-llama/Llama-2-7b 是 gated 仓库——需先在 Hugging Face 模型页申请访问权限，<br/># 并 export HF_TOKEN=&lt;你的token&gt;（或执行 huggingface-cli login），否则下载报 401/403。<br/># 依赖：pip install transformers accelerate bitsandbytes<br/>quantization_config = BitsAndBytesConfig(<br/>    load_in_4bit=True,<br/>    bnb_4bit_compute_dtype=torch.float16,   # 反量化后的计算精度<br/>    bnb_4bit_quant_type="nf4",              # NF4：LLM 场景最常用的 4bit 类型<br/>)<br/><br/>model = AutoModelForCausalLM.from_pretrained(<br/>    "meta-llama/Llama-2-7b",<br/>    quantization_config=quantization_config,<br/>    device_map="auto",                      # 4bit 加载必须指定，否则直接 ValueError<br/>    torch_dtype=torch.float16,              # 非量化模块（LayerNorm 等）的存储精度<br/>)</code>
```

---

---

- **配置显式且完整**：`device_map="auto"` + `torch_dtype` 是 bitsandbytes 4bit 加载的硬前提，缺失即 ValueError——部署脚本应像 harness 一样把所有前置条件显式化（参考 `ai-agent-harness/config/config.yaml.example` 的配置外置模式）。
- **凭据走环境变量**：gated 模型的 HF token 用 `os.environ["HF_TOKEN"]` / `huggingface-cli login` 注入，绝不写进代码或配置文件——与 harness「API Key 一律 os.environ」的约定一致。
- **量化类型有依据**：NF4/FP4、compute dtype 的取舍应记录在部署文档中，便于回滚与复现——对应 harness 的 CHANGELOG / docs 实践。
- **先测后上**：量化后务必跑回归集对比输出质量（困惑度/任务指标），可参考 `ai-agent-harness/harness/benchmark.py` 的基准评测思路。
