## 一、批量处理

核心思路：**引擎内置一个常驻 worker 消费循环**（阻塞取队列 → 攒批 → 批量前向），每个请求入队时登记一个 `asyncio.Future`，结果（**包括异常**）统一写入 Future——调用方 `await Future` 即可拿到结果或错误，不存在忙轮询，也不会因异常导致请求永远留在结果表里死等。

```python
# 批量推理引擎（伪代码：重点在 worker 消费循环与 Future 结果表；完整实现见 ownrag/harness 工程）
import asyncio
import uuid
from typing import Dict

class BatchedInference:
    """批量推理引擎：常驻 worker 消费循环 + Future 结果表。
    start/stop、攒批 _collect_batch / 填充 _pad_sequence 实现从略（InferenceRequest 即单条请求）。"""

    def __init__(self, model, max_batch: int = 8, max_queue: int = 1024):
        self.model = model
        self.max_batch = max_batch
        #   ★特殊点1 背压显式化：Queue(maxsize) 队列满时 add_request 挂起——
        #     过载时上游等待，而不是请求无限堆积打爆内存（OOM）
        self.queue: asyncio.Queue = asyncio.Queue(maxsize=max_queue)
        self.futures: Dict[str, asyncio.Future] = {}   # request_id -> Future

    async def add_request(self, request) -> str:
        request_id = uuid.uuid4().hex
        self.futures[request_id] = asyncio.get_running_loop().create_future()
        await self.queue.put((request_id, request))
        return request_id

    async def _run_worker(self) -> None:
        """消费循环：阻塞取队列 → 10ms 窗口攒批 → 批量前向 → 写回 Future"""
        while True:
            first_id, first_req = await self.queue.get()
            #   ★特殊点2 阻塞 get 零忙轮询：无请求时挂起，队列状态只由 worker 改变，
            #     修掉旧方案 empty() 与 get() 的竞态（请求可能永远滞留、无人触发）
            batch_ids, batch_reqs = self._collect_batch(first_id, first_req)   # 满员或 10ms 窗口到期即触发

            try:
                inputs = self._pad_sequence([r.input_ids for r in batch_reqs])
                outputs = await self.model.generate_batch(inputs)
                for rid, out in zip(batch_ids, outputs):
                    self._settle(rid, out)             # 成功 → set_result
            except Exception as e:
                #   ★特殊点3 异常也 set_exception：调用方拿到错误而不是死等，
                #     绝不让异常请求永远留在结果表里（失败也是结果）
                for rid in batch_ids:
                    self._settle(rid, RuntimeError(f"批量推理失败: {e}"))

    def _settle(self, request_id: str, value) -> None:
        ...   # Future 全量回收统一入口：pop 后未完成才写入（结果/异常二选一，从略）

    async def wait_result(self, request_id: str, timeout: float = 30.0):
        fut = self.futures.get(request_id)
        if fut is None:
            raise KeyError(f"未知请求: {request_id}")
        return await asyncio.wait_for(fut, timeout=timeout)   # 显式超时兜底；内部异常原样抛给调用方
```

## 二、动态批量

调度层只做三件事：确保 worker 在跑、入队、`await` 结果——**没有任何忙轮询**。

```python
class DynamicBatching:
    """动态批量调度：await Future，结果/异常/超时三态明确（调度层零忙轮询）"""

    def __init__(self, engine: BatchedInference):
        self.engine = engine

    async def schedule(self, request):
        await self.engine.start()                 # 确保 worker 已启动
        request_id = await self.engine.add_request(request)
        return await self.engine.wait_result(request_id, timeout=30.0)


# 使用（示意；模型批量前向为示意占位，接入真实模型后即可运行）：
# result = await DynamicBatching(BatchedInference(model)).schedule(
#     InferenceRequest(input_ids=[1, 2, 3]))
```

相比「调用方 0.01s 轮询 + `queue.empty()` 判断」的旧方案，这一版修掉了三个隐患：

```text
旧方案问题                              新方案对应设计
─────────────────────────────────      ─────────────────────────────────
empty() 与 get() 竞态，请求可能         worker 阻塞 get() + get_nowait()
永远滞留队列、无人触发                  顺序消费，队列状态只有 worker 改变

批次之外/异常请求永远不在               每个请求登记 Future；成功 set_result、
cache，调用方死等                       失败 set_exception，全量可回收

无背压，请求堆积打爆内存                Queue(maxsize=...) 队列满时入队挂起
```

### 企业级升级要点

- **结果表 + Future 全量回收**：成功与异常都写回 Future，杜绝「调用方死等」——与 `ai-agent-harness/harness/main_loop.py` 的 `_execute_tools_parallel`（gather + return_exceptions）同一哲学：失败也是结果。
- **消费循环替代忙轮询**：阻塞 `get()` 驱动、10ms 攒批窗口控延迟——对应 harness 主循环「事件驱动、有界等待」的调度风格。
- **背压显式化**：`asyncio.Queue(maxsize=...)` 上限 + 显式超时，过载时上游挂起而不是 OOM——参考 `harness/cost_tracker.py` 的预算熔断思想（资源上限前置声明）。
- **超时兜底**：`wait_result` 用 `asyncio.wait_for` 显式超时，避免慢请求拖死上游——同 `main_loop.py` 中工具执行的 wait_for 超时模式。
- **生产实现**：连续批处理（continuous batching）请直接用 vLLM / TGI；本篇是理解其调度模型的最小教学版。
