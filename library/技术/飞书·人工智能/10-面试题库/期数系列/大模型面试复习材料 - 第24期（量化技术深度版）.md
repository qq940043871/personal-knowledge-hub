### 2.1 LLM量化的数学原理——从 FP16 到 INT4 的映射函数

#### 第1层：量化问题的形式化定义

**核心问题**：将连续值的FP16权重/激活映射到离散值的INT8/INT4，同时最小化精度损失

**数学定义**：

```
<code>量化函数：Q(x) = Round( (x - z) / s )  <br/>反量化函数：DQ(y) = y × s + z<br/>其中：<br/>  · s（scale）：缩放因子，控制量化步长<br/>  · z（zero_point）：零点，处理非对称分布</code>
```

**INT8（对称量化）**：

```
<code>s = max(|x|) / 127<br/>z = 0<br/>Q(x) = Round(x / s)</code>
```

**INT4（非对称量化，AWQ采用）**：

```
<code>s = (max(x) - min(x)) / 15<br/>z = Round(-min(x) / s)<br/>Q(x) = Clip(Round((x - z) / s), 0, 15)</code>
```

#### 第2层：为什么INT4比INT8难？——信息论视角

**信息论分析**：

- INT8：256个离散值，信息容量 = log2(256) = 8 bits
- INT4：16个离散值，信息容量 = log2(16) = 4 bits
- **信息损失**：INT4比INT8损失4 bits（50%信息容量）

**关键问题**：LLM权重分布接近拉普拉斯分布（尖峰厚尾），直接量化会导致：

1. 尾部分布被截断（重要权重丢失）
1. 舍入误差累积（深层模型误差传播）

**AWQ的解决方案**：只量化权重，不量化激活；并用激活值的重要性加权

#### 第3层：AWQ（Activation-aware Weight Quantization）算法原理

**核心洞察**：不是所有权重都同等重要，激活值大的通道对应的权重更重要

**算法流程**：

```
<code>1. 收集校准集（100-1000个样本）<br/>2. 前向传播，记录每层激活值的统计信息<br/>3. 计算每个通道的「重要性分数」= mean(|activation|)<br/>4. 对重要性高的通道，保护其对应的权重（不量化或用更细粒度）<br/>5. 搜索最优的缩放因子 s（最小化量化误差）</code>
```

**数学形式化**：

```
<code>AWQ损失函数：<br/>  L(s) = || W - s · Q(W/s) ||_F^2 · diag(importance)<br/>其中：<br/>  · W：原始权重矩阵<br/>  · Q：量化函数<br/>  · importance：激活值的重要性向量<br/>  · diag(importance)：对角矩阵，对高重要性通道赋予更高权重</code>
```

#### 第4层：GPTQ（后训练量化算法）原理

**核心思想**：逐层量化，并用二阶优化（Hessian矩阵）最小化量化误差

**算法流程**：

```
<code>1. 对每一层：<br/>   a. 计算该层的Hessian矩阵近似 H = 2·X·X^T / n<br/>      （X是该层输入激活，n是校准集大小）<br/>   b. 贪心量化每个权重 w_ij：<br/>      - 量化：w_ij_quant = Q(w_ij)<br/>      - 计算量化误差：error = (w_ij_quant - w_ij) / H_jj<br/>      - 补偿误差：将error按Hessian比例分摊到其他未量化权重<br/>   c. 完成该层后，用量化后的权重继续下一层</code>
```

**为什么用Hessian？**

- 一阶优化（只最小化 ||W - W_quant||）忽略了对输出的影响
- 二阶优化（考虑Hessian）直接最小化输出误差 ||Y - Y_quant||
- 实验：GPTQ比简单舍入量化精度高3-5个百分点

#### 第5层：FP8量化——新一代标准

**为什么需要FP8？**

- INT8/INT4：动态范围固定（INT8: [-128, 127]）
- FP8：动态范围灵活（指数位 + 尾数位），更适合LLM的拉普拉斯分布权重

**FP8的两种格式**：

| th | th | th | th | th | th |
| --- | --- | --- | --- | --- | --- |
| td | td | td | td | td | td |
| td | td | td | td | td | td |

**Transformer-Engine（NVIDIA）**：

- 前向传播：FP8计算
- 反向传播：FP16存储梯度（避免梯度下溢）
- 实测：训练速度 +30%，显存占用 -40%

#### 第3层：异常值（Outlier）处理

**问题**：LLM激活值中存在少量极大值（Outlier），直接量化会导致大量信息损失

**Outlier检测方法**：

```
<code>def detect_outliers(activations, threshold=5.0):<br/>    """<br/>    检测激活值中的异常值<br/>    threshold: 标准差的倍数（默认5倍标准差以上视为异常）<br/>    """<br/>    mean = activations.mean()<br/>    std = activations.std()<br/>    outliers = torch.abs(activations - mean) &gt; threshold * std<br/>    return outliers</code>
```

**处理方案**：

1. **单独存储**：Outlier用FP16存储，其余用INT4
1. **平滑处理**：对激活值做平滑（如Softmax温度缩放），减少Outlier
1. **逐通道量化**：对每个输出通道单独计算scale，适应不同分布的激活值

#### 第2层：QAT的数学原理

**核心思想**：在前向传播中插入「伪量化」操作，让模型在训练时就适应量化误差

**训练时前向传播**：

```
<code>y = W_quant · x_quant<br/>其中：<br/>  W_quant = Q(W) = Round(W / s) × s  （STE近似梯度）<br/>  x_quant = Q(x) = Round(x / s_x) × s_x</code>
```

**反向传播**：用STE（Straight-Through Estimator）近似梯度

```
<code>∂L/∂W ≈ ∂L/∂W_quant  （跳过量化操作的梯度截断）</code>
```

#### 第3层：代码实现（QAT训练循环）

```
<code>class QATLinear(nn.Module):<br/>    """量化感知训练的Linear层"""<br/>    def __init__(self, in_features, out_features, num_bits=8):<br/>        super().__init__()<br/>        self.weight = nn.Parameter(torch.Tensor(out_features, in_features))<br/>        self.num_bits = num_bits<br/>        self.scale = nn.Parameter(torch.ones(1), requires_grad=True)  # 可学习的scale<br/><br/>    def forward(self, x):<br/>        # 伪量化：训练时模拟量化，但用STE近似梯度<br/>        if self.training:<br/>            weight_quant = self.quantize(self.weight)<br/>            x_quant = self.quantize(x)<br/>            return F.linear(x_quant, weight_quant)<br/>        else:<br/>            # 推理时：用真实的INT8/INT4计算<br/>            return F.linear(x, self.weight_quant)<br/><br/>    def quantize(self, x):<br/>        """伪量化函数（STE近似）"""<br/>        scale = self.scale<br/>        x_quant = torch.round(x / scale) * scale<br/>        return x_quant<br/><br/># 训练循环<br/>model = LLaMA_13B()<br/>model = replace_linear_with_qat(model)  # 替换所有Linear层为QATLinear<br/><br/>optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)<br/>for epoch in range(3):  # QAT通常只需要3-5个epoch<br/>    for batch in train_data:<br/>        loss = model(batch)<br/>        loss.backward()<br/>        optimizer.step()</code>
```

#### 第4层：工业实践建议

**何时用PTQ？**

#### 第3层：显存管理策略（20分钟）

**核心矛盾**：

- INT4量化后，模型权重只占7.8 GB
- 但KV Cache仍需要大量显存（尤其长上下文）
- 目标：在80GB显存中，最大化并发请求数

**策略1：PagedAttention + INT4 KV Cache**

```
<code>· KV Cache也量化到INT8（激进方案可以到INT4）<br/>· 用PagedAttention管理：显存利用率 60% → 92%<br/>· 7.8GB（模型权重）+ 52GB（KV Cache，INT8）=<br/>  总显存 59.8GB &lt; 80GB ✅<br/>· 可支持并发：~180个请求（每个请求KV Cache ~290MB）</code>
```

**策略2：KV Cache Offloading**

```
<code>· 冷数据（早期层、早期token）放到CPU内存<br/>· 热数据（高层、最近token）留在GPU<br/>· 用预测模型预判哪些KV会被访问（类似CPU Cache预取）<br/>· 效果：显存占用 -40%，延迟增加 +15ms（可接受）</code>
```

**策略3：动态批处理（Continuous Batching）**

```
<code>· 不等一个batch填满，有请求完成就立即填入新请求<br/>· 配合PagedAttention，GPU利用率 45% → 90%<br/>· 实现：用vLLM框架（已内置Continuous Batching）</code>
```
