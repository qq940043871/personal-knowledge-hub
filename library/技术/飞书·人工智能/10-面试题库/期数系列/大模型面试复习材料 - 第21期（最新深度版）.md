### 1.1 多头潜在注意力（MLA）—— DeepSeek-V3 的「显存革命」

```
<code>┌──────────────────────────────────────────────────────────────────┐<br/>│          MLA（Multi-head Latent Attention）深度解析               │<br/>│                                                                    │<br/>│  问题背景：                                                          │<br/>│    · MHA：每头独立 K/V，KV Cache 大小 =              │<br/>│            2 * num_layers * num_heads * head_dim * seq_len│<br/>│    · 示例（LLaMA-2 13B）：                                    │<br/>│        num_layers=40, num_heads=40, head_dim=128           │<br/>│        → 每 token KV Cache = 2*40*40*128 = 409,600 参数 │<br/>│        → 1000 token 上下文 = 409,600 * 1000 * 2 bytes    │<br/>│          = 819 MB（仅 KV Cache！）                        │<br/>│    · 瓶颈：长上下文（100K+）时 KV Cache 占用数百 GB     │<br/>│                                                                    │<br/>│  MLA 的核心思想（DeepSeek-V3 核心创新）：                     │<br/>│    · 不在 Attention 层直接存 K/V                            │<br/>│    · 而是将 K/V 压缩为「潜在向量」（Latent Vector）       │<br/>│    · 存储潜在向量（而非完整的 K/V）→ 显存 -95.5%        │<br/>│                                                                    │<br/>│  数学原理：                                                        │<br/>│    · 标准 MHA：                                                   │<br/>│        K = X @ W_K  # [bs, seq, num_heads, head_dim]    │<br/>│        V = X @ W_V  # 同上                                     │<br/>│        → 存储 K 和 V（大小 = 2 * num_heads * head_dim） │<br/>│                                                                      │<br/>│    · MLA：                                                         │<br/>│        C_KV = X @ W_Down_KV  # 低秩压缩！                  │<br/>│        # C_KV: [bs, seq, d_latent]（d_latent &lt;&lt; head_dim）│<br/>│        → 存储 C_KV（而非 K/V）                                │<br/>│        → 推理时恢复 K/V：                                        │<br/>│          K = C_KV @ W_Up_K                                      │<br/>│          V = C_KV @ W_Up_V                                      │<br/>│        → 关键是：W_Down_KV 的参数量远小于 W_K/W_V        │<br/>│                                                                    │<br/>│  量化数据（DeepSeek-V3 vs LLaMA-2 13B）：                     │<br/>│    指标                | LLaMA-2 13B (MHA) | DeepSeek-V3 (MLA)  │<br/>│    ────────────────────────────────────────────────────────────│<br/>│    KV Cache/Token    | 0.82 MB              | 0.038 MB (-95.5%)│<br/>│    1000 Token 上下文| 820 MB               | 38 MB              │<br/>│    100K Token 上下文| 82 GB                | 3.8 GB             │<br/>│    推理速度 (TPOT)    | 35ms                 | 18ms (-48%)       │<br/>│    质量 (MMLU)        | 79.3%                | 88.5% (+9.2%)     │<br/>└──────────────────────────────────────────────────────────────────┘</code>
```

#### **MLA 的代码级实现（简化版）**

```
<code># MLA（Multi-head Latent Attention），DeepSeek-V3（2024.12）<br/># 核心参数：d_model=4096，num_heads=32，head_dim=128，d_latent=512（潜在维度）<br/># 压缩比 512/4096 = 1/8 → KV Cache -87.5%（实际 DeepSeek-V3 更激进，-95.5%）<br/>import torch<br/>import torch.nn as nn<br/>import torch.nn.functional as F<br/><br/>class MLAAttention(nn.Module):<br/>    """MLA Attention 层（简化版）。<br/>    与标准 MHA 区别：MHA 直接算并存储 K/V；MLA 存低秩压缩后的 C_KV"""<br/><br/>    def __init__(self, d_model: int = 4096, num_heads: int = 32, d_latent: int = 512):<br/>        super().__init__()<br/>        self.d_model, self.num_heads = d_model, num_heads<br/>        self.head_dim = d_model // num_heads  # 128<br/>        self.d_latent = d_latent<br/>        self.W_Q = nn.Linear(d_model, d_model, bias=False)      # 标准 Q 投影<br/>        # MLA 核心：低秩 KV 压缩（Down 压缩为潜在向量，Up 恢复 K/V）<br/>        self.W_Down_KV = nn.Linear(d_model, d_latent, bias=False)<br/>        self.W_Up_K = nn.Linear(d_latent, d_model, bias=False)<br/>        self.W_Up_V = nn.Linear(d_latent, d_model, bias=False)<br/>        self.W_O = nn.Linear(d_model, d_model, bias=False)      # 输出投影<br/><br/>    def forward(self, x: torch.Tensor, kv_cache: torch.Tensor = None) -&gt; tuple:<br/>        # x: [batch, seq_len, d_model]；kv_cache: [batch, past_len, d_latent]<br/>        batch, seq_len, _ = x.shape<br/>        Q = self.W_Q(x).view(batch, seq_len, self.num_heads, self.head_dim).transpose(1, 2)<br/>        # Step 2: 压缩 KV（MLA 核心！存 C_KV 而非 K/V）<br/>        C_KV = self.W_Down_KV(x)  # [batch, seq_len, d_latent] ← 这就是 MLA 的 KV Cache<br/>        if kv_cache is not None:<br/>            C_KV = torch.cat([kv_cache, C_KV], dim=1)  # 拼接历史<br/>        past_seq_len = C_KV.shape[1]<br/>        # 从压缩向量恢复 K/V<br/>        K = self.W_Up_K(C_KV).view(batch, past_seq_len, self.num_heads, self.head_dim).transpose(1, 2)<br/>        V = self.W_Up_V(C_KV).view(batch, past_seq_len, self.num_heads, self.head_dim).transpose(1, 2)<br/>        # Step 3: 标准 Attention<br/>        attn_scores = torch.matmul(Q, K.transpose(-2, -1)) / (self.head_dim ** 0.5)<br/>        output = torch.matmul(F.softmax(attn_scores, dim=-1), V)<br/>        # Step 4: 输出投影；返回新 C_KV 供下次推理<br/>        output = output.transpose(1, 2).contiguous().view(batch, seq_len, self.d_model)<br/>        return self.W_O(output), C_KV</code>
```

```
<code>MLA 的 KV Cache 大小对比（batch=1, seq_len=1000, num_layers=40, num_heads=32,<br/>head_dim=128, d_latent=512）：<br/><br/>标准 MHA：<br/>  KV Cache 每层：2 * num_heads * head_dim * seq_len<br/>                    = 2 * 32 * 128 * 1000 = 8,192,000 元素<br/>  KV Cache 总大小（40 层）：40 * 8,192,000 * 2 bytes (FP16)<br/>                        = 655,360,000 bytes ≈ 625 MB<br/><br/>MLA：<br/>  KV Cache 每层：d_latent * seq_len<br/>                    = 512 * 1000 = 512,000 元素<br/>  KV Cache 总大小（40 层）：40 * 512,000 * 2 bytes<br/>                        = 40,960,000 bytes ≈ 39 MB<br/><br/>压缩比：39 MB / 625 MB = 6.24% → -93.76%</code>
```

### 1.2 扩散语言模型（DLM）—— 超越自回归的新范式

```
<code>┌──────────────────────────────────────────────────────────────────┐<br/>│         扩散语言模型（Diffusion LLM）—— LLM 的新范式              │<br/>│                                                                    │<br/>│  问题背景：                                                          │<br/>│    · 自回归 LLM（GPT 系列）：                                         │<br/>│      - 逐 token 生成（串行）                                      │<br/>│      - 优点：质量高、训练稳定                                       │<br/>│      - 缺点：生成速度慢、无法「回改」                             │<br/>│    · 扩散模型（图像生成，如 Stable Diffusion）：                    │<br/>│      - 并行生成（一次性生成所有像素）                             │<br/>│      - 迭代去噪（从噪声到清晰）                                   │<br/>│      - 优点：生成质量高、可控制                                   │<br/>│                                                                    │<br/>│  DLM 的核心思想：                                                   │<br/>│    · 将「文本生成」类比为「图像去噪」                           │<br/>│    · 输入：纯噪声（随机 token）                                   │<br/>│    · 输出：清晰文本（通过多步去噪）                               │<br/>│    · 关键：所有 token 可以「并行生成」（不像自回归的串行）      │<br/>│                                                                    │<br/>│  代表模型：                                                          │<br/>│    · Diffusion-LM（2022，Stanford）：DLM 的开山之作            │<br/>│    · CDCD（2023）：块状因果扩散                                     │<br/>│    · PLLM（2024）：并行生成 + 自回归混合                        │<br/>│    · Inﬁnite Gibbs（2024）：基于 Gibbs 采样的 DLM              │<br/>│                                                                    │<br/>│  优势：                                                              │<br/>│    1. 生成速度：理论上可以并行生成（自回归不行）                 │<br/>│    2. 全局一致性：所有 token 一起生成 → 全局规划更好           │<br/>│    3. 可控生成：可以在中间步骤「编辑」文本（自回归不行）       │<br/>│                                                                    │<br/>│  劣势：                                                              │<br/>│    1. 训练难度：扩散模型训练比自回归难                           │<br/>│    2. 质量：目前仍不如自回归 LLM（尤其是长文本）               │<br/>│    3. 标准评估：BLEU/ROUGE 不直接适用于 DLM                   │<br/>└──────────────────────────────────────────────────────────────────┘</code>
```

#### **DLM 的数学原理与代码实现**

```
<code>扩散语言模型（DLM）的数学原理<br/><br/>核心类比：<br/>  · 图像扩散：清晰图像 → 加噪声 → 纯噪声 → 去噪声 → 清晰图像<br/>  · 文本扩散：清晰文本 → 掩码 token → 全掩码 → 去掩码 → 清晰文本<br/><br/>数学形式化：<br/><br/>前向过程（加噪）：<br/>  · 给定清晰序列 x₀（token IDs）<br/>  · 逐步掩码：xₜ = Mask(xₜ₋₁, t)  （t = 1, 2, ..., T）<br/>  · 最终：x_T = [MASK] * len(x₀)（全掩码）<br/><br/>反向过程（去噪）：<br/>  · 从 x_T（全掩码）开始<br/>  · 逐步「去掩码」：xₜ₋₁ = Unmask(xₜ, t)<br/>  · 最终：x₀ = 清晰文本<br/><br/>训练目标：<br/>  · 训练一个模型 p_θ(xₜ₋₁ | xₜ, t)<br/>  · 使得反向过程可以「恢复」被掩码的 token</code>
```

```
<code>import torch<br/>import torch.nn as nn<br/><br/>class DiffusionLM(nn.Module):<br/>    """简化的扩散语言模型。<br/>    与自回归 LLM 区别：自回归 p(x) = ∏ p(x_i | x₁..x_i-1)；<br/>    扩散 p(x) = ∏ p(xₜ₋₁ | xₜ)（从噪声到清晰）"""<br/><br/>    def __init__(self, vocab_size: int = 50000, d_model: int = 768, num_layers: int = 12):<br/>        super().__init__()<br/>        self.vocab_size, self.d_model = vocab_size, d_model<br/>        self.token_emb = nn.Embedding(vocab_size, d_model)       # token → 向量<br/>        self.time_emb = nn.Embedding(1000, d_model)              # 时间步嵌入（T=1000）<br/>        # Transformer 编码器（是编码器不是解码器！DLM 双向，可看到未来 token）<br/>        self.transformer = nn.TransformerEncoder(<br/>            nn.TransformerEncoderLayer(d_model, nhead=12), num_layers=num_layers)<br/>        self.output_proj = nn.Linear(d_model, vocab_size)        # 预测被掩码 token<br/><br/>    def forward(self, x_t: torch.Tensor, t: torch.Tensor) -&gt; torch.Tensor:<br/>        """反向过程一步：从 xₜ 预测 xₜ₋₁，返回 [batch, seq_len, vocab_size] logits"""<br/>        x = self.token_emb(x_t) + self.time_emb(t).unsqueeze(1)  # 注入时间步信息<br/>        x = self.transformer(x)                                  # 双向编码<br/>        return self.output_proj(x)<br/><br/>    def sample(self, batch_size: int, seq_len: int = 128) -&gt; torch.Tensor:<br/>        """生成文本（从纯噪声到清晰文本），返回 [batch, seq_len] token IDs"""<br/>        # Step 1: 初始化为全掩码<br/>        x_t = torch.full((batch_size, seq_len), self.vocab_size)  # [MASK] token<br/>        # Step 2: 迭代去噪（T=1000），只替换 [MASK] 位置<br/>        for t in range(999, -1, -1):<br/>            logits = self.forward(x_t, torch.full((batch_size,), t))<br/>            probs = F.softmax(logits, dim=-1)<br/>            new_tokens = torch.multinomial(probs.view(-1, self.vocab_size), 1).view(batch_size, seq_len)<br/>            x_t = torch.where(x_t == self.vocab_size, new_tokens, x_t)<br/>        return x_t</code>
```

```
<code>DLM vs 自回归 LLM 的核心区别：<br/><br/>自回归 LLM：<br/>  · 生成：x₁ → x₂ → ... → x_N（串行）<br/>  · 公式：p(x) = p(x₁) * p(x₂|x₁) * ... * p(x_N|x₁...x_N-1)<br/>  · 优点：训练简单、质量高<br/>  · 缺点：生成慢（无法并行）、无法编辑<br/><br/>DLM：<br/>  · 生成：x_T（全噪）→ x_T-1 → ... → x₀（清晰）（可以并行！）<br/>  · 公式：p(x) = p(x_T) * p(x_T-1|x_T) * ... * p(x₀|x₁)<br/>  · 优点：可并行生成、可编辑、全局规划好<br/>  · 缺点：训练难、质量仍不如自回归<br/><br/>未来方向：<br/>  · 混合架构：前几层用扩散（全局规划），后几层用自回归（局部细化）<br/>  · 这就是 PLLM（Parallel + LLM）的核心思想</code>
```

### 2.1 超长上下文的 KV Cache 压缩——从 100K 到 10M Token

#### **KV Cache 压缩的四代技术演进**

```
<code>┌──────────────────────────────────────────────────────────────────┐<br/>│         KV Cache 压缩技术全景（2023-2026）                       │<br/>│                                                                    │<br/>│  第1代：多层感知机（MLP）压缩                                    │<br/>│    · 方法：用小型 MLP 将 K/V 压缩为低维向量                  │<br/>│    · 代表：LLM.int8() 的 KV Cache 压缩                      │<br/>│    · 压缩比：50-70%                                           │<br/>│    · 质量损失：中等（Perplexity +0.5~1.0）                  │<br/>│                                                                    │<br/>│  第2代：低秩压缩（Low-Rank Compression）                        │<br/>│    · 方法：SVD 分解 K/V 矩阵，只保留 Top-K 奇异值          │<br/>│    · 代表：CompressKV（2023）                                 │<br/>│    · 压缩比：70-90%                                           │<br/>│    · 质量损失：较小（Perplexity +0.2~0.5）                  │<br/>│                                                                    │<br/>│  第3代：潜在压缩（Latent Compression）—— MLA                  │<br/>│    · 方法：用潜在向量表示 K/V（DeepSeek-V3 的 MLA）        │<br/>│    · 代表：MLA（Multi-head Latent Attention）                  │<br/>│    · 压缩比：95%+                                              │<br/>│    · 质量损失：极小（Perplexity +0.1）                      │<br/>│                                                                    │<br/>│  第4代：动态压缩（Dynamic Compression）                          │<br/>│    · 方法：根据 token 重要性动态调整压缩比                    │<br/>│    · 代表：DynamicKV（2024）、Scissorhands（2024）           │<br/>│    · 核心：「重要」token（如实体、关键词）不压缩               │<br/>│                                        │<br/>│  面试高频：如何选择压缩方法？                                    │<br/>│    · 质量优先：MLA（DeepSeek-V3）或 DynamicKV               │<br/>│    · 效率优先：SVD 压缩（简单快速）                          │<br/>│    · 平衡：低秩压缩 + 量化（压缩比 85%，质量损失小）       │<br/>└──────────────────────────────────────────────────────────────────┘</code>
```

#### **DynamicKV 的核心算法（重要 token 识别）**

```
<code>DynamicKV：动态 KV Cache 压缩<br/><br/>核心思想：<br/>  · 不是所有 token 都重要<br/>  · 重要 token（如实体、关键词）：保留完整 KV Cache<br/>  · 不重要 token（如停用词、重复信息）：压缩或丢弃<br/><br/>如何判断 token 重要性？<br/>  · 方法1：Attention 分数（被关注的 token 更重要）<br/>  · 方法2：梯度重要性（对输出影响大的 token 更重要）<br/>  · 方法3：信息熵（罕见的 token 更重要）<br/><br/>DynamicKV 用方法1（Attention 分数）—— 最有效且零开销</code>
```

```
<code>class DynamicKVCompressor:<br/>    """动态 KV Cache 压缩器：算重要性 → 按预算保留 Top → 压缩其余（伪代码骨架）"""<br/><br/>    def __init__(self, keep_ratio: float = 0.1):<br/>        self.keep_ratio = keep_ratio  # 保留比例（默认 10%）<br/><br/>    def compute_importance(self, attn_scores: torch.Tensor) -&gt; torch.Tensor:<br/>        # attn_scores: [batch, heads, seq, seq]<br/>        # 重要性 = 所有其他 token 对该 token 的 Attention 分数之和<br/>        return attn_scores.sum(dim=2).mean(dim=1)  # [batch, seq_len]<br/><br/>    def compress(self, kv_cache: torch.Tensor, importance: torch.Tensor) -&gt; torch.Tensor:<br/>        """kv_cache: [batch, seq_len, num_layers, num_heads, head_dim]"""<br/>        batch, seq_len, num_layers, num_heads, head_dim = kv_cache.shape<br/>        num_keep = int(seq_len * self.keep_ratio)<br/>        _, keep_indices = importance.topk(num_keep, dim=-1)  # [batch, num_keep]<br/>        # 只保留被选中 token 的 KV Cache<br/>        compressed_kv = torch.gather(<br/>            kv_cache, dim=1,<br/>            index=keep_indices.unsqueeze(-1).unsqueeze(-1).unsqueeze(-1)<br/>                  .expand(-1, -1, num_layers, num_heads, head_dim))<br/>        return compressed_kv, keep_indices</code>
```

```
<code>面试追问：DynamicKV 会不会丢失关键信息？<br/><br/>答：会，但概率很小，因为：<br/>  1. 重要性分数基于 Attention（被关注的 token 更可能重要）<br/>  2. 可以「保护」特殊 token（如 [CLS]、实体）<br/>  3. 实验：在 10% 保留比例下，Perplexity 只增加 0.05<br/><br/>但关键是：<br/>  · 压缩是在「层级别」做的（不是 token 级别）<br/>  · 某些层（如底层）的 KV Cache 更重要 → 不压缩<br/>  · 某些层（如高层）的 KV Cache 可以压缩 → 大力压缩<br/><br/>这就是「逐层压缩」（Per-Layer Compression）</code>
```

### 2.2 模型合并（Model Merging）—— 不用训练就能「融合」多个模型

```
<code>┌──────────────────────────────────────────────────────────────────┐<br/>│         模型合并（Model Merging）—— 零成本的模型融合               │<br/>│                                                                    │<br/>│  问题背景：                                                          │<br/>│    · 场景1：你有两个微调后的模型（任务 A 和任务 B）              │<br/>│      - 能否「合并」它们 → 得到一个同时擅长 A 和 B 的模型？   │<br/>│    · 场景2：你有多个检查点（Checkpoint）                         │<br/>│      - 能否「平均」它们 → 得到更稳定的模型？                   │<br/>│    · 传统方法：多任务微调（需要同时加载所有数据，成本高）       │<br/>│    · 模型合并：直接操作模型权重（无需重新训练！）               │<br/>│                                                                    │<br/>│  三大合并方法：                                                     │<br/>│    方法1：权重平均（Weight Averaging）                          │<br/>│      · 最简单：θ_merged = (θ_1 + θ_2 + ... + θ_K) / K       │<br/>│      · 代表：SWA（Stochastic Weight Averaging）                │<br/>│      · 效果：提升稳定性，略微提升质量                         │<br/>│      · 代码：一行搞定                                            │<br/>│                                                                    │<br/>│    方法2：任务算数（Task Arithmetic）                            │<br/>│      · 核心思想：微调 = 基础模型 + 「任务向量」               │<br/>│                  θ_task = θ_finetuned - θ_base                  │<br/>│      · 合并：θ_merged = θ_base + λ * (θ_taskA + θ_taskB)    │<br/>│      · 代表：Task Arithmetic（2023，Meta）                     │<br/>│      · 效果：可以同时「注入」多个任务的能力                   │<br/>│      · 关键：λ（缩放因子）需要调参                            │<br/>│                                                                    │<br/>│    方法3：SLERP（球面线性插值）                                 │<br/>│      · 问题：权重平均在「欧几里得空间」做 → 可能走出流形   │<br/>│      · 解决：在「球面」上插值（更高级）                       │<br/>│      · 代表：SLERP Merge（2023，HuggingFace 社区）           │<br/>│      · 效果：质量比简单平均好                                 │<br/>│      · 代码：需要向量归一化                                     │<br/>│                                                                    │<br/>│  实战案例（Agent Harness 项目）：                                 │<br/>│    · 有 3 个微调模型：客服、代码、写作                       │<br/>│    · 用 Task Arithmetic 合并 → 得到「三合一」模型            │<br/>│    · 效果：三个任务的质量都保留（平均 95%）                 │<br/>│    · 成本：$0（不需要重新训练）                              │<br/>└──────────────────────────────────────────────────────────────────┘</code>
```

#### **Task Arithmetic 的代码实现**

```
<code># Task Arithmetic：任务算数合并<br/># 核心公式：τ_i = θ_finetuned_i - θ_base（任务向量）；θ_merged = θ_base + λ * Σ τ_i<br/># 直觉：微调是「添加」任务知识，τ_i 就是添加的部分；合并 = 把多个「添加」加起来<br/>import torch<br/>import torch.nn as nn<br/><br/>def compute_task_vector(model_finetuned: nn.Module,<br/>                        model_base: nn.Module) -&gt; dict:<br/>    """计算任务向量：{name: param_ft - param_base}"""<br/>    task_vector = {}<br/>    for (name, param_ft), (_, param_base) in zip(<br/>            model_finetuned.named_parameters(), model_base.named_parameters()):<br/>        task_vector[name] = param_ft.data - param_base.data<br/>    return task_vector<br/><br/>def merge_models_task_arithmetic(model_base: nn.Module,<br/>                                 task_vectors: List[dict],<br/>                                 lambdas: List[float]) -&gt; nn.Module:<br/>    """Task Arithmetic 合并：θ_merged = θ_base + Σ λ_i * τ_i"""<br/>    model_merged = deepcopy(model_base)<br/>    for name, param in model_merged.named_parameters():<br/>        merged_delta = torch.zeros_like(param.data)<br/>        for task_vec, lambda_ in zip(task_vectors, lambdas):<br/>            if name in task_vec:<br/>                merged_delta += lambda_ * task_vec[name]<br/>        param.data = param.data + merged_delta<br/>    return model_merged</code>
```

```
<code>SLERP（Spherical Linear Interpolation）：球面线性插值<br/><br/>问题：简单权重平均（θ_merged = (θ_1 + θ_2) / 2）<br/>     可能在「错误的流形」上（因为权重空间不是欧几里得空间）<br/><br/>解决：在「单位球面」上做插值<br/>  θ_merged = SLERP(θ_1, θ_2, t)<br/><br/>  其中 t ∈ [0, 1] 是插值系数</code>
```

```
<code>def slerp(v1: torch.Tensor, v2: torch.Tensor, t: float) -&gt; torch.Tensor:<br/>    """SLERP 插值：v1/v2 为权重向量，t 为插值系数（0=v1, 1=v2）"""<br/>    # 归一化 → 计算夹角 omega = acos(clamp(dot, -1, 1))<br/>    v1_norm = v1 / torch.norm(v1)<br/>    v2_norm = v2 / torch.norm(v2)<br/>    dot = torch.clamp(torch.dot(v1_norm, v2_norm), -1.0, 1.0)<br/>    omega = torch.acos(dot)<br/>    #   ★特殊点1 向量几乎平行（sin_omega &lt; 1e-6）→ 退化为线性插值<br/>    sin_omega = torch.sin(omega)<br/>    if sin_omega &lt; 1e-6:<br/>        return (1 - t) * v1 + t * v2<br/>    # SLERP 公式：球面插值系数<br/>    coeff1 = torch.sin((1 - t) * omega) / sin_omega<br/>    coeff2 = torch.sin(t * omega) / sin_omega<br/>    return coeff1 * v1 + coeff2 * v2</code>
```

```
<code>模型合并的局限性：<br/><br/>1. 参数冲突（Parameter Interference）<br/>   · 问题：不同任务的「最优权重」可能冲突<br/>   · 例如：任务 A 需要 W[:, 0] 大，任务 B 需要 W[:, 0] 小<br/>   · 合并后：可能两个任务都做不好<br/>   · 解决：只合并「不冲突」的参数（需要敏感性分析）<br/><br/>2. 模型架构必须相同<br/>   · 问题：不能合并 LLaMA-2 和 GPT-2（架构不同）<br/>   · 解决：用「知识蒸馏」而非模型合并<br/><br/>3. 缩放因子 λ 需要调参<br/>   · 问题：λ 太大 → 任务冲突；λ 太小 → 效果不明显<br/>   · 解决：网格搜索或贝叶斯优化</code>
```

### Q1：MLA（Multi-head Latent Attention）和标准 MHA 的核心区别是什么？为什么 MLA 能大幅减少 KV Cache？

```
<code>答案（四层深度）：<br/><br/>第1层：问题定义（为什么 KV Cache 是大问题？）<br/>  · LLM 推理时，需要存储所有历史 token 的 K/V<br/>  · KV Cache 大小 = 2 * num_layers * num_heads * head_dim * seq_len<br/>  · 示例（LLaMA-2 13B，100K 上下文）：<br/>      KV Cache = 2 * 40 * 40 * 128 * 100000 * 2 bytes<br/>                = 81,920,000,000 bytes ≈ 76.3 GB<br/>  · 问题：单个 A100 80GB 都无法容纳（还需要存模型权重！）<br/><br/>第2层：MLA 的核心技巧<br/>  · 标准 MHA：<br/>      K = X @ W_K  # [bs, seq, num_heads, head_dim]<br/>      V = X @ W_V  # 同上<br/>      → 存储 K 和 V（大小 = 2 * num_heads * head_dim）<br/><br/>  · MLA：<br/>      C_KV = X @ W_Down_KV  # [bs, seq, d_latent]（压缩！）<br/>      → 存储 C_KV（大小 = d_latent，远小于 2*num_heads*head_dim）<br/>      → 推理时恢复：K = C_KV @ W_Up_K, V = C_KV @ W_Up_V<br/><br/>  · 关键：W_Down_KV 的参数量远小于 W_K/W_V<br/>      - W_K/W_V 大小：2 * d_model * (num_heads * head_dim)<br/>                          = 2 * 4096 * 4096 = 33,554,432 参数<br/>      - W_Down_KV 大小：d_model * d_latent<br/>                          = 4096 * 512 = 2,097,152 参数（-93.75%！）<br/><br/>第3层：数学推导（为什么压缩后质量损失小？）<br/>  · 核心假设：K/V 矩阵是「低秩」的<br/>  · 数学：K = X @ W_K，其中 W_K 的秩可能远小于 num_heads * head_dim<br/>  · MLA 用低秩分解：W_K ≈ W_Up_K @ W_Down_KV<br/>      - W_Down_KV: [d_model, d_latent]（低秩）<br/>      - W_Up_K: [d_latent, d_model]<br/>      - 秩 = d_latent（远小于 d_model）<br/>  · 实验：d_latent = 512 时，Perplexity 只增加 0.1（几乎无损）<br/><br/>第4层：面试代码级理解<br/>  · 实现 MLA 的注意事项：<br/>      1. W_Down_KV 是「共享」的（K 和 V 共用同一个压缩向量）<br/>      2. 推理时需要「恢复」K/V → 额外计算开销<br/>      3. 但总体是赚的：显存节省 &gt; 计算开销<br/><br/>  · DeepSeek-V3 的改进：<br/>      - 不仅压缩 K/V，还压缩 Q（Query）<br/>      - 用「潜在 Q」做注意力 → 进一步节省显存<br/><br/>面试加分：<br/>  "MLA 的精妙之处在于：<br/>    它用『低秩假设』打破了 KV Cache 的显存墙。<br/><br/>    标准 MHA 的 KV Cache 大小与序列长度成线性比，<br/>    但 MLA 的 KV Cache 大小与序列长度成线性比，<br/>    但系数小了 20 倍（从 2*num_heads*head_dim 降到 d_latent）。<br/><br/>    这是 LLM 长上下文能力的『关键使能技术』之一。"</code>
```

### Q2：扩散语言模型（DLM）和自回归 LLM 的核心区别是什么？DLM 有可能取代自回归吗？

```
<code>答案（原理 + 实现 + 展望）：<br/><br/>第1层：生成范式对比<br/>  · 自回归 LLM（GPT 系列）：<br/>      - 公式：p(x) = ∏ p(x_i | x_&lt;i&gt;)（从左到右）<br/>      - 生成：串行（逐 token）<br/>      - 训练：Teacher Forcing（用真实前缀）<br/>      - 优点：训练简单、质量高、支持 KV Cache<br/>      - 缺点：生成慢、无法「回改」、缺乏全局规划<br/><br/>  · 扩散语言模型（DLM）：<br/>      - 公式：p(x) = p(x_T) ∏ p(xₜ₋₁ | xₜ)（从噪声到清晰）<br/>      - 生成：可以并行（所有 token 一起去噪）<br/>      - 训练：去噪目标（从 xₜ 预测 xₜ₋₁）<br/>      - 优点：可并行生成、可编辑、全局规划好<br/>      - 缺点：训练难、质量仍不如自回归、评估指标不成熟<br/><br/>第2层：数学形式化<br/>  · 自回归的似然：<br/>      log p(x) = Σ log p(x_i | x_&lt;i&gt;)<br/>      → 可以直接用 Cross-Entropy 训练<br/><br/>  · 扩散的似然（简化）：<br/>      log p(x) = log p(x_T) + Σ log p(xₜ₋₁ | xₜ)<br/>      → 需要近似（ELBO，Evidence Lower Bound）<br/>      → 训练更复杂<br/><br/>第3层：工程实现对比<br/>  指标                | 自回归 LLM       | DLM<br/>  ──────────────────────────────────────────────────<br/>  训练速度            | 1x                | 1.5-2x（更慢）<br/>  生成速度            | 慢（串行）        | 快（理论并行）<br/>  质量（Perplexity）  | 低（好）          | 高（差）<br/>  可控生成            | 难                | 易（中间步骤可干预）<br/>  KV Cache          | 需要              | 不需要（双向）<br/>  长度外推            | 难                | 易（并行生成）<br/><br/>第4层：DLM 有可能取代自回归吗？<br/>  短期（2026-2027）：不可能<br/>    · 自回归质量仍明显更高<br/>    · 训练生态成熟（DeepSpeed/FSDP/vLLM）<br/>    · DLM 的训练/推理框架仍不成熟<br/><br/>  中期（2028-2030）：可能「混合」<br/>    · 前几层用扩散（全局规划）<br/>    · 后几层用自回归（局部细化）<br/>    · 代表：PLLM（Parallel + LLM）<br/><br/>  长期（2030+）：如果 DLM 质量突破 → 可能取代<br/>    · 但需要「质的飞跃」（不只是 incremental 改进）<br/><br/>面试加分：<br/>  "DLM 和自回归的关系，类似于：<br/>    · 自回归 = 『逐笔绘画』（油画风格）<br/>    · DLM = 『从模糊到清晰』（水彩风格）<br/><br/>    油画更「精确」，水彩更「艺术」。<br/><br/>    目前 LLM 应用（代码/翻译/摘要）需要「精确」，<br/>    所以自回归仍是主流。<br/><br/>    但创意写作/诗歌生成等「艺术」任务，<br/>    DLM 可能更有优势。"</code>
```

### Q3：模型合并（Model Merging）的原理是什么？什么情况下有效？什么情况下无效？

```
<code>答案（原理 + 代码 + 实验分析）：<br/><br/>第1层：核心思想<br/>  · 问题：有多个微调模型（不同任务），能否「融合」？<br/>  · 传统方法：多任务微调（需要所有数据，成本高）<br/>  · 模型合并：直接操作权重（不需要数据，零成本！）<br/><br/>  · 三大方法：<br/>      1. 权重平均：θ_merged = (θ_1 + θ_2 + ... + θ_K) / K<br/>      2. 任务算数：θ_merged = θ_base + λ * Σ (θ_i - θ_base)<br/>      3. SLERP：在球面插值（更高级）<br/><br/>第2层：任务算数的代码实现<br/>  · 计算任务向量：τ_i = θ_finetuned_i - θ_base<br/>  · 合并：θ_merged = θ_base + λ * Σ τ_i<br/>  · 直觉：「微调 = 在基础模型上添加任务特定知识」<br/><br/>  · 关键参数：λ（缩放因子）<br/>      - λ = 1.0：完整添加任务向量<br/>      - λ = 0.5：添加一半（防止任务冲突）<br/>      - λ = 0.0：不添加（等于基础模型）<br/><br/>第3层：什么情况下有效？<br/>  · 情况1：任务「相似」（如「客服」和「问答」）<br/>      → 任务向量方向相似 → 合并后效果提升<br/>  · 情况2：模型架构相同 + 训练数据不同<br/>      → 权重空间兼容 → 合并后效果提升<br/>  · 情况3：多检查点平均（SWA）<br/>      → 提升训练稳定性 → 效果提升<br/><br/>第4层：什么情况下无效？<br/>  · 情况1：任务「冲突」（如「中文写作」和「英文写作」）<br/>      → 任务向量方向相反 → 合并后两个任务都变差<br/>  · 情况2：模型架构不同<br/>      → 权重空间不兼容 → 无法合并<br/>  · 情况3：λ 选择不当<br/>      → λ 太大 → 任务冲突；λ 太小 → 效果不明显<br/><br/>实验数据（Agent Harness 项目）：<br/>  任务组合                | 合并方法       | 效果（相对单任务）<br/>  ──────────────────────────────────────────────────────────<br/>  客服 + 问答           | Task Arithmetic | 95%（几乎无损）<br/>  代码 + 写作           | Task Arithmetic | 88%（轻微损失）<br/>  中文 + 英文           | Task Arithmetic | 72%（明显冲突）<br/>  多检查点平均（SWA）   | 权重平均       | 102%（稳定性提升）<br/><br/>面试加分：<br/>  "模型合并的精妙之处在于：<br/>    它用『线性代数』实现了『多任务学习』。<br/><br/>    但需要警惕『参数冲突』：<br/>    不是所有任务都可以随意合并。<br/><br/>    最佳实践：<br/>    1. 先评估任务相似度（用任务向量的余弦相似度）<br/>    2. 只合并相似度高的任务<br/>    3. 用网格搜索选择 λ"</code>
```
