#### **HyDE（Hypothetical Document Embedding）详解**

```
<code>async def hyde_search(query: str, vector_db, llm) -&gt; List[dict]:<br/>    """<br/>    HyDE 核心思路：<br/>    1. 让 LLM 假装回答问题，生成一段"假答案"（Hypothetical Document）<br/>    2. 用这段假答案的 Embedding 去检索<br/>    3. 假答案比原始 Query 更接近真实文档的语义空间<br/><br/>    示例：<br/>    Query: "Vue3 和 React 哪个性能更好？"<br/>    HyDE 生成的假答案: "Vue3 和 React 在性能方面各有优势。<br/>      Vue3 使用 Proxy 实现响应式... React 使用 Virtual DOM..."<br/>    → 用这段话去检索，比直接用 Query 检索效果好得多<br/>    """<br/><br/>    # Step 1: 生成假设性文档<br/>    hyde_prompt = f"""<br/>    请回答以下问题，即使你不确定也请给出尽可能合理的回答：<br/>    {query}<br/>    """<br/>    hypothetical_doc = await llm.chat(hyde_prompt)<br/><br/>    # Step 2: 用假设性文档的 Embedding 检索<br/>    query_embedding = embed(hypothetical_doc)<br/>    results = await vector_db.search(query_embedding, top_k=5)<br/><br/>    return results</code>
```

#### **语义分块 vs 固定长度分块**

```
<code># ❌ 固定长度分块（简单但容易截断语义）<br/>def naive_chunk(text: str, chunk_size: int = 500) -&gt; List[str]:<br/>    return [text[i:i+chunk_size] for i in range(0, len(text), chunk_size)]<br/><br/># ✅ 语义分块（保持段落/章节完整性）<br/>def semantic_chunk(text: str, model) -&gt; List[str]:<br/>    """<br/>    原理：计算相邻句子的 Embedding 相似度<br/>    相似度骤降的位置 → 语义断点 → 在此分块<br/>    """<br/>    sentences = split_sentences(text)<br/>    embeddings = [embed(s) for s in sentences]<br/><br/>    chunks = []<br/>    current_chunk = [sentences[0]]<br/><br/>    for i in range(1, len(sentences)):<br/>        # 计算与上一句的相似度<br/>        sim = cosine_similarity(embeddings[i], embeddings[i-1])<br/><br/>        if sim &lt; 0.5:  # 相似度骤降 → 新分块<br/>            chunks.append(" ".join(current_chunk))<br/>            current_chunk = [sentences[i]]<br/>        else:<br/>            current_chunk.append(sentences[i])<br/><br/>    if current_chunk:<br/>        chunks.append(" ".join(current_chunk))<br/><br/>    return chunks</code>
```

**使用 RAGAS 框架**

```
<code># RAGAS 评估四大核心指标<br/>ragas_metrics = {<br/>    # 1. Faithfulness（忠实度）：答案是否忠实于检索到的上下文<br/>    #    值域 0-1，越高越好<br/>    "faithfulness": 0.91,<br/><br/>    # 2. Answer Relevancy（答案相关性）：答案是否切题<br/>    #    值域 0-1，越高越好<br/>    "answer_relevancy": 0.88,<br/><br/>    # 3. Context Recall（上下文召回）：相关信息是否都被检索到了<br/>    #    值域 0-1，越高越好<br/>    "context_recall": 0.82,<br/>}</code>
```

**优化路径**：

- Faithfulness 低 → 加强 Prompt 约束（"只根据参考资料回答"）
- Answer Relevancy 低 → 优化 Query Rewrite
- Context Precision 低 → 调优 Embedding 模型 / 增加重排序
- Context Recall 低 → 扩大 Top-K / 改进分块策略

**适用场景**：

- 通用 Embedding 在特定领域效果不好（如：医疗、法律术语）
- 需要 Embedding 对某些概念更敏感

```
<code># 使用 sentence-transformers 微调<br/>from sentence_transformers import SentenceTransformer, InputExample, losses<br/><br/># 1. 加载预训练模型<br/>model = SentenceTransformer('BAAI/bge-large-zh-v1.5')<br/><br/># 2. 准备训练数据（三元组：query, positive, negative）<br/>train_examples = [<br/>    InputExample(texts=["如何退款", "退款流程", "充值流程"]),<br/>    InputExample(texts=["发票开具", "开发票", "报销流程"]),<br/>    # ... 更多训练样本<br/>]<br/><br/># 3. 构建 DataLoader<br/>from torch.utils.data import DataLoader<br/>train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=32)<br/><br/># 4. 使用 MultipleNegativesRankingLoss<br/>#    （对比学习：正例拉近，负例推远）<br/>train_loss = losses.MultipleNegativesRankingLoss(model=model)<br/><br/># 5. 微调<br/>model.fit(<br/>    train_objectives=[(train_dataloader, train_loss)],<br/>    epochs=3,<br/>    warmup_steps=100,<br/>    output_path="./fine_tuned_embedding"<br/>)</code>
```

**面试要点**：

- **数据量要求**：至少 1000 对高质量正例
- **训练数据构建**：正例：同一问题的不同表述 / 同一文档的不同分块
- 负例：不同问题的 Query / 不同主题的文档
- **评估方法**：微调前后在测试集上的 Recall@K 对比

**挑战**：

- 分块太多 → 检索噪声大
- 分块太大 → 上下文窗口不够用
- 文档结构复杂（目录、图表、附录）→ 简单分块会破坏语义

**解决方案：层级化 RAG**

```
<code>class HierarchicalRAG:<br/>    """层级化 RAG：先定位章节，再检索段落"""<br/><br/>    def __init__(self):<br/>        # 两级索引<br/>        self.chapter_index = VectorDB("chapters")   # 章节级（粗检索）<br/>        self.chunk_index = VectorDB("chunks")       # 段落级（细检索）<br/><br/>    async def build_index(self, document: str):<br/>        """构建层级索引"""<br/>        # 1. 提取文档结构（目录/标题）<br/>        for chapter in extract_chapters(document):<br/>            # 2. 章节级索引：标题+摘要 → embedding<br/>            await self.chapter_index.add(<br/>                id=chapter["id"],<br/>                embedding=embed(chapter["title"] + " " + chapter["summary"]),<br/>                metadata={"chapter_id": chapter["id"], "page_range": chapter["pages"]}<br/>            )<br/>            # 3. 段落级索引（关联到章节）<br/>            for chunk in semantic_chunk(chapter["content"]):<br/>                await self.chunk_index.add(<br/>                    id=chunk["id"], embedding=embed(chunk["content"]),<br/>                    metadata={"chapter_id": chapter["id"]}<br/>                )<br/><br/>    async def search(self, query: str) -&gt; list:<br/>        """两阶段检索"""<br/>        # Phase 1: 粗检索（定位章节）<br/>        chapters = await self.chapter_index.search(query, top_k=2)<br/>        target_chapter_ids = [c["metadata"]["chapter_id"] for c in chapters]<br/><br/>        # Phase 2: 细检索（在目标章节内搜索段落）<br/>        chunks = []<br/>        for cid in target_chapter_ids:<br/>            results = await self.chunk_index.search(<br/>                query,<br/>                top_k=5,<br/>                filter={"chapter_id": cid}  # 只在目标章节内搜索<br/>            )<br/>            chunks.extend(results)<br/><br/>        return sorted(chunks, key=lambda x: x["score"], reverse=True)[:5]</code>
```

**核心思路：LLM 负责"判断"，Rule Engine 负责"执行"**

```
<code>class HybridAgent:<br/>    """LLM + Rule Engine 混合架构"""<br/><br/>    def __init__(self):<br/>        self.llm = LLMClient()<br/>        self.rule_engine = RuleEngine()<br/><br/>        # 预定义规则（高置信度场景直接走规则，不需要 LLM）<br/>        self.rules = {<br/>            "退款查询": self._rule_refund_query,<br/>            "订单状态": self._rule_order_status,<br/>            "常见问题": self._rule_faq,<br/>        }<br/><br/>    async def handle(self, user_input: str) -&gt; str:<br/>        """混合处理"""<br/><br/>        # Step 1: LLM 意图识别<br/>        intent = await self.llm.classify(<br/>            user_input,<br/>            categories=list(self.rules.keys()) + ["其他"]<br/>        )<br/><br/>        # Step 2: 高置信度 → 直接走规则<br/>        if intent.confidence &gt; 0.9 and intent.label in self.rules:<br/>            return self.rules[intent.label](user_input)<br/><br/>        # Step 3: 低置信度 → LLM 生成回答<br/>        response = await self.llm.chat(user_input)<br/><br/>        # Step 4: 事后审核（规则引擎检查 LLM 输出）<br/>        if self.rule_engine.contains_sensitive_info(response):<br/>            return "抱歉，我无法提供该信息。"<br/><br/>        return response<br/><br/>    def _rule_refund_query(self, query: str) -&gt; str:<br/>        """规则：退款查询"""<br/>        order_id = extract_order_id(query)<br/>        return self.rule_engine.query_database(<br/>            "SELECT refund_status FROM orders WHERE id = ?",<br/>            [order_id]<br/>        )</code>
```

**面试表达**：

> "我们的策略是'规则兜底 + LLM 增强'。高频、标准化的场景（退款查询、订单状态）走规则引擎，响应快、成本零、100% 准确。复杂的、长尾的场景走 LLM。同时 LLM 的输出会经过规则引擎的事后审核，防止错误信息泄露。"
