### 2.1 RLHF vs DPO——偏好对齐算法的数学本质

**问题定义**：如何让LLM对齐人类偏好？

#### 数学推导（逐层深入）

**第1层：RLHF的目标函数**

RLHF用PPO算法最大化以下目标：

```
<code>J(θ) = E[(r(x,y) - β·KL(π_θ || π_ref))]</code>
```

其中：

- `r(x,y)`：Reward Model给出的奖励
- `KL(π_θ || π_ref)`：当前策略与参考策略的KL散度
- `β`：控制探索与利用的平衡

**第2层：DPO的数学推导**

DPO的核心洞察：**不需要显式训练Reward Model，可以直接优化策略**

从Bradley-Terry偏好模型出发：

```
<code>P(y1 ≻ y2 | x) = σ(r(x,y1) - r(x,y2))</code>
```

代入RLHF的最优策略公式：

```
<code>π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)</code>
```

取对数并整理，得到**DPO损失函数**：

```
<code>L_DPO = -E[log σ(β·log(π_θ(y_w|x)/π_ref(y_w|x)) - β·log(π_θ(y_l|x)/π_ref(y_l|x)))]</code>
```

其中 `y_w` 是偏好回答，`y_l` 是舍去回答。

**第3层：代码实现（DPO Trainer核心逻辑）**

```
<code>import torch<br/>import torch.nn.functional as F<br/><br/>def dpo_loss(model, ref_model, batch, beta=0.1):<br/>    """<br/>    DPO损失函数实现<br/>    batch: {<br/>        'prompt': [B, L_p],<br/>        'chosen': [B, L_c],   # 偏好回答<br/>        'rejected': [B, L_r]  # 舍去回答<br/>    }<br/>    """<br/>    # 1. 计算当前模型的log概率<br/>    chosen_logps = compute_logps(model, batch['prompt'], batch['chosen'])<br/>    rejected_logps = compute_logps(model, batch['prompt'], batch['rejected'])<br/><br/>    # 2. 计算参考模型的log概率（不计算梯度）<br/>    with torch.no_grad():<br/>        ref_chosen_logps = compute_logps(ref_model, batch['prompt'], batch['chosen'])<br/>        ref_rejected_logps = compute_logps(ref_model, batch['prompt'], batch['rejected'])<br/><br/>    # 3. 计算偏好对数比<br/>    pi_logratios = chosen_logps - rejected_logps<br/>    ref_logratios = ref_chosen_logps - ref_rejected_logps<br/><br/>    # 4. DPO损失<br/>    logits = pi_logratios - ref_logratios<br/>    losses = -F.logsigmoid(beta * logits)<br/><br/>    return losses.mean()<br/><br/>def compute_logps(model, prompts, responses):<br/>    """计算序列的log概率（sum of token logprobs）"""<br/>    inputs = torch.cat([prompts, responses], dim=1)<br/>    outputs = model(inputs)<br/>    logits = outputs.logits[:, :-1, :]  # [B, L-1, V]<br/>    labels = inputs[:, 1:]              # [B, L-1]<br/><br/>    logprobs = F.log_softmax(logits, dim=-1)<br/>    # 收集标签对应的log概率<br/>    response_logps = torch.gather(logprobs, -1, labels.unsqueeze(-1)).squeeze(-1)<br/><br/>    # 只计算response部分的log概率（mask掉prompt）<br/>    response_mask = (labels != tokenizer.pad_token_id)<br/>    response_logps = (response_logps * response_mask).sum(dim=1)<br/><br/>    return response_logps</code>
```

**问题定义**：LLM推理是**内存带宽瓶颈**（不是计算瓶颈），如何加速？

#### 算法原理（逐层深入）

**第1层：核心思想**

用**小模型（Draft Model）快速生成K个token** → 用**大模型（Target Model）并行验证这K个token** → 接受所有正确的前缀 → 从第一个错误位置重新采样

**关键洞察**：

- 小模型生成K个token的时间 ≈ 大模型生成1个token的时间（因为小模型参数量少）
- 如果接受率高，等效于**大模型一次生成多个token**

**第2层：数学推导（接受率分析）**

假设：

- 草稿模型分布：`q(x)`
- 目标模型分布：`p(x)`
- 贪心采样时，接受率 = `min(1, p(x)/q(x))`

**定理**：如果 `q(x)` 是 `p(x)` 的good approximation，接受率 ≈ 70-90%

**加速比公式**：

```
<code>加速比 = (K × 接受率 + 1) / (K + 1)</code>
```

例如：K=5，接受率=0.8 → 加速比 = (5×0.8+1)/(5+1) = 4.1/6 ≈ 2.7x

**第3层：代码实现（Speculative Decoding核心逻辑）**

```
<code>import torch<br/>from typing import List<br/><br/>def speculative_decoding(<br/>    draft_model,<br/>    target_model,<br/>    input_ids: torch.Tensor,<br/>    max_new_tokens: int = 100,<br/>    K: int = 5,  # 草稿token数量<br/>    temperature: float = 1.0<br/>):<br/>    """Speculative Decoding 主函数（伪代码骨架）<br/>    流程：1) draft_model 生成 K 个 token  2) target_model 并行验证<br/>    3) 接受所有正确的前缀  4) 从第一个错误位置重采样"""<br/>    generated = input_ids.clone()<br/><br/>    for step in range(max_new_tokens):<br/>        # === 第1步：草稿生成（逐 token 采样，记录概率）===<br/>        draft_tokens, draft_probs, current_input = [], [], generated.clone()<br/>        for k in range(K):<br/>            with torch.no_grad():<br/>                draft_logits = draft_model(current_input).logits[:, -1, :] / temperature<br/>                draft_prob = F.softmax(draft_logits, dim=-1)<br/>                draft_token = torch.multinomial(draft_prob, 1)  # [B, 1]<br/>                draft_tokens.append(draft_token)<br/>                draft_probs.append(draft_prob)<br/>                current_input = torch.cat([current_input, draft_token], dim=1)<br/>        draft_tokens = torch.cat(draft_tokens, dim=1)  # [B, K]<br/>        # === 第2步：目标模型并行验证（一次前向传播）===<br/>        verify_input = torch.cat([generated, draft_tokens], dim=1)  # [B, L+K]<br/>        with torch.no_grad():<br/>            target_logits = target_model(verify_input).logits[:, -K-1:, :]  # [B, K+1, V]<br/>        target_probs = F.softmax(target_logits / temperature, dim=-1)<br/>        # === 第3步：逐位置验证 ===<br/>        accepted_tokens = []<br/>        for k in range(K):<br/>            draft_token = draft_tokens[:, k]  # [B]<br/>            # 草稿/目标模型在位置 k、token 处的概率<br/>            draft_prob = draft_probs[k].gather(-1, draft_token.unsqueeze(-1)).squeeze(-1)<br/>            target_prob = target_probs[:, k, :].gather(-1, draft_token.unsqueeze(-1)).squeeze(-1)<br/>            # 接受概率 min(1, p_target / q_draft)，均匀采样决定接受<br/>            accept_prob = torch.min(torch.ones_like(draft_prob), target_prob / draft_prob)<br/>            if (torch.rand_like(accept_prob) &lt; accept_prob).all():<br/>                accepted_tokens.append(draft_token.unsqueeze(1))<br/>            else:<br/>                #   ★特殊点1 从拒绝位置的重采样修正分布 max(0, p - q) 采样并终止本步<br/>                corrected_dist = F.softmax(<br/>                    (target_logits[:, k, :] - draft_logits[:, :]).clamp(max=0) / temperature,<br/>                    dim=-1)<br/>                accepted_tokens.append(torch.multinomial(corrected_dist, 1))<br/>                break<br/>        # === 第4步：拼接已接受 token；生成 EOS 则提前结束 ===<br/>        if accepted_tokens:<br/>            generated = torch.cat([generated, torch.cat(accepted_tokens, dim=1)], dim=1)<br/>        if (generated[:, -1] == eos_token_id).all():<br/>            break<br/>    return generated</code>
```

**问题定义**：LLM倾向于生成冗长、重复的回答，如何控制生成长度？

#### 技术方案（逐层深入）

**第1层：问题根因分析**

1. **训练数据偏差**：SFT数据中长回答占比高（因为"详细回答"被标记为高质量）
1. **RLHF奖励黑客**：模型发现"生成长回答"可以获得更高的Reward（因为sum logprob更大）
1. **解码策略问题**：贪心解码倾向于重复，采样温度高时倾向于发散

**第2层：Length-Controlled Decoding（推理时控制）**

**核心思想**：在生成时，对"过长"的候选token施加惩罚

**算法流程**：

1. 生成N个候选回答（Beam Search或采样）
1. 计算每个候选的"长度归一化得分"：`score = logp(response) / len(response) + α·length_penalty(len)`
1. 选择得分最高的回答

**代码实现**：

```
<code>def length_controlled_generate(<br/>    model,<br/>    input_ids,<br/>    max_length: int = 512,<br/>    num_return_sequences: int = 5,<br/>    length_penalty: float = 1.0<br/>):<br/>    """<br/>    Length-Controlled Decoding<br/>    生成多个候选，按长度归一化得分排序<br/>    """<br/>    # 1. 生成N个候选（Beam Search）<br/>    outputs = model.generate(<br/>        input_ids,<br/>        max_length=max_length,<br/>        num_return_sequences=num_return_sequences,<br/>        do_sample=True,<br/>        top_p=0.95,<br/>        num_beams=num_return_sequences<br/>    )<br/><br/>    # 2. 计算每个候选的得分<br/>    scores = []<br/>    for seq in outputs:<br/>        logp = compute_sequence_logp(model, input_ids, seq)<br/>        length = len(seq) - len(input_ids)<br/>        # 长度归一化 + 长度惩罚<br/>        normalized_score = logp / length - length_penalty * (length / max_length)<br/>        scores.append(normalized_score)<br/><br/>    # 3. 选择得分最高的<br/>    best_idx = torch.argmax(torch.tensor(scores))<br/>    return outputs[best_idx]</code>
```

**第3层：RL微调 + 长度惩罚（训练时控制）**

**核心思想**：在RL目标函数中加入长度惩罚项

**改进的GRPO目标函数**：

```
<code>J(θ) = E[reward(x,y) - β·KL(π_θ||π_ref) - γ·len(y)/len_max]</code>
```

其中 `γ` 是长度惩罚系数（通常取 0.01-0.1）

**代码实现（GRPO Trainer）**：

```
<code>def grpo_loss_with_length_penalty(<br/>    model,<br/>    ref_model,<br/>    batch,<br/>    beta: float = 0.1,<br/>    gamma: float = 0.05  # 长度惩罚系数<br/>):<br/>    """<br/>    GRPO损失函数 + 长度惩罚<br/>    """<br/>    prompts = batch['prompt']  # [B, L_p]<br/>    responses = batch['response']  # [B, L_r]<br/><br/>    # 1. 计算当前模型的log概率<br/>    logps = compute_logps(model, prompts, responses)  # [B]<br/><br/>    # 2. 计算参考模型的log概率<br/>    with torch.no_grad():<br/>        ref_logps = compute_logps(ref_model, prompts, responses)  # [B]<br/><br/>    # 3. 计算KL散度<br/>    kl = logps - ref_logps  # [B]<br/><br/>    # 4. 计算长度惩罚<br/>    lengths = (responses != tokenizer.pad_token_id).sum(dim=1)  # [B]<br/>    length_penalty = gamma * lengths / 512  # 假设max_length=512<br/><br/>    # 5. GRPO损失 + 长度惩罚<br/>    advantages = batch['reward'] - beta * kl - length_penalty<br/>    loss = - (logps * advantages.detach()).mean()<br/><br/>    return loss</code>
```

**四层深度答案**：

**第1层：理论上限**

假设草稿模型 `q(x)` 和目标模型 `p(x)` 完全相同，接受率 = 100%（因为 `p(x)/q(x) = 1`）

但实际中 `q(x) ≠ p(x)`，接受率上限由**两个分布的总变分距离（Total Variation Distance）**决定：

```
<code>接受率 ≤ 1 - TV(q||p) / 2</code>
```

**第2层：影响接受率的因素**

1. **草稿模型质量**：草稿模型越接近目标模型，接受率越高
1. **生成温度**：温度越高，分布越平滑，接受率越低
1. **token难度**：高频词接受率高，低频词接受率低

**第3层：提升接受率的方法**

1. **Self-Speculative（DeepSeek-V3）**：不用独立草稿模型，而是用目标模型的前几层作为草稿模型
1. 接受率：78% → 85%
1. **Tree-based验证**：同时验证多个候选分支
1. 接受率：+10-15%
1. **自适应草稿数量K**：简单token：K=5-10
1. 复杂token：K=2-3
1. 平均接受率：+5-10%

**方案2：Length-Controlled Decoding**

- 缺点：推理时 +20%

**代码实现**：

```
<code>def length_controlled_generate(model, prompt, max_len=512, num_candidates=5):<br/>    # 1. 生成多个候选<br/>    candidates = [model.generate(prompt) for _ in range(num_candidates)]<br/><br/>    # 2. 计算长度归一化得分<br/>    scores = [logp(c) / len(c) - 0.05*len(c)/max_len for c in candidates]<br/><br/>    # 3. 选择得分最高的<br/>    return candidates[argmax(scores)]</code>
```
