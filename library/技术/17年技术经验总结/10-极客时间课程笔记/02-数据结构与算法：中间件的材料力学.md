## 一、复杂度分析：开工前的"载荷估算"

《之美》03/04讲和《通关》03讲都把复杂度分析放最前面，不是仪式感——

```
复杂度 = 估算结构载荷的手艺：
  - 时间复杂度：CPU 账单
  - 空间复杂度：内存账单
  - 最好/最坏/均摊：比如动态数组扩容，均摊 O(1)，但最坏一次 O(n)
    —— Redis 渐进式 rehash、Java HashMap 树化，都是在"抹平最坏情况"

工程推论：凡是最坏情况会被放大成线上事故的地方（Redis 单线程、GC 停顿），
设计者都会花大力气把"最坏 O(n)"改造成"均摊 O(1)"或"分摊到每次操作"。
```

再加一条课程里没直说但工程里天天用的：**常数因子与缓存局部性**。

```
CPU 缓存行 = 64 字节。数组连续存储，一次缓存行加载带上邻居；
链表每个节点散落在堆里，每跳一次都可能是一次缓存未命中。
→ 同样是 O(n) 遍历，数组可能比链表快 5~10 倍——这就是"复杂度相同，性能悬殊"的秘密。
伪共享：两个线程各写一个变量，但两变量恰好在同一缓存行 → 互相打架
  → Disruptor 缓存行填充（《之美》54讲）就是这么来的
```

## 二、逐个盘点：每种材料的物理脾气

### 2.1 数组 vs 链表：内存连续性的胜利

```
数组：内存连续 → CPU 缓存行(64B)一次加载多个元素 → 遍历快
      随机访问 O(1)；插入删除 O(n)；扩容要整体搬家
链表：指针跳转 → 每跳一次都是一次随机访存 → 缓存不友好
      插入删除 O(1)；随机访问 O(n)；每个指针 8B 的隐性空间税

工程推论：
  - Redis ziplist/listpack、Kafka 日志、Protobuf —— 热路径全在用"连续内存数组"思想
  - LRU Cache（《通关》55/56讲）= 哈希表(定位) + 双向链表(维护时序)
    —— 组合结构是中间件的常态：单一结构几乎从不直接满足工程需求
```

### 2.2 散列表：O(1) 的代价

工业级散列表（《之美》19讲核心命题）要同时解决四件事：

```
1. 哈希冲突：链表法(Java HashMap) / 开放寻址(ThreadLocalMap)
2. 扩容搬迁：负载因子超阈值 → rehash，最坏 O(n)
     → Redis 的答案：渐进式 rehash，把搬迁成本摊到每次操作上（见 03 篇）
     → Java 8 的答案：链表长度≥8 且桶数≥64 树化成红黑树，最坏 O(log n)
3. 哈希函数：快 + 均匀 + 抗碰撞（MurmurHash 在 Redis/Nginx 都在用）
4. 无序性：散列表天生不支持范围查询
     → 这就是"为什么还需要树"（《之美》24讲的标题即答案）
```

### 2.4 堆：TopK 和定时器的底座

- TopK：维持 k 大小的小顶堆，O(n log k)（《之美》29讲：热搜 Top10）
- 定时任务：优先队列/时间轮
  - Netty HashedWheelTimer、Kafka 延迟队列、Linux 内核 htimer —— **OS 和中间件又想到一起去了**
- 为什么堆排序没有快排快（28讲）：堆的访存是跳跃式的（parent/child 下标差一半），缓存不友好；快排是顺序分区——**又是缓存局部性赢**

## 三、"改造清单"：经典结构上中间件都动了哪刀

| 经典结构 | 中间件改造 | 为什么动刀 |
|---------|-----------|-----------|
| 哈希表 | Redis 渐进式 rehash | 单线程不能容忍一次 O(n) 搬迁 |
| 哈希表 | HashMap 树化(8→红黑树) | 恶意 hash 碰撞的 DoS 防御 |
| LRU | InnoDB young/old 分区 LRU | 全表扫描会污染全缓存（04篇） |
| LRU | Redis 近似 LRU(抽样5个) | 全局双向链表的锁和内存太贵（03篇） |
| B+树 | InnoDB change buffer | 二级索引写先攒着，读时合并 |
| 跳表 | Redis 加 span(跨度)字段 | 快速按排名查询(zrank) |
| 双向链表 | Redis quicklist(listpack链) | 大列表内存与性能折中 |
| 队列 | Disruptor 环形无锁队列（《之美》54讲） | 锁和伪共享都比想象中贵 |
| 堆 | 内核 hrtimer 红黑树/时间轮 | 大量定时器的插入删除成本 |

## 四、把"选材"问题变成一个决策树

```
你要解决什么？
├─ 精确按键查一条 → 散列表（内存）/ B+树（要落盘、要范围）
├─ 范围查询/排序遍历
│   ├─ 内存、改多读少 → 跳表
│   ├─ 内存、稳定延迟 → 红黑树
│   └─ 磁盘 → B+ 树（页对齐、矮胖）
├─ TopK / 优先级 → 堆
├─ 存在性判断(海量) → 布隆过滤器 / 位图
├─ 关系/依赖 → 图 + 拓扑排序
└─ 时序去重/最近使用 → 哈希表 + 双向链表 (LRU)
```
