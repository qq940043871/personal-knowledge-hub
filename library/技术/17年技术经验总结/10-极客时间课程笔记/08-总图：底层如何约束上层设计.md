## 二、约束矩阵：每个软件 × 每条底层约束

| 底层约束 | Redis | MySQL | Nginx | JVM | Tomcat |
|---------|-------|-------|-------|-----|--------|
| **磁盘随机IO慢5个量级** | 全内存+持久化顺序化(AOF/RDB) | B+树矮胖+redo顺序写+Buffer Pool | sendfile零拷贝 | 堆外/mmap读写文件 | 静态资源靠sendfile，业务交给OS |
| **fsync 是诚实税** | AOF everysec 丢1秒 | 双1配置+组提交 | — | — | — |
| **线程/上下文切换贵** | 单线程命令执行(6.0仅IO并行) | 后台刷脏/主线程几乎不碰盘 | 多worker单线程 | 线程池、TLAB、(虚拟线程) | BIO→NIO：O(连接)→O(活跃) |

## 三、五个软件，五种答案（一段话复盘）

- **Redis**：数据小而热，全放内存。既然计算是纳秒级，就别让锁和切换污染它——单线程，把并发难题变成"近似"和"渐进"。**它信奉：够用的近似 > 昂贵的精确。**
- **MySQL**：数据大而冷，必须落盘。那就把随机写全换成顺序写（WAL），把热数据全搬进内存（Buffer Pool），把崩溃恢复做成重放日志（crash-safe）。**它信奉：顺序写 + 批量刷 + 双保险。**
- **Nginx**：没有业务逻辑，只有流量。把线程消灭掉（事件驱动），把拷贝消灭掉（sendfile），把进程做成可接班的（master-worker 平滑重启）。**它信奉：为流量而生的极简。**
- **JVM**：要给业务一个"看不见内核"的幻觉。内存是 malloc 出来的，线程是 clone 出来的，停顿是缺页中断报出来的。**它信奉：把 OS 的能力翻译成托管世界的概念。**
- **Tomcat**：业务必须执行（Servlet 阻塞语义），线程不可省但必须省着用——于是 Connector 换了三代 IO 模型，Container 稳如老狗。**它信奉：把"被 OS 推着变"和"业务语义要稳"分层。**

## 四、万能追问链（面试和实战都好用）

```
Q：XX 为什么这么设计？
  └─ A1：它在对抗哪个物理瓶颈？（磁盘慢？切换贵？fsync诚实税？内存有限？）
       └─ A2：它用什么数据结构+IO模型来对抗？（→ 02篇决策树 + 01篇IO模型谱系）
            └─ A3：这个方案又引入了什么新问题？（渐进式rehash的双表查询、
                 WAL的双日志一致性、NIO的Buffer管理、GC的跨代引用……）
                 └─ A4：它怎么解决新问题？（通常还是那几招：分层、攒批、
                      增量、近似、双保险——回到 01 篇账单思想）
```

**例题自测（每题都能用追问链答四层）：**
1. Redis 为什么 6.0 才引入多线程？为什么只多线程网络部分？
2. MySQL 为什么 redo log 和 binlog 要两阶段提交，不能合一？
3. Nginx 为什么 worker 数建议等于核数，而不是核数×2？
4. JVM 为什么分代？ZGC 为什么能摆脱堆大小对停顿的影响？
5. Tomcat 从 BIO 到 NIO，`acceptCount` 的语义为什么一直没变？
6. 浏览器为什么 JS 单线程却"并发"？（13篇）
7. 前端为什么没有"锁"这个概念？（14篇：一致性被语言层消化了）
