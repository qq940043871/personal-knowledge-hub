# 10 · 高并发系统设计：演进路径

> 来源课程：《高并发系统设计40问》(49讲) + 《从0开始学架构》高性能篇 + 《微服务架构实战160讲》
> 定位：**这是"装配说明书"——五大软件(MySQL/Redis/Nginx/JVM/Tomcat)是零件，本篇讲它们按什么顺序、为什么被装进系统。**
> 更新时间：2026-11-06

## 一、一条主线：并发量增长 × 架构演进（课程01讲通用方法论）

```
所有高并发问题只有三个终极答案（01讲）：
  1. Scale-up 垂直扩展：换更强的机器 —— 有物理上限，先快后死贵
  2. Scale-out 水平扩展：加更多机器 —— 架构复杂度换容量
  3. Cache 缓存：减少对下游的访问 —— 用空间和一致性换时间

演进顺序（与业务量对齐，不要提前过度设计）：
  单体 All-in-one
  → 数据库读写分离（05-MySQL 主从的登场理由）
  → 缓存加速读（06-Redis 的登场理由）
  → 消息队列削峰（07-消息中间件的登场理由）
  → 服务化拆分 + RPC（Tomcat/Netty 集群的登场理由）
  → 分库分表 + NoSQL 互补
  → 多机房 / 单元化
```

## 二、每一步演进 = 给某个底层瓶颈"续命"

| 演进步骤 | 缓解的瓶颈 | 对应课程讲次 | 底层关联（01篇） |
|---------|-----------|-------------|-----------------|
| 读写分离 | 单库连接数 + 读磁盘压力 | 08讲 | 连接=fd，读=磁盘IO |
| 分库分表 | 单表 B+ 树过高 + 写入集中 | 09/10讲 | 树高=IO次数（04篇2000万经验值） |
| 引入缓存 | 数据库读 QPS | 12~15讲 | 内存 100ns vs 磁盘 100μs（01篇账单） |
| 消息队列 | 瞬时写洪峰 | 17~19讲 | 把同步 fsync 链变成异步削峰 |
| 服务化+RPC | 单机 CPU/内存上限 | 21~23讲 | 核数上限（CPU定律） |
| 负载均衡/API网关 | 流量分配与治理 | 26/27讲 | Nginx 的主场（05篇） |
| 多机房 | 单机房物理灾害 | 28讲 | 跨机房 RTT 是新的硬约束 |

## 三、池化：被低估的"第一优化"（课程07讲）

```
为什么先讲池化：创建数据库连接 = TCP三次握手 + 认证 + 内存分配
  → 毫秒级成本 × 每请求一次 = 灾难
池化的通用公式：
  连接池(db/redis/http) 线程池(Tomcat Executor) 内存池(Nginx/Netty) 对象池
  —— 全部是同一个思想：把"贵的创建"变成"便宜的租还"（01篇账单思想）

池的参数怎么定（07讲+06篇JVM线程）：
  连接池大小 ≈ 核数 × 2 + 磁盘数（HikariCP 公式，源自"CPU满转+IO等待"模型）
  线程池   ≈ 核数/(1-阻塞系数)
  —— 不是玄学，是排队论：池太大反而增加调度和上下文切换
```

## 四、缓存篇的完整方法论（课程12~15讲）

```
读写模式（13讲）：
  Cache Aside（旁路缓存）= 业务标配：读→缓存miss→查库→回填；写→先更库→再删缓存
  为什么是"删缓存"不是"改缓存"：并发写+读写交错时，改缓存会产生脏数据（延迟写覆盖）
  为什么"先更库再删缓存"：先删缓存的话，删完旧值又被回填（读到旧库值）

穿透/击穿/雪崩（14/15讲）：
  穿透：查不存在的key → 布隆过滤器（02篇）/ 空值缓存
  击穿：热key过期瞬间打穿 → 互斥重建 / 逻辑过期
  雪崩：大批key同时过期 → 过期时间加抖动 / 多级缓存
  —— 三个词的本质都是"缓存与数据库之间的一致性窗口"被放大

多级缓存：CDN(16讲) → Nginx proxy cache → Redis → JVM 本地缓存
  —— 每一级都是一次"离用户更近"（01篇：访问路径越长越慢）
```

## 五、服务化之后的新问题（课程21~29讲）

```
服务拆分后，"一次请求"变成了"一次调用链"：
  [客户端] → [网关 Nginx/Kong] → [A 服务 Tomcat] → [B 服务] → [Redis] → [MySQL]
                                        └→ [MQ] → [C 服务]

新问题与解法（每一条都是分布式版的底层约束）：
  RPC毫秒级(23讲)      → Netty(06篇同源) + 连接池 + 序列化选型
  服务寻址(24讲)       → 注册中心(CP还是AP=09篇CAP选择)
  慢请求排查(25讲)     → 分布式Trace：一次请求一条traceId
                        （对标01篇"Linux性能优化"方法论的分布式版）
  负载均衡(26讲)       → 四层(LVS/DPVS) vs 七层(Nginx) —— 05篇的集群形态
  API网关(27讲)        → 认证/限流/路由前置，本质是"把横切关注点上移"
  多机房(28讲)         → 单元化：让请求尽量封闭在一个机房内（RTT定律）
  Service Mesh(29讲)   → 把"服务治理"下沉到 sidecar —— 管理设计的边车模式（11篇）
```

## 六、维护篇：让系统"活得久"（课程30~36讲）

```
监控(30/31讲)：指标分层 —— 系统(CPU/内存/IO, 01篇工具箱)
              → 组件(QPS/RT/错误率) → 业务(订单/转化)
压测(32讲)：全链路压测 = 在生产环境影子流量，验证"账单模型"的真实容量
配置管理(33讲)：Apollo 配置中心（11篇微服务模块化详解）
降级熔断(34讲)：熔断=快速失败保护上游；降级=牺牲非核心保核心
              （Hystrix/Sentinel 的思想；11篇 Hystrix 模块详解）
限流(35讲)：计数器/漏桶/令牌桶 —— 02篇算法的直接工程应用
```
