# 文字为啥非得向量化 嵌入矩阵中隐藏的真理

> 白话Transformer（二）—— 从数字到语义：Transformer中的词向量化之路

## 一、引言

在上一期中，我们鸟瞰了Transformer的整体架构，理解了其“编码-解码”的核心范式。然而，一切伟大的旅程都始于第一步。对于机器而言，理解人类语言的第一步，并非理解其语义，而是处理其形式。

文字，在计算机世界中最初只是一串离散的符号。如何让这些符号承载意义，并成为模型可以计算的原料？这便是本章要探讨的核心问题：**向量化**。我们将深入Transformer故事的开端，厘清一条从简单数字到丰富语义的演进之路。

### 1. 内容回顾

在第一期中，我们了解到Transformer是一个序列到序列的模型，其核心由编码器和解码器构成，依赖自注意力机制等模块处理序列信息。然而，模型内部的全都是矩阵运算，它无法直接处理“苹果”、“喜欢”这样的文字符号。

### 2. 本期主题

因此，本期我们将深入故事的“开头”——**向量化**。具体而言，是探讨如何将离散的文字单元（Token）转换为模型可以处理的连续数值形式。

### 3. 核心问题

我们如何让机器“理解”文字？第一步，也是最关键的一步，就是将其转化为数学形式——即**向量**。这个过程，通常被称为**词嵌入**。

## 二、核心概念：维度、向量与线性可分

在探讨复杂的语言之前，让我们先从一个简单的分类问题入手，建立对向量的直观感受。

### 1. 直观案例：男女生分类

假设我们有一群男生和女生，并为每个人分配一个数字编号。

- **一维情况（一个数字）**：如果仅用一个数字（如学号）来表示每个人，你会发现，要找到一条清晰的线（一个规则）来划分男生和女生，边界可能非常复杂曲折（非线性）。
- **二维情况（两个数字）**：如果我们为每个人分配两个数字，例如（编号，身高），那么划分任务可能就变得简单得多。我们或许只需一条直线，就能大致区分两个区域。

### 2. 数学抽象

这个简单的例子揭示了向量与维度的关键洞见：

- **一维向量 vs. 二维向量**：一维向量（一个数字）所能表达的信息非常有限，数据点只能在一条直线上排布。二维向量（两个数字）则将数据铺展在一个平面上，增加了信息表达的维度和灵活性。
- **关键洞见：高维空间中的数据更可能“线性可分”**：随着维度的增加，数据点在高维空间中的分布变得更加稀疏，模型越有可能找到一个简单的超平面（在二维中是直线，三维中是平面）来区分不同类别的数据。这对机器学习模型至关重要。
- **术语**：
  - **升维**：将数据从低维空间映射到高维空间的过程。
  - **降维**：将数据从高维空间映射到低维空间的过程（常用于可视化）。

> **核心启示**：为了充分表达词语的丰富含义，我们需要使用**维度足够高**的向量来表示每个词。

## 三、词嵌入的历史演进

明白了向量维度的重要性后，我们回到文本处理领域，看看技术是如何演进的。

### 1. 从“字”到“词”：Token与分词

在自然语言处理中，我们首先需要确定处理的基本单位。这个最小单位被称为**Token**。它可以是一个字、一个词，甚至是一个子词（如“playing”被分为“play”和“##ing”）。将一段文本切分成Token序列的过程，称为**分词**。

### 2. 人工定义特征的时代

**方法**：为向量的每一维手动定义一个明确的语义特征（如第1维代表“食物属性”，第2维代表“动物属性”），然后为每个词在这些维度上打分。

**问题**：词的含义极其丰富、抽象且多变，人工无法穷举和精确量化所有特征。这种方法不现实。

### 3. One-Hot编码（独热编码）

为了摆脱人工定义的困境，一种极端的自动化方法出现了。

- **方法**：假设词表大小为V，则每个词用一个V维向量表示。该词在词表中索引的位置为1，其余所有位置均为0。
- **优点**：简单，且每个词有唯一的标识。
- **缺陷**：
  1. **维度灾难**：当词表很大时（如数万维），向量极其稀疏，计算和存储效率低下。
  2. **无法表达相似性**：任意两个不同词的One-Hot向量正交，点积恒为0，意味着模型认为“国王”和“女王”的相似度与“国王”和“苹果”完全一样，这显然不合理。

### 4. 分布式表示的兴起——Word2Vec

One-Hot编码的根本问题在于，其向量内部的各个维度没有内在联系。Word2Vec等模型提出了革命性的**分布式表示**思想。

- **核心思想**：放弃人为定义每个维度的含义，转而让模型通过一个自监督任务，从海量文本中自动学习每个词的向量表示。
- **训练目标**：以“预测上下文”为例。
  - **正样本**：给定一个中心词（如“苹果”），最大化其与上下文词（如“水果”、“手机”）的向量相似度（点积）。
  - **负样本**：随机采样一些不相关的词（如“汽车”、“法律”），最小化它们与中心词的向量相似度。
- **训练结果**：经过训练，得到一个稠密的词向量矩阵（维度远小于词表大小），其中每个词对应一个蕴含了语义信息的向量。
- **惊艳特性**：
  1. **语义聚集**：意思相近的词，其向量在空间中距离更近。
  2. **语义算术**：能够进行向量运算，例如：`vector(‘king’) - vector(‘man’) + vector(‘woman’)` 的结果与 `vector(‘queen’)` 非常接近。
- **遗留问题**：
  1. **静态向量**：一个词只有一个固定的向量表示，无法处理一词多义（例如，“苹果”在“吃苹果”和“苹果公司”中含义不同，但向量相同）。
  2. **非端到端**：Word2Vec作为一个独立的预训练过程，生成的词向量矩阵在下游任务中通常被**冻结**，不随任务更新，导致特征提取与任务训练过程割裂。

## 四、Transformer的解决方案：嵌入矩阵与端到端训练

为了克服Word2Vec的局限性，并充分利用深度学习的优势，现代Transformer模型采用了一种更简洁、更强大的范式。

### 1. 现代范式

将词向量矩阵（现正式称为**嵌入矩阵，Embedding Matrix**）视为模型参数的一部分，与其他所有参数一起，从零开始进行**端到端训练**。

### 2. 处理流程

1. **输入**：一个句子（如“我喜欢吃苹果”）。
2. **分词与映射**：句子被分词为Token序列（如`[“我”, “喜欢”, “吃”, “苹果”]`）。每个Token被映射为一个数字ID（该词在预设词表中的索引，如`[101, 567, 233, 892]`）。
3. **查找**：模型拥有一个形状为 `[vocab_size, embedding_dim]` 的嵌入矩阵（随机初始化）。程序根据每个Token的ID，从嵌入矩阵中查找出对应的行向量。这个向量就是该Token的**词嵌入**。
4. **训练与更新**：这些词嵌入向量直接输入到Transformer的编码器/解码器中。随着模型在最终任务（如下一词预测、文本分类）上进行训练，损失函数的梯度会**反向传播**到嵌入矩阵，使其不断更新，从而学到最适合当前任务的词表示。

### 3. 代码实现（PyTorch示例）

```Python
import torch
import torch.nn as nn

# 1. 定义超参数
vocab_size = 10000   # 词表大小
embedding_dim = 256  # 嵌入维度

# 2. 创建可训练的嵌入层（核心：nn.Embedding）
embedding_layer = nn.Embedding(num_embeddings=vocab_size, embedding_dim=embedding_dim)

# 3. 模拟输入：一组Token IDs
token_ids = torch.LongTensor([101, 567, 233, 892]) # 句子“我喜欢吃苹果”对应的ID

# 4. 查找并获取词嵌入
token_embeddings = embedding_layer(token_ids) # 输出形状: [4, 256]

print("词嵌入向量维度:", token_embeddings.shape)
print("其中一个词的向量（前5维）:", token_embeddings[0, :5].detach().numpy())
```

> **关键点**：`nn.Embedding` 在初始化时内部矩阵是随机的。在后续的模型训练循环中，通过 `optimizer.step()` 和反向传播，这个矩阵的值会被逐步优化。

## 五、总结与展望

### 1. 演进之路总结

词向量技术经历了清晰的演进脉络：

- **人工特征定义**：理想化但不可行。
- **One-Hot编码**：简单自动化，但维度高且无法表达语义关系。
- **Word2Vec**：革命性的自动学习，得到语义向量，但静态且与下游任务割裂。
- **Transformer嵌入层**：作为端到端模型的一部分，随机初始化并在最终任务中联合训练，获得动态优化、任务适配的词表示。

**核心趋势**：从“精巧复杂”的人工设计与分阶段训练，走向“简单通用”的端到端“暴力”训练。在大数据和强大算力的支撑下，让模型自己从头学习一切，往往能取得更优的效果。

### 2. 当前局限性

尽管取得了巨大进步，但本章所讲的**词嵌入**仍然是**静态的**。即，同一个词（Token ID）无论出现在何种上下文中，其嵌入向量在送入后续模块前都是相同的。模型仍未具备根据上下文动态调整词义的能力。

### 3. 下期预告

那么，如何让词向量“动”起来，根据上下文赋予“苹果”不同的含义？答案就藏在Transformer的后续模块中。下期，我们将深入Transformer内部，重点剖析**自注意力机制**，看它如何对静态的词嵌入进行加权混合，从而生成富含上下文信息的**动态表示**。
