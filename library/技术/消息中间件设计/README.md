# 消息中间件设计

> **系列定位**：本系列是消息中间件的**存储层设计文档集**——聚焦数据模型的表结构设计（SQL Schema）、高可用与集群方案、安全与监控运维设计，以及配套的实施指南（建表脚本 / ER 图 / API 清单 / 部署配置）。
>
> **本系列不包含消息引擎的实现代码**：文章描述的是"如何设计支撑一个消息中间件的存储与集群方案"，而非"如何用代码写出消息中间件"。如需引擎实现类内容，请参考本库其他"手写"系列。
>
> 说明：本系列原名"手写消息中间件"，因内容实为数据库设计而非引擎实现，已于 2026-11 更名为"消息中间件设计"。

## 📌 设计理念

1. **可靠性优先** — 消息不丢、不重、不乱序是底线
2. **分层解耦** — 协议层、路由层、存储层清晰分离
3. **可观测** — 所有关键路径均有埋点，便于监控告警
4. **易扩展** — 核心模型稳定，业务扩展通过插件实现
