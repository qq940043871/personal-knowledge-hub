# 通俗理解范围管理

项目范围是项目经理最主要关注的事情，没有范围啥事都干不成，先要有知道干啥，先规划下【范围规划】有了这些，然后就是知道都敢那些活【范围定义】，有了这些定义，总是需要分解下，【WBS】,分解完了，找客户确定下，免得错了【范围确认】有了这些就可以开始，大部分时间就是需要控制别跑偏了【范围控制】。
先说规划，也就是计划，依靠的东西都差不多 整体的项目管理计划【项目管理计划】，刚开始啥都没有可以用【项目章程】在依靠下公司的经验和制度【组织过程资产】【企业环境因素】，最重要的就是范围说明书，没有这个其他都是白搭 【范围说明书】有了这些，依靠一些方法比如老人的经验最有用【专家判断】，然后就是一些模板技术【模板和技术】这个是用的最多，然后就可以编写一个【范围管理计划】了。
范围管理计划搞定了，就开始梳理都有些工作的点了，靠的是什么？比如依靠范围说明书【范围说明书】，依靠一些经验制度【组织过程资产】，还有就是制定的计划【范围管理计划】还有就是过程中，那个大爷提出一些变更【批准的变更请求】有了这些加上点手段 比如刚开始对产品的分析【产品分析】，对哪些负责的大爷也要分析下【干系人分析】比如领导老人们的建议【专家判断】，定义的时候肯定有一些二选一【可选方案的识别】有这些基本就可以定义范围了，那么范围说明书可以更新下【范围说明书更新】，比如有一个范围清单【范围清单】，比如把整体的项目计划更新下，万一多识别出来 一个功能【项目管理计划书】然后就是请求的新的变更【请求的变更】。
定义出来工作的点了，基本就可以对范围进行分解了也就是【wbs】，靠的东西就是之前的比如范围、计划、公司的经验教训【项目管理计划】【范围管理计划】【范围说明书】【组织过程资产】还有就是批准的一些的变更【批准的需求变更】有这些加上些分解技术【分解技术】还有就是模板【WBS模板】然后就基本分解完了 ，生成一份文档 【wbs、wbs字典】，过程中发现新的变更【请求的变更】对范围说明书有影响的，就【范围说明书更新】对项目管理计划有影响的就【更新项目管理计划】，然后基本可以看出一些里程碑【范围基准】。
wbs定好了，就需要找那些大爷们确认了，如果不确认，偏差了都不认账，收不到钱，所以确认很重要，依靠啥呢？无非就是范围说明书、项目管理计划、WBS、wbs字典，还有就是交付物，客户也就是看到交付物才知道偏差，大多数这样 【范围说明书】【项目管理计划】【wbs，wbs字典】【交付物】有了这些东西，然后逐个检查【检查】基本就可以确认了，留下文档以备对质。确认完了，接受了你的交付物【已接受的额交付物】，要不就是给点建议【建议的纠正措施】然后就是提出变更【请求的变更】。
范围控制最头疼了，事情比较多，依靠的还是老几样，项目的范围、项目的计划、项目的绩效、批准的变更、分解的结构 【项目范围说明书】【项目范围管理计划】【项目的绩效信息】【绩效报告】【wbs、wbs字典】有了这些，方法很多，比如偏差太大，重新规划【重新规划】、偏差分析下【偏差分析】，比如需要变更【变更控制系统】，这么多东西总是需要管理【配置管理系统】，控制完了，就是推荐一批，更新一批，提出变更【更新范围说明书】【更新项目范围管理计划】【更新组织过程资产】【更新wbs、wbs字典】【推荐的纠正、预防、修改措施】【提出的新的变更需求】估计里程碑也会变【更新范围基线】
