# 常见技术架构

常用的技术架构可根据业务场景、规模和技术特性分为以下几类，覆盖从单体到分布式、从传统到云原生的主流形态：

## 1. 单体架构（Monolithic Architecture）
核心是将所有功能模块打包成一个独立应用，部署在单一服务器上。

+ 优势：开发简单、部署便捷、初期维护成本低，适合小型项目或初创阶段产品。
+ 典型场景：个人项目、小型企业内部系统（如简单的办公OA）。

## 2. 分层架构（Layered Architecture）
属于单体架构的优化形式，按职责将系统划分为纵向层级，常见的是“三层架构”或“四层架构”。

+ 核心层级：表现层（用户交互）、业务逻辑层（核心业务处理）、数据访问层（与数据库交互），部分会增加领域层（封装业务实体）。
+ 优势：职责清晰、便于代码复用和维护，是传统应用的主流架构。
+ 典型场景：传统管理系统、企业级CRUD应用。

## 3. 微服务架构（Microservices Architecture）
将系统拆分为多个独立的小型服务，每个服务聚焦单一业务能力，通过API实现跨服务通信。

+ 优势：可独立开发、部署和扩展，技术栈灵活，能应对高并发和复杂业务场景。
+ 挑战：需要解决服务注册发现、分布式事务、链路追踪等问题。
+ 典型场景：大型互联网应用（如电商平台、社交APP）、需要快速迭代的产品。

## 4. 微内核架构（Microkernel Architecture）
也叫“插件化架构”，核心是一个精简的内核（提供基础能力），业务功能通过插件模块实现。

+ 优势：内核稳定，插件可灵活增减，便于按需扩展和版本迭代。
+ 典型场景：IDE工具（如IntelliJ IDEA）、物联网设备系统、可定制化的SaaS平台。

## 5. 分布式架构（Distributed Architecture）
将系统功能分散到多个独立服务器节点，通过网络协同工作，核心是解决“跨节点协作”和“数据一致性”问题。

+ 关键技术：分布式缓存（Redis集群）、分布式数据库（MySQL主从复制）、消息队列（Kafka、RabbitMQ）等。
+ 优势：提高系统可用性、容错性和并发处理能力，支持横向扩展。
+ 典型场景：高并发访问的互联网平台（如直播系统、支付系统）、海量数据处理场景。

## 6. 云原生架构（Cloud-Native Architecture）
专为云环境设计，核心是利用云平台的弹性、可扩展性，结合容器化、DevOps等技术实现高效交付。

+ 核心组件：容器（Docker）、容器编排（Kubernetes）、服务网格（Istio）、无服务器架构（Serverless）等。
+ 优势：弹性伸缩、快速部署、故障自愈，适合云平台部署的各类应用。
+ 典型场景：云服务应用、大规模微服务集群、弹性需求强烈的业务（如电商大促）。

## 7. 事件驱动架构（Event-Driven Architecture）
基于“事件”传递实现组件间通信，组件通过发布/订阅事件完成协作，无需直接依赖。

+ 优势：解耦性强、响应及时，适合异步处理场景和复杂的业务流转。
+ 典型场景：实时数据处理（如日志分析）、业务流程自动化（如订单状态变更通知）。

## 8. 服务网格架构（Service Mesh）
作为微服务的补充架构，专门处理服务间的网络通信，将流量控制、安全认证、监控追踪等功能从业务代码中剥离。

+ 核心组件：数据平面（Sidecar代理，如Envoy）、控制平面（管理代理集群）。
+ 优势：简化微服务通信复杂度，统一管控网络策略，不侵入业务代码。
+ 典型场景：大规模微服务集群（如大型金融、电商的微服务系统）。
