# 资金货物灵活配置

设计“合同-履约记录-支付记录”的表结构时，需兼顾**业务完整性**（覆盖各类场景）、**灵活性**（支持规则变更）和**可扩展性**（适配新业务），核心思路是通过“主表+子表+关联表”的模式，将固定属性与动态属性分离，同时用“配置化字段”支持灵活规则。以下是具体设计方案：

## **一、核心表结构设计**
### **1. 合同主表（contract）**
存储合同基础信息，仅保留高频通用字段，避免冗余。

| 字段名 | 类型 | 说明 | 灵活性设计 |
| --- | --- | --- | --- |
| contract_id | bigint | 合同唯一ID（主键） | 自增或雪花ID，支持分布式系统 |
| contract_no | varchar(50) | 合同编号（业务唯一，如“HT202310001”） | 支持自定义编号规则（前缀+日期+序号） |
| subject | varchar(200) | 合同标的（如“1000吨螺纹钢采购”） | 通用文本，适配各类标的 |
| buyer_id | bigint | 买方ID（关联客户表） | 外键关联，支持多主体 |
| seller_id | bigint | 卖方ID（关联供应商表） | 外键关联，支持多主体 |
| total_amount | decimal(20,2) | 合同总金额 | 保留两位小数，支持大额交易 |
| currency | varchar(3) | 币种（如“CNY”“USD”） | 枚举值，可动态扩展新币种 |
| status | tinyint | 合同状态（0-草稿，1-生效，2-终止，3-归档） | 状态枚举可扩展，适配全生命周期 |
| sign_date | date | 签订日期 |  |
| start_date | date | 生效日期 |  |
| end_date | date | 到期日期 |  |
| payment_rule_type | varchar(20) | 付款规则类型（如“预付款+尾款”“信用证”“账期”） | 预留扩展，支持新增规则类型 |
| delivery_rule_type | varchar(20) | 履约（交付）规则类型（如“一次性交付”“分批交付”“按需提货”） | 预留扩展，支持新增交付类型 |
| remark | text | 备注 | 长文本，存储非结构化说明 |
| create_time | datetime | 创建时间 |  |
| update_time | datetime | 更新时间 |  |

**灵活性亮点**：

+ 用`payment_rule_type`和`delivery_rule_type`标记规则类型，而非硬编码具体规则，后续新增规则（如“仓单质押+分期付款”）无需改表结构；
+ 买方/卖方用ID关联外部主体表，支持企业、个人等多类型主体。

### **2. 合同条款配置表（contract_term）**
存储合同中与履约、支付相关的关键条款（动态规则），避免主表字段膨胀，支持灵活配置。

| 字段名 | 类型 | 说明 | 灵活性设计 |
| --- | --- | --- | --- |
| term_id | bigint | 条款ID（主键） |  |
| contract_id | bigint | 关联合同ID（外键） | 一对一或一对多（多个条款） |
| term_type | varchar(20) | 条款类型（如“payment”付款条款，“delivery”交付条款，“penalty”违约条款） | 按类型区分，支持新增条款类型 |
| rule_key | varchar(50) | 规则键（如“prepayment_ratio”预付款比例，“installment_count”分期次数） | 动态定义规则维度 |
| rule_value | varchar(100) | 规则值（如“30%”“3次”“月结30天”） | 文本存储，适配数值、文本、日期等类型 |
| rule_desc | varchar(200) | 规则描述（如“预付款比例30%，发货前支付”） | 便于业务理解 |
| sort | int | 排序号（条款展示顺序） |  |

**灵活性亮点**：

+ 采用“键值对”存储条款，支持任意维度的规则配置（如“预付款比例”“每批交付量”“逾期违约金比例”），新增规则只需增加`rule_key`，无需改表；
+ 一个合同可对应多个条款（如同时配置预付款比例、尾款支付条件、交付批次），满足复杂场景。

### **3. 履约记录表（fulfillment）**
记录合同履约的关键节点（如交付、验收），支持分批履约，与合同条款联动。

| 字段名 | 类型 | 说明 | 灵活性设计 |
| --- | --- | --- | --- |
| fulfillment_id | bigint | 履约记录ID（主键） |  |
| contract_id | bigint | 关联合同ID（外键） |  |
| fulfillment_no | varchar(50) | 履约单号（如“FUL202310001-01”，带批次号） | 支持分批履约，批次号区分 |
| fulfillment_type | varchar(20) | 履约类型（如“delivery”发货，“acceptance”验收，“return”退货） | 支持正向/反向履约，可扩展类型 |
| related_batch | varchar(50) | 关联批次（如“第1批”“2023年Q4”，对应分批交付场景） | 灵活标记批次，适配不同分批规则 |
| quantity | decimal(20,3) | 履约数量（如“200吨”“500件”） | 保留三位小数，支持小数单位（如原油“桶”） |
| unit | varchar(20) | 单位（如“吨”“件”“桶”） | 自由定义，适配各类商品 |
| status | tinyint | 履约状态（0-待执行，1-进行中，2-完成，3-失败，4-取消） | 状态可扩展，覆盖全履约周期 |
| start_time | datetime | 履约开始时间 |  |
| complete_time | datetime | 履约完成时间 |  |
| fulfillment_remark | text | 履约备注（如“验收合格，品位65%”“部分破损，已协商扣款”） | 存储具体履约细节 |
| attachment_ids | varchar(500) | 关联凭证ID（如发货单、验收报告，逗号分隔） | 关联附件表，支持多凭证 |
| create_time | datetime | 创建时间 |  |
| update_time | datetime | 更新时间 |  |

**灵活性亮点**：

+ `fulfillment_type`支持多种履约动作（发货、验收、退货等），适配正向履约与异常处理；
+ 用`related_batch`标记批次，无需预设批次数量，支持“按需提货”等灵活分批场景；
+ 数量与单位分离，适配不同商品（如钢材“吨”、化工品“立方米”）。

### **4. 支付记录表（payment）**
记录合同相关的支付/收款记录，支持多笔支付，与履约节点关联。

| 字段名 | 类型 | 说明 | 灵活性设计 |
| --- | --- | --- | --- |
| payment_id | bigint | 支付记录ID（主键） |  |
| contract_id | bigint | 关联合同ID（外键） |  |
| payment_no | varchar(50) | 支付单号（如“PAY202310001-01”） | 支持多笔支付，单号唯一 |
| payment_type | varchar(20) | 支付类型（如“prepayment”预付款，“installment”分期付款，“balance”尾款） | 支持任意支付阶段，可扩展 |
| amount | decimal(20,2) | 支付金额 |  |
| currency | varchar(3) | 币种（与合同一致或单独配置，如跨境支付） | 支持与合同不同币种（需汇率转换） |
| payer_id | bigint | 付款方ID（关联主体表） | 可与买方不一致（如第三方代付） |
| payee_id | bigint | 收款方ID（关联主体表） | 可与卖方不一致（如第三方代收） |
| payment_method | varchar(20) | 支付方式（如“bank_transfer”银行转账，“L/C”信用证，“check”支票） | 支持各类支付工具，可扩展 |
| status | tinyint | 支付状态（0-待支付，1-已支付，2-部分支付，3-退款，4-失败） | 覆盖支付全状态，支持部分支付 |
| pay_time | datetime | 实际支付时间 |  |
| related_fulfillment_id | bigint | 关联履约ID（如“发货后付款”关联对应发货记录，可为null） | 支持“无关联履约”的支付（如预付款） |
| receipt_no | varchar(100) | 支付凭证号（如银行流水号、信用证编号） |  |
| payment_remark | text | 支付备注（如“对应第1批货物验收合格”） |  |
| create_time | datetime | 创建时间 |  |
| update_time | datetime | 更新时间 |  |

**灵活性亮点**：

+ `payment_type`支持任意支付阶段，无需预设分期数，适配“一次付款分批履约”“多次付款一次履约”等场景；
+ `related_fulfillment_id`可空，支持“预付款（无前置履约）”“发货后付款（关联发货记录）”等不同关联关系；
+ 付款方/收款方可与合同买方/卖方不一致，支持代付、代收场景。

### **5. 辅助表（按需设计）**
+ **附件表（attachment）**：存储履约/支付相关的凭证（如发货单、银行回单），用`attachment_ids`关联到履约/支付表。
+ **合同变更记录表（contract_change）**：记录合同条款、金额等变更历史，关联合同ID，支持回溯。

## **二、表关系设计**
+ **合同主表（contract）** ←1:N→ **合同条款配置表（contract_term）**：一个合同可有多条条款（如付款+交付+违约条款）。
+ **合同主表（contract）** ←1:N→ **履约记录表（fulfillment）**：一个合同可有多笔履约记录（如分批交付）。
+ **合同主表（contract）** ←1:N→ **支付记录表（payment）**：一个合同可有多笔支付记录（如预付款+尾款）。
+ **履约记录表（fulfillment）** ←0:1→ **支付记录表（payment）**：一笔履约可关联一笔支付（如“发货后付款”），也可无关联（如预付款对应的履约尚未发生）。

## **三、灵活性保障要点**
1. **避免硬编码规则**：用“类型字段+键值对配置”替代固定字段（如用`payment_rule_type`+`contract_term`存储付款规则，而非在合同表加`prepayment_ratio`字段），新增规则无需改表。
2. **支持多对多关联**：履约与支付可灵活关联（1:N、N:1、0:N），适配“一次支付对应多批履约”“一批履约对应多笔支付”等场景。
3. **状态与类型可扩展**：所有状态（如合同状态、支付状态）和类型（如履约类型、支付类型）均用枚举或文本存储，新增值只需更新业务代码，无需改表结构。
4. **冗余字段预留**：核心表可预留1-2个`ext_json`字段（JSON类型），存储突发的个性化需求（如特殊行业的专属规则），避免频繁改表。

## **四、示例场景适配验证**
1. **场景1：一次付款，分批履约**
    - 合同表：`payment_rule_type`=“full_prepayment”，`delivery_rule_type`=“batch_delivery”。
    - 条款表：记录“总支付金额500万，分3批交付（每批200吨）”。
    - 支付表：1条支付记录（金额500万，`payment_type`=“full_prepayment”）。
    - 履约表：3条履约记录（`related_batch`=“第1/2/3批”，关联同一合同ID）。
2. **场景2：分阶段付款（预付款+验收后付款）**
    - 合同表：`payment_rule_type`=“stage_payment”。
    - 条款表：记录“预付款30%（发货前付），尾款70%（验收后付）”。
    - 支付表：2条支付记录（`payment_type`分别为“prepayment”“balance”）。
    - 履约表：1条发货记录+1条验收记录，验收记录关联尾款支付记录。

通过以上设计，表结构既能覆盖常规场景，又能灵活适配复杂规则变更，同时保持数据关联清晰，为后续业务扩展提供支撑。
