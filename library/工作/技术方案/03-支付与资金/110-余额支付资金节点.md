# 余额支付资金节点

在B2B大宗商品或供应链业务中，这四个资金节点的设置直接关系到**平台的风控能力**和**交易双方的资金周转效率**。

基于行业最佳实践，结合你之前的“线上/线下交收”和“仓单/线下配货”场景，我为你梳理了标准的处理逻辑：

---

## 1. 卖方什么时候收到货款（结算节点）
这取决于合同约定的**“结算模式”**。在系统中，通常有以下三种主流配置：

+ **模式A：极速回款（先款后货/发货即结算）**
    - **触发点：** 卖方点击“确认发货” 或 仓单系统完成“冻结/出库”时。
    - **适用场景：** 卖方强势，或平台对货物有绝对控制权（如仓单质押模式）。
    - **风险：** 买方收到货后发现质量问题，钱已经在卖方口袋里了，平台很难追回。
+ **模式B：担保交易（货到结算）—— **_**推荐标准模式**_
    - **触发点：** 买方点击“确认收货” 或 物流系统回传“已签收” 或 仓单完成“过户”时。
    - **逻辑：** 资金在平台/银行监管户停留，待物权转移完成后，系统触发分账指令给卖方。
    - **优势：** 平衡买卖双方权益。
+ **模式C：票到结算（账期/尾款模式）**
    - **触发点：** 买方收到增值税发票并验真通过后。
    - **逻辑：** 往往用于支付合同的“尾款”（如10%-20%）。货款的大头在收货时结清，剩余部分等票据。

---

## 2. 什么时候释放卖方保证金
卖方缴纳保证金主要是为了防范：**虚假发货、货物质量问题、不开发票**。释放节点通常是分阶段的：

+ **节点1：买方收货时（释放部分）**
    - 如果交易顺利完成，没有质量异议，可以释放 **50%-80%** 的保证金。
    - _理由：_ 只要货到了，最大的违约风险（不发货）已经解除。
+ **节点2：买方收票时（释放剩余/全部）—— **_**核心风控点**_
    - B2B交易中，发票（专票）至关重要。
    - **触发点：** 卖方上传发票信息 -> 买方/平台验证无误。
    - **操作：** 释放剩余保证金。如果卖方拖延开票，平台可直接从保证金中扣除税点赔付给买方。
+ **节点3：质保期结束后**
    - 对于某些工业品，可能要求在收货后30天（质保期）无质量问题才释放。

---

## 3. 什么时候支付买卖双方手续费
手续费（佣金）的收取通常采用**“截流”**和**“预扣”**两种方式。

+ **卖方手续费：在“给卖方打钱”的那一刻扣除（截流）。**
    - **场景：** 订单金额100万，费率1‰（1000元）。
    - **时机：** 当触发“卖方收到货款”节点时。
    - **资金流：** 监管户支出100万 -> 99.9万进卖方账户，1000元进平台收益账户。
    - _银行类实现：_ 使用银行的“分账”或“多方分润”接口。
+ **买方手续费：在“买方付款”或“合同生效”时收取。**
    - **方式一（推荐）：** 包含在货款中。买方付100.1万，其中0.1万是手续费。
    - **方式二：** 从买方保证金中扣除。合同生效时，直接扣除买方保证金账户中的相应金额。

---

## 4. 买方保证金（履约金）如何处理
买方保证金的核心作用是**“锁定库存”**和**“违约赔付”**。它的生命周期处理最复杂，主要有两种路径：

### 路径A：履约金转货款（抵扣模式）—— _资金利用率最高_
这是你之前关心的模式，最受买方欢迎。

1. **冻结：** 合同签订，冻结买方20%资金。
2. **支付尾款：** 买方支付剩余80%资金进入监管户。
3. **交收瞬间：**
    - 系统将20%保证金状态改为“待结算货款”。
    - 系统将这20% + 80% 打包结算给卖方。
4. **结果：** 保证金消失，变成了货款流向卖方。

### 路径B：原路退回（独立模式）
适用于保证金和货款走不同账户，或者银行通道不支持复杂转账的场景。

1. **冻结：** 冻结买方20%。
2. **支付全款：** 买方必须支付100%全额货款（此时平台压了买方120%的钱）。
3. **收货完成：**
    - 平台将100%货款给卖方。
    - 平台将20%保证金**解冻/退回**给买方。
4. **缺点：** 占用买方资金量大，体验较差。

---

## 总结：一个完整的B2B资金流转剧本
假设：合同金额100万，买方保证金20万，卖方保证金10万，平台收卖方1000元手续费。

| 阶段 | 动作 | 资金变动 |
| :--- | :--- | :--- |
| **1. 签约** | 买卖双方确认合同 | **买方：** 支付/冻结20万（履约金）   **卖方：** 支付/冻结10万（履约金） |
| **2. 付款** | 买方支付尾款 | **买方：** 再支付80万进入监管户。   此时监管户共有：买方100万(20+80) + 卖方10万。 |
| **3. 发货** | 卖方发货/转让仓单 | 状态变更，资金不动。 |
| **4. 收货** | **买方确认收货** | **1. 结算货款：** 监管户将买方的100万进行分账 -> 99.9万给卖方，1000元给平台。   **2. 释放卖方保证金（部分）：** 解冻卖方5万保证金（剩5万等发票）。 |
| **5. 开票** | 卖方上传发票，买方验票 | **3. 释放卖方剩余保证金：** 解冻卖方剩余5万保证金。   **4. 流程结束：** 所有资金结清。 |
| **6. 违约** | 若买方中途不要货了 | 监管户将买方20万履约金 -> 划拨给卖方作为赔偿 -> 合同关闭。 |
