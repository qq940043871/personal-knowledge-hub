# 支付模型应该如何设计

在合同交收过程中涉及以下概念

合同交收节点：

交收申请；交收确认；付款；配货；收货；账单确认；开票；收票；

涉及资金：

买方履约金；卖方履约金；买方支付货款；卖方收到货款；释放买方履约金；释放卖方履约金；

买方手续费；卖方手续费；冻结卖方开票保证金；释放卖方开票保证金；

买方履约金冲抵买方货款；

支付方式：

余额类；银行授权类；线下支付类；

基于以上信息帮我设计一套灵活的支付模型；要求实现：

1. 银行的支付凭证需要显示买卖双方的真实信息
2. 卖方的开票保证金需要支持在收到货款后，在进行冻结（因为卖方没资金，就是单纯卖货）

:::color3
余额类支付：（采用卖方收到款后再冻结开票保证金的方式）

买方履约金，卖方履约金，买方支付货款，卖方收到货款，卖方释放履约金，冻结卖方开票保证金，释放卖方开票保证金

:::

:::color3
网银授权类：（采用买方支付货款时，分俩笔支付搞定（1部分货款，1部分尾款））

买方履约金，卖方履约金，买方支付货款，卖方收到货款，卖方释放履约金，买方支付最终尾款，卖方收到最终尾款

:::
