# 内容安全检测方案

好的，针对业务系统改造对接阿里云内容安全接口（主要用于文本、图片、视频的内容安全检测），这里是一个详细的改造方案规划和关键点说明：

**核心目标：** 无缝集成阿里云内容安全能力（如 `Green` 或 `Content Moderation` 服务），对用户产生的文本、图片、视频内容进行实时或准实时审核，拦截、标记或处置违规内容，确保业务合规性，规避法律风险，保护用户权益。

**改造核心思路：**

1. **识别风险接入点：** 定位用户内容产生的关键业务节点（发布、上传、修改、评论、私信等）。
2. **选择接入模式：** 根据业务场景、实时性要求、成本敏感度选择最佳调用方式（同步 vs 异步队列 vs 批量任务）。
3. **设计拦截/处置策略：** 根据检测结果定义清晰的处置流程（通过、拦截人工复核、打标限流）。
4. **构建解耦/可扩展架构：** 将审核能力抽象为服务，便于维护、扩展和升级。
5. **保障系统稳定与数据安全：** 处理异常、超时、流控，保护用户传输数据。

## 详细改造方案
### 一. 系统分析 & 准备阶段
1. **深度梳理业务流程：**
    - 明确哪些功能模块会产生待检测内容：
        * **发布类：** 文章、帖子、商品描述、评论/回复、弹幕、直播标题/封面/回放文件、问题/回答、用户昵称/签名/头像。
        * **上传类：** 图片上传（头像、相册、产品图）、视频上传（短视频、长视频、直播回放上传）。
        * **聊天类：** 私信、群消息、客服聊天记录（视合规要求）。
    - 确定内容检测的**触发时机**：是创建时立即检测？还是编辑时也检测？状态变更（如公开 -> 私密）是否需要复核？
    - 识别当前系统对内容的**存储/处理方式**（DB、文件存储、CDN地址）。
2. **定义风险等级与处置策略：**
    - **与阿里云结果映射：**
        * `pass` (合规)：放行，展示。
        * `review` (可疑/需人工复核)：进入待审状态（隐藏、限流展示给少部分人、标黄等），通知审核人员。
        * `block` (违规)：拒绝发布/上传、删除现有内容、通知用户/管理员。
    - **细化策略（非常重要）：**
        * 根据 `Suggestion` 结合具体的 `Label` 和 `Score` 设定更细的分数阈值（如：涉黄 > 90分直接拦，60-90分待审，<60分可能放行但有标签）。
        * 不同场景不同处置：普通评论 vs 直播间封面图的处理严格程度不同。
        * 二次复核：对`block`的内容可由审核人员再次确认后执行最终操作。
3. **选择阿里云服务与接口：**
    - **核心服务：** `Green`（绿网）是阿里云主要的内容安全产品。
    - **关键接口：**
        * **文本审核 (**`Text Scan`**):**
            + 同步调用：高实时性要求场景（评论、聊天）。
            + 异步检测 (`AsyncScanResults`): 长文本、可接受的延迟场景。
            + **参数要点：** 设置`Scenes`（场景，如 `antispam`垃圾文本, `porn` 色情）, `Content` (文本内容或经过安全`URL`如OSS文件，建议直接传内容避免URL泄露)，考虑`Labels`过滤（如只检测色情和广告）。
        * **图片审核 (**`Image Scan`**):**
            + 支持同步/异步。
            + **参数要点：** `Scenes` (`porn`色情, `terrorism`暴恐涉政, `ad`违规广告, `live`不良画面等)，`DataId`(业务标识)，`Url` (图片公网可访问URL - **首选，无需修改业务系统存储**)，`Content` (Base64编码，用于小图片直接传)。
            + **核心：业务系统图片存储后，生成临时可访问URL**（如OSS签发临时访问URL）再传给阿里云。
        * **视频审核 (**`Video Scan`** - 通常是异步):**
            + 涉及音画两部分，检测耗时长。
            + **参数要点：**
                - `Tasks`: 任务数组。
                - 任务参数：`DataId`, `Url` (视频文件的公网可访问URL - **首要选择**), `Scenes` (`porn`色情, `terrorism`暴恐涉政, `live`不良画面, `logo`台标水印等)。
                - `Callback`: (必须) 设置回调地址接收结果 - **系统改造关键点**。
                - `Audio Scenes` (可选)：如果不检测音频内容可不设。
            + **策略：** 提交检测 -> 立即或短暂延迟后返回“检测中” -> 业务系统标记内容为“审核中”状态（隐藏或限流）-> 等待阿里云回调告知结果 (可能几分钟到几十分钟) -> 根据回调结果更新内容状态（放行、屏蔽）。
        * **短视频片段检测 (可选)：** `Video Synchronous Scan`或`Image Scan`轮询抽帧结果代替，实时性要求极高的场景。
4. **评估成本与QPS：**
    - 阿里云按量计费（文本条数、图片张数、视频时长）。
    - 预估业务峰值QPS，必要时购买预付费资源包降低成本。
    - 了解阿里云接口QPS限制和流控策略。

### 二. 系统架构与模块改造设计
1. **核心架构模式：**
    - **服务解耦：** 新建一个**独立的内容安全服务 (**`Content Security Service`**, **`CSS`**)**。业务系统只需调用该服务接口，将待审核内容及上下文传递给它，无需直接对接阿里云SDK细节。`CSS`负责封装阿里云调用逻辑、结果处理、策略执行、日志记录、错误处理等。
    - **优势：** 高内聚低耦合，方便升级、扩展（如未来换厂商或加多平台审核）、统一策略、易维护。
2. `Content Security Service`** (**`CSS`**) 设计：**
    - **关键模块/功能：**
        * **接入层 (**`API Gateway`**):** 接收来自各业务系统的审核请求。
        * **调度中心:**
            + 根据请求类型（文本/图片/视频）、业务场景、实时性要求决定调用模式（同步调用阿里云、提交异步任务、放入队列）。
            + 生成唯一 `DataId` (需关联到业务内容ID)。
            + 处理与阿里云API的交互（调用、处理响应、回调接收）。
        * **策略引擎：**
            + 加载并应用之前定义的**风险等级与处置策略**。
            + 分析阿里云原始结果 (`Labels`, `Suggestion`, `Score`)。
            + 输出最终的**处置指令 (**`PASS`**, **`REVIEW`**, **`BLOCK`**) 和标签信息**。
        * **异步处理器 (针对视频/可选文本/图片异步化)：**
            + **视频：** 接收阿里云回调 → 解析结果 → 调用策略引擎 → 更新原始视频对应的业务数据状态（通过`DataId`找到业务记录）。
                - 需要可靠的回调处理（幂等、确认接收）。
            + **队列消费 (可选)：** 使用消息队列（如RocketMQ/Kafka）处理高并发请求或异步任务，平滑削峰填谷。
        * **本地缓存:**
            + 缓存常变的阿里云配置（如AccessKey, 策略参数 - 需安全）。
            + 缓存结果（短时内相同内容可避免重复检测）。
        * **日志与监控：** 记录详细请求参数、结果、耗时、错误；对接监控告警。
    - **存储 (可选):** 审核记录表（关联`DataId`, 业务ID, 原始内容/特征，阿里云原始结果，最终处置状态，时间戳等）- 用于审计、溯源、策略优化。
3. **业务系统关键改造点：**
    - **识别接入点改造:**
        * **文本：**
            + 在用户点击“提交”后，业务服务调用`CSS.TextCheck(content, userInfo, context)`。
            + **同步模式：** 等待`CSS`返回处置指令（毫秒级）。`CSS`同步调用阿里云文本审核接口。
                - 指令`PASS`：正常流程。
                - 指令`BLOCK`：拦截，提示用户内容违规。
                - 指令`REVIEW`：存入DB但状态为“待审”（隐藏），通知用户可能需要审核，通知人工后台。
            + **异步模式 (长文本)：** 业务调用`CSS.SubmitTextJob(content, userInfo, context)`收到`DataId` -> 将内容连同`DataId`设为待审状态（隐藏）-> 等待`CSS`异步处理完毕回调业务API（或`CSS`主动拉结果触发业务更新）。
        * **图片：**
            + 用户选择/上传图片后。
            + **方式一(主流)：** 业务系统先将图片上传到自己的存储(如OSS) -> 生成**公网可访问的、有时效性(几分钟)**的临时URL（确保安全） -> 调用`CSS.ImageCheck(tempUrl, userInfo, context)`。
            + **方式二：** 对极小图片，获取图片Bytes转为Base64 -> 调用`CSS.ImageCheck(base64Content, ...)`（不推荐，浪费带宽）。
            + **结果处理：** 类似文本同步或异步。
        * **视频：**
            + 视频上传成功 (保存到文件存储服务如OSS/MinIO) -> 业务服务生成视频**公网可访问的、有时效性(如1小时)**的临时URL -> 调用`CSS.SubmitVideoJob(videoUrl, callbackUrl='CSS回调地址', userInfo, context)`。
            + `CSS`接收到请求后，向阿里云提交异步视频审核任务(_必须带上阿里云的回调地址_`callback`_为_`CSS`_内部地址_)。
            + 业务服务收到`CSS`的提交成功响应（通常附带一个`CSS`维护的任务ID/`DataId`）：
                - 将**业务视频对象状态标记为"审核中(**`reviewing`**)"**。
                - **展示层面：** 对“审核中”的视频应做处理（如显示“审核中”，不可播放/只可播放前几秒低风险预览）。
            + `CSS`收到阿里云的**回调通知**（含结果和`DataId`）。
            + `CSS`解析结果 -> 策略引擎分析 -> 调用业务系统的**通知API（如 **`biz/notify/videoReviewResult`**)** 或直接更新业务DB（取决于解耦程度），传递`DataId`和最终处置指令。
                - 业务系统根据指令更新视频状态：`APPROVED`(审核通过) / `FAILED`(违规禁止) -> 开放播放 / 移除并通知用户。或置为`MANUAL_REVIEW`(可疑触发人工审核)。
    - **状态机改造：** 为内容实体（评论、帖子、图片、视频）增加审核状态字段（如：`pending`待审，`reviewing`检测中(视频异步)，`approved`通过，`rejected`拒绝，`manual_review`待人工复核）。
    - **后台管理改造：**
        * 增加**人工审核后台**，供运营人员查看被 `css` 打上 `REVIEW` 标识的内容，做出最终裁决。
        * 展示阿里云检测结果标签和分数作为参考。
    - **用户交互改造：**
        * 提交后如果长时间审核中，友好提示。
        * 内容被拒绝，清晰告知（可带拒绝原因大类）。
        * 提供申诉入口。

### 三. 关键技术选型与实施难点
1. **消息队列 (可选但推荐)：** 在业务高峰或检测服务有波动时，使用RocketMQ/Kafka削峰。业务提交给队列 -> `CSS`消费队列进行检测 -> 结果存回队列/回调业务。
2. **API回调处理：**
    - **视频核心：** `CSS`为阿里云提供**内部稳定的回调地址（API）**。必须确保此接口安全（HTTPS, IP白名单/签名验证）、幂等（防止阿里云重复通知）、可靠（重试机制）。
    - **调用业务通知接口：** `CSS`回调业务接口通知结果时，也要考虑幂等和失败重试。
3. **安全控制 (关键!)：**
    - **AccessKey严格管理：** 在`CSS`中使用阿里云AccessKey，**禁止明文存储**。使用KMS/Secrets Manager或云平台的RAM角色。
    - **传输安全：** 所有调用（业务->`CSS`, `CSS`->阿里云）强制使用HTTPS。
    - **临时URL安全：**
        * 用于图片、视频检测的临时URL必须设置超短的有效期（如 **1-5分钟**）。
        * **OSS建议：** 使用`SignUrl`，参数中指定超短`Expires`时间。
        * **确保URL不能被未授权访问：** URL本身应是临时有效的令牌（Token），而非公开URL。
    - **避免内容泄露：** 避免将业务敏感内容明文写入日志。
4. **性能与稳定性：**
    - **超时设置：** 业务系统调用`CSS`超时、`CSS`调用阿里云超时（尤其视频、长文本异步）、阿里云回调超时。合理设置（文本几秒内，视频可设长为几分钟提交成功即可）。
    - **限流与重试：**
        * `CSS`应对业务系统调用进行限流（防止业务系统异常爆发）。
        * `CSS`应对调用阿里云API进行限流（遵守阿里云QPS限制），做好熔断降级（当大量失败时，短期内部分放行或转入待审队列，记录告警）。阿里云限制通常是动态令牌桶。
        * **重试策略：** 对网络抖动或阿里云短暂失败，`CSS`应实现带有退避时间（如指数退避）的重试机制（尤其视频提交任务）。
    - **异常处理：**
        * `CSS`调阿里云失败（网络/权限问题/流控）：记录详细日志告警，根据业务场景采取不同策略（直接放行？标记待审？阻塞？需结合策略）。
        * 阿里云回调失败/超时：阿里云会重试（通常2-3次，有间隔）。`CSS`要确保回调接口高度可用并处理幂等。
        * 业务系统调用`CSS`失败：业务系统要考虑重试逻辑或降级策略（暂时不检测？标记为待审）。
    - **监控告警：**
        * 成功率/错误率/耗时：业务 -> `CSS`， `CSS` -> 阿里云。
        * 异步队列堆积情况。
        * 人工审核队列积压情况。
        * “审核中”状态超时内容告警。
        * 费用支出监控。
5. **策略可配置化：** 设计`CSS`策略引擎时，应支持配置加载（如从DB读取策略阈值和映射规则），无需重新部署即可调整审核严格度。
6. **测试方案:**
    - 阿里云官方提供的**测试内容库**（用于过白名单测试）和**违规测试库**（包含各类违规范例）。
    - 搭建**沙盒环境**，全面测试各种内容的提交、调用、结果映射、处置流程以及异常、网络中断场景。
    - **压力测试：** `CSS`及队列系统的承载能力。

### 四. 上线与后续优化
1. **灰度发布：**
    - 先在小范围用户/业务线开通审核。
    - 逐步放大流量，监控系统状态。
    - **重要：** 新功能上线，建议初期“审核中”状态内容**只展示给发布者
