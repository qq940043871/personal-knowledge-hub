# 合同中心交收模型和支付模型设计文档
## 一、交收模型设计
1. **交收类型**
    - 线上交收：适用于通过平台完成交易确认的场景，如大宗商品、批量采购等。
    - 线下交收：适用于买卖双方直接线下对接货物的场景，如本地小额交易、定制化商品等。
2. **配货类型**
    - 仓单配货：适用于有固定仓库的商品，如大宗商品、批量采购。
    - 线下配货：适用于卖方无固定仓库的商品，如零售订单。
3. **提货类型**
    - 自提：买方到指定仓库凭仓单提取货物。
    - 配送：仓库根据指令将货物配送至买方指定地点。
    - 转入库：货物从当前仓库转入买方指定的其他仓库。
4. **交收路径状态图**
    - 线下交收 → 流程结束
    - 线上交收 → 线下配货 → 流程结束
    - 线上交收 → 仓单配货 → 自提 → 进入“自提流程”
    - 线上交收 → 仓单配货 → 配送 → 进入“配货流程”
    - 线上交收 → 仓单配货 → 转入库 → 进入“转入库流程”
5. **交收流程的适用场景**
    - 线下交收：适用于买卖双方线下直接对接货物的场景，如本地小额交易、定制化商品。
    - 线上交收 + 线下配货：适用于线上确认交易，线下卖方直接向买方配货的场景，如卖方无固定仓库。
    - 线上交收 + 仓单配货 + 自提：适用于买方到指定仓库凭仓单提取货物的场景，如大宗商品、批量采购。
    - 线上交收 + 仓单配货 + 配送：适用于仓库根据指令将货物配送至买方指定地点的场景，如异地采购、零售订单。
    - 线上交收 + 仓单配货 + 转入库：适用于货物从当前仓库转入买方指定的其他仓库的场景，如库存调拨、跨仓管理。

## 二、支付模型设计
1. **支付方式**
    - 余额类：平台内部账户，可以实现所有卖方收款节点和卖方保证金释放节点。
    - 银行类：需通过技术适配实现所有流程，如预授权/担保支付/子账户体系。
    - 线下类：仅能记录状态，无法自动化。
2. **卖方收款节点**
    - 买方付款时：适用于预付款或担保交易，卖方提前收款，买方风险较高。
    - 买方收货时：适用于货到付款或验货后付款，卖方后收款，买方风险较低。
    - 卖方收款时：可能为技术口径，建议明确为平台放款指令触发时。
3. **卖方保证金释放节点**
    - 买方收货时：适用于“收货付款”模式，逻辑自洽。
    - 卖方收款时：通用兜底，适用于“付款即收款”模式。
    - 买方收票时：适用于需开票闭环的场景，如大宗商品、B2B交易。
4. **履约保证金 → 货款的实现机制**
    - 推荐采用“平台中间账户 + 账务指令”模式，履约金冻结在平台保证金子账户，成交后将部分冻结资金转为“应收货款”，再联动银行发起货款实付。
    - 银行只需执行“付款”，资金来源混合逻辑由平台账务系统封装。

## 三、合同交收设计建议
1. **合同模板配置化**
    - `delivery_type`：线上/线下
    - `allocation_type`：仓单/线下
    - `pickup_type`：自提/配送/转入库（仅当仓单配货时必填）
    - `payment_method`：余额/银行/线下
    - `seller_settle_at`：付款时/收货时
    - `margin_release_at`：收货时/收款时/收票时
    - `allow_margin_to_payment`：是否允许履约金转货款
