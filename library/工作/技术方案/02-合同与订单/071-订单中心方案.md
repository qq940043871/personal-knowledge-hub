# 高并发B2B订单中心架构落地方案
## 一、方案概述
### 1.1 方案背景
适配B2B电商多业务场景、多支付方式、合同履约联动、多级审批、高并发访问需求，解决订单与合同/支付/履约耦合、并发性能不足、数据不一致、运维复杂、信创合规等问题，实现**高并发、高可用、高一致、易扩展、全信创兼容**的订单体系。

### 1.2 核心目标
+ 高并发：支撑万级TPS订单并发，峰值流量无卡顿、无雪崩
+ 高可用：系统可用性99.99%，故障自愈、无单点、支持弹性扩容
+ 数据一致：订单-支付-库存-合同-履约数据强最终一致，无超卖、无脏数据
+ 灵活适配：支持多业务场景、多支付方式、自定义审批/履约流程
+ 信创合规：全栈适配国产软硬件，满足等保三级、信创验收要求

### 1.3 适用场景
B2B集采、现货采购、合同履约、招投标、分批发货、多方式支付、多级审批等复杂订单场景。

## 二、整体架构设计
### 2.1 架构分层（云原生微服务架构）
```plain
接入层 → 网关层 → 业务服务层 → 数据层 → 基础设施层
```

1. **接入层**：CDN、静态资源加速、WAF防护
2. **网关层**：API网关、限流、熔断、鉴权、路由、灰度发布
3. **业务服务层**：订单核心服务、合同服务、履约服务、支付服务、库存服务、审批服务、用户中心
4. **数据层**：分布式数据库、分布式缓存、消息队列、搜索引擎、数据仓库
5. **基础设施层**：容器编排、服务治理、监控告警、日志审计、信创底层软硬件

### 2.2 核心服务拆分（解耦核心）
1. **订单核心服务**：订单创建、查询、状态管理、订单快照、分库分表
2. **合同服务**：合同模板、电子签章、PDF生成、合同-订单关联、契约管控
3. **履约服务**：发货、收货、验收、对账、变更、售后、流程引擎
4. **支付中心服务**：统一支付入口、多支付方式适配、对账、退款、资金结算
5. **库存服务**：库存扣减、预占、释放、库存同步、防超卖
6. **审批服务**：多级审批、流程配置、审批流转、权限管控
7. **公共服务**：用户中心、消息中心、日志中心、缓存一致性服务

### 2.3 高并发核心保障机制
+ 异步削峰：核心流程异步化，消息队列解耦
+ 读写分离：订单读请求走缓存/从库，写请求走主库
+ 分库分表：水平分片分散数据库压力
+ 缓存兜底：分布式缓存扛90%读流量，无本地缓存
+ 限流熔断：峰值流量限流，故障自动熔断降级
+ 幂等设计：杜绝重复下单、重复支付、重复扣减

## 四、核心模块详细设计
### 4.1 订单核心模块
#### 4.1.1 数据模型（分库分表）
+ **分库分表规则**：按企业ID/订单ID哈希分片，订单主表+订单明细表+订单快照表
+ **订单主表**：订单ID、企业ID、合同ID、订单金额、订单状态、支付状态、审批状态、创建时间
+ **订单明细表**：商品信息、数量、单价、税率、金额、库存预占ID
+ **订单快照表**：下单时商品、合同、用户全量快照，防止数据变更

#### 4.1.2 核心接口
+ 订单创建（幂等）、订单查询、订单取消、订单关闭、订单状态同步
+ 高并发优化：接口限流、参数校验、异步落库、缓存预热

### 4.2 合同-订单联动模块
1. 合同审核通过后，自动生成/关联订单
2. 订单履约进度回写合同，同步合同履约状态
3. 订单变更联动合同变更，保留变更日志
4. 手动刷数/合同修正，通过CDC自动更新订单缓存

### 4.3 支付模块（统一收口）
1. 统一支付入口，适配对公转账、账期、预付款、银企直联、在线支付
2. 订单创建→生成支付单→支付回调→订单支付状态同步
3. 支付失败自动重试、超时自动释放库存
4. 支付数据异步对账，确保资金-订单一致

### 4.4 履约模块（流程配置化）
1. 基于流程引擎，配置不同业务履约流程
2. 支持分批发货、部分收货、多级验收、对账结算
3. 履约状态实时同步订单，驱动订单生命周期
4. 履约异常自动告警，支持人工干预

### 4.5 库存防超卖模块
1. 下单时库存预占，支付成功后扣减，支付失败释放
2. 分布式锁+数据库乐观锁双重保障
3. 库存数据缓存化，定期同步数据库

### 4.6 缓存一致性模块
1. 仅使用**Redis分布式缓存**，无本地缓存
2. 订单写操作：更新高斯DB→通过消息队列通知缓存服务删除缓存
3. 手动刷数/数据库修复：高斯DB CDC监听→按缓存规则配置表自动删除缓存
4. 所有缓存设置30s-5min过期，兜底保障

## 五、高并发核心流程（落地步骤）
### 5.1 订单创建流程（高并发核心）
1. 前端请求→网关鉴权限流→参数校验→幂等校验（防重复提交）
2. 校验合同有效性、用户权限、商品库存
3. 预占库存（分布式锁）、生成订单号
4. 异步落库（主库）、生成订单快照
5. 返回下单成功→同步创建支付单
6. MQ异步通知合同、履约、消息模块

### 5.2 订单支付流程
1. 调用统一支付接口→选择支付方式→发起支付
2. 支付渠道回调→校验支付结果→更新订单支付状态
3. 扣减实际库存→发送履约通知→更新合同状态
4. 异步删除订单缓存，同步数据

### 5.3 订单履约流程
1. 履约服务接收通知→执行履约流程（发货/验收）
2. 履约节点完成→回写订单履约状态
3. 全部履约完成→更新订单为完成状态
4. 异步触发对账、开票流程

## 六、高可用&容错设计
### 6.1 限流熔断
+ 网关层：接口限流、IP限流、企业维度限流
+ 服务层：Sentinel配置熔断策略，故障降级返回友好提示
+ 数据库：连接池限流、慢SQL管控

### 6.2 故障自愈
+ 服务无状态化，K8s自动扩缩容、故障重启
+ 数据库主从切换，高斯DB自动故障转移
+ 消息队列异步重试，死信队列处理异常消息

### 6.3 数据容错
+ 订单操作全链路日志，支持问题回溯
+ 分布式事务保证核心数据一致
+ 定期数据对账，自动修复不一致数据
+ 数据定时备份，支持灾备恢复

## 七、信创&安全合规设计
### 7.1 信创适配
+ 全栈软硬件国产化替换，无国外依赖
+ 数据库、中间件、操作系统完成兼容适配
