# TOB电商系统平台化参数治理技术落地方案
## 一、方案总则
### 1.1 方案背景
当前系统为满足多客户个性化定制需求，采用**客户维度直接新增参数/开关**的实现方式，随着客户数量增长，引发一系列核心问题：

1. 系统参数泛滥，无统一管控，参数无归属、无约束、无权限隔离
2. 不同客户参数交叉组合，引发逻辑冲突、功能异常，出现组合爆炸
3. 代码充斥大量if-else嵌套，可读性、可维护性极差
4. 定制改动无隔离，单个客户问题波及全平台，系统稳定性大幅下降
5. 测试无法覆盖所有参数组合，线上问题频发，业务感知极差

本方案旨在**彻底根治参数乱象**，实现系统从项目制向平台制转型，保障系统稳定性、可扩展性，同时满足客户个性化需求。

### 1.2 核心目标
1. **参数统一管控**：所有参数归属化、标准化、可视化，杜绝随意新增
2. **客户逻辑隔离**：不同客户配置相互独立，无交叉污染
3. **系统稳定性保障**：核心业务逻辑无侵入，定制化能力可灰度、可降级、可回滚
4. **降低维护成本**：消除冗余if-else，简化业务逻辑，提升开发测试效率
5. **支撑规模化扩展**：支持批量接入新客户，无需改动核心代码
6. **信创兼容适配**：全方案适配国产数据库、中间件，符合信创要求

### 1.3 适用范围
本方案适用于系统内**所有业务配置参数、客户定制开关、个性化业务规则**，涵盖订单、合同、履约、支付、开票、消息通知等全业务模块。

## 二、整体技术架构
### 2.1 架构设计原则
+ **核心底座纯净**：平台核心流程、核心代码不掺杂客户定制逻辑
+ **能力原子化**：个性化功能封装为独立能力，参数绑定对应能力
+ **配置与代码分离**：所有定制化参数、规则通过配置实现，无硬编码
+ **客户权限收敛**：通过套餐分配能力，禁止直接给客户开放独立参数
+ **高可用兜底**：配置支持缓存、降级、回滚，不影响核心业务

### 2.2 分层架构设计
```plain
应用管理层 → 能力配置核心层 → 业务引擎层 → 数据持久层 → 缓存层
```

1. **应用管理层**：后台配置管理页面，实现能力、套餐、客户参数可视化配置
2. **能力配置核心层**：能力引擎、参数解析、规则匹配、客户权限校验
3. **业务引擎层**：订单、合同、履约、支付等核心业务服务，无定制化硬编码
4. **数据持久层**：高斯DB，存储能力、参数、套餐、客户配置数据
5. **缓存层**：国产Redis，缓存能力配置、客户参数，提升查询性能

### 2.3 核心数据模型
1. **能力模型**：原子化业务功能，是参数、逻辑、行为的最小载体
2. **参数模型**：参数归属唯一能力，带类型、默认值、可见性约束
3. **套餐模型**：多个能力的集合，作为客户授权的最小单元
4. **客户配置模型**：客户绑定套餐，可按需覆盖能力默认参数

## 三、核心模块技术设计
### 3.1 能力管理模块
#### 3.1.1 功能定义
对系统所有个性化业务功能进行原子化拆分、注册、管理，是参数管控的核心载体。

#### 3.1.2 核心属性
+ 能力编码：唯一标识，英文大写+下划线，不可重复
+ 能力名称：业务可读性名称
+ 归属模块：绑定订单/支付/合同/履约等业务模块
+ 状态：启用/禁用/灰度
+ 基础能力标识：平台必选基础能力，不可禁用

#### 3.1.3 核心接口
+ 能力注册/编辑/删除/启停
+ 能力关联参数管理
+ 客户能力权限校验

### 3.2 参数管理模块
#### 3.2.1 功能定义
统一管理系统所有配置参数，实现参数**强归属、强约束、可追溯**，禁止游离参数。

#### 3.2.2 核心规则
1. 所有参数必须归属唯一能力，无归属参数禁止创建
2. 参数约束：参数键、参数名称、参数类型（整型/字符串/布尔/JSON）、平台默认值
3. 权限控制：区分平台内部参数、客户可编辑参数
4. 取值优先级：客户个性化覆盖值 > 能力默认值 > 系统全局默认值

### 3.3 套餐管理模块
#### 3.3.1 功能定义
将多个能力打包为套餐，实现客户批量授权，杜绝单个参数开放导致的乱象。

#### 3.3.2 套餐分类
+ 基础套餐：所有客户必选，包含平台核心基础能力
+ 标准套餐：通用业务能力组合，适配大多数客户
+ 高级套餐：包含复杂定制化能力，适配中大型客户
+ 专属定制套餐：针对头部客户定制化能力包

#### 3.3.3 核心功能
+ 套餐创建/编辑/启停
+ 套餐绑定/解绑能力
+ 套餐生效/过期时间配置

### 3.4 客户授权模块
#### 3.4.1 功能定义
实现客户与套餐的绑定，完成客户能力权限分配，实现客户间配置隔离。

#### 3.4.2 核心规则
1. 单个客户可绑定1个或多个套餐
2. 客户仅可使用套餐内包含的能力及对应参数
3. 支持客户针对能力参数个性化覆盖，保留修改日志
4. 客户配置变更实时同步缓存，保证时效性

### 3.5 能力引擎模块
#### 3.5.1 功能定义
业务服务调用核心入口，封装能力校验、参数解析、规则匹配逻辑，消除业务代码if-else嵌套。

#### 3.5.2 核心接口
```java
// 校验客户是否拥有指定能力
boolean hasCapability(Long customerId, String capabilityCode);

// 获取指定参数值（带默认值兜底）<T> T getParam(Long customerId, String capabilityCode, String paramKey, T defaultValue);

// 获取客户所有可用能力列表
<String> getCustomerCapabilityList(Long customerId);
```

## 四、数据库表结构设计（高斯DB，可直接执行）
```sql
-- 1. 平台能力注册表：存储所有原子化业务能力
CREATE TABLE sys_capability
(
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    code        VARCHAR(64)  NOT NULL COMMENT '能力唯一编码',
    name        VARCHAR(128) NOT NULL COMMENT '能力名称',
    module      VARCHAR(64)  NOT NULL COMMENT '归属模块：ORDER/PAYMENT/CONTRACT/LOGISTICS',
    is_basic    TINYINT      NOT NULL DEFAULT 0 COMMENT '是否基础能力：1-是 0-否',
    status      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：1-启用 0-禁用 2-灰度',
    remark      VARCHAR(512) DEFAULT NULL COMMENT '能力说明',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_cap_code (code)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4 COMMENT ='平台能力注册表';

-- 2. 能力参数配置表：所有参数归属对应能力
CREATE TABLE sys_capability_param
(
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    capability_code VARCHAR(64)  NOT NULL COMMENT '关联能力编码',
    param_key       VARCHAR(64)  NOT NULL COMMENT '参数键',
    param_name      VARCHAR(128) NOT NULL COMMENT '参数名称',
    value_type      VARCHAR(32)  NOT NULL COMMENT '参数类型：INT/STRING/BOOL/JSON',
    default_value   VARCHAR(512) DEFAULT NULL COMMENT '平台默认值',
    is_customer_edit TINYINT     NOT NULL DEFAULT 0 COMMENT '客户是否可编辑：1-是 0-否',
    remark          VARCHAR(256) DEFAULT NULL COMMENT '参数说明',
    create_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_cap_param (capability_code, param_key)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4 COMMENT ='能力参数配置表';

-- 3. 套餐表：能力组合打包
CREATE TABLE sys_package
(
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    code        VARCHAR(64)  NOT NULL COMMENT '套餐编码',
    name        VARCHAR(128) NOT NULL COMMENT '套餐名称',
    type        TINYINT      NOT NULL COMMENT '套餐类型：1-基础 2-标准 3-高级 4-专属定制',
    status      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：1-启用 0-禁用',
    remark      VARCHAR(512) DEFAULT NULL COMMENT '套餐说明',

    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_package_code (code)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4 COMMENT ='套餐配置表';

-- 4. 套餐能力关联表
CREATE TABLE sys_package_capability
(
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    package_code    VARCHAR(64) NOT NULL COMMENT '套餐编码',
    capability_code VARCHAR(64) NOT NULL COMMENT '能力编码',
    create_time     DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_pkg_cap (package_code, capability_code)

  DEFAULT CHARSET = utf8mb4 COMMENT ='套餐能力关联表';

-- 5. 客户套餐关联表
CREATE TABLE customer_package_rel
(
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    customer_id     BIGINT   NOT NULL COMMENT '客户ID',
    package_code    VARCHAR(64) NOT NULL COMMENT '套餐编码',
    effect_time     DATETIME NOT NULL COMMENT '生效时间',
    expire_time     DATETIME NULL COMMENT '过期时间',
    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

-- 6. 客户参数个性化覆盖表

    param_key       VARCHAR(64)   NOT NULL COMMENT '参数键',
    param_value     VARCHAR(1024) NOT NULL COMMENT '客户自定义参数值',
    create_time     DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
```

## 五、核心业务流程
### 5.1 配置管理流程（运营/开发）
1. 新增个性化需求，先注册对应**能力**，而非直接新增参数
2. 为能力配置关联**参数**，设置默认值、编辑权限
3. 创建/更新**套餐**，将能力绑定至对应套餐
4. 给客户分配**套餐**，完成能力授权
5. 针对客户特殊需求，在套餐范围内，配置**个性化参数覆盖**

### 5.2 业务执行流程（运行时）
1. 业务接口请求，携带客户ID、业务场景信息
2. 调用能力引擎，校验客户是否拥有对应能力权限
3. 按优先级解析客户最终参数值
4. 业务服务基于参数执行逻辑，无if-else嵌套
5. 配置变更后，自动更新缓存，保证数据一致性

### 5.3 缓存同步流程
1. 能力、套餐、参数配置加载后，缓存至Redis，过期时间30分钟
2. 配置变更时，实时删除对应缓存，下次请求重新加载
3. 客户参数覆盖变更，同步刷新客户专属缓存
4. 缓存故障时，直接查询数据库兜底，保证业务可用

## 六、技术实施方案
### 6.1 实施阶段（分阶段落地，无业务中断）
#### 阶段一：底座搭建（1-2周）
1. 完成上述数据库表创建，初始化基础能力、基础套餐
2. 开发能力引擎核心接口、参数解析、缓存逻辑
3. 开发后台配置管理页面，实现能力、套餐、客户配置可视化管理

#### 阶段二：存量参数梳理迁移（2-3周）
1. 全面梳理系统现有所有参数、开关，归类对应能力
2. 编写数据迁移脚本，将存量客户配置迁移至新表结构
3. 保留旧配置作为兜底，兼容现有业务逻辑

#### 阶段三：代码重构优化（迭代执行）
1. 按业务模块，逐步替换if-else硬编码，改用能力引擎接口
2. 新需求开发，严格按照能力-参数-套餐流程实现，禁止直接新增客户参数
3. 逐步下线旧配置、旧代码，完成全量切换

#### 阶段四：测试验证与全量上线
1. 单元测试、集成测试，验证能力、参数、客户配置正确性
2. 灰度上线，先试点客户使用，无问题后全量推广
3. 线上监控，处理异常问题，完善兜底策略

### 6.2 兼容性处理
1. **信创兼容**：适配高斯DB、国产Redis、国产中间件，无国外技术依赖
2. **老业务兼容**：迁移过程保留旧配置兜底，逐步重构，不影响现有业务
3. **高并发兼容**：缓存支撑高并发查询，能力校验无性能损耗

### 6.3 高可用保障
1. **配置缓存兜底**：Redis集群部署，配置缓存支持持久化
2. **故障降级**：能力引擎故障时，默认使用平台基础能力、默认参数
3. **回滚机制**：配置变更支持一键回滚，避免配置错误引发线上问题
4. **日志监控**：全量记录配置变更、能力校验、参数解析日志，方便问题排查

## 七、风险防控
1. **迁移风险**：分模块迁移，灰度验证，保留回滚方案，避免数据丢失
2. **性能风险**：配置全量缓存，减少数据库查询，避免影响接口响应速度
3. **业务风险**：客户配置隔离，单个客户配置错误不影响其他客户
4. **迭代风险**：新需求严格遵循方案流程，杜绝回归旧开发模式

2. 客户定制化需求无需改动核心代码，通过配置实现
3. 业务代码无冗余if-else嵌套，逻辑清晰
4. 客户间配置完全隔离，无交叉影响
5. 线上因参数组合引发的问题下降90%以上
