# 统一商品

举一个比较简单的例子，那就是B to B挂牌模式情况下，我做销售挂牌。挂牌时候我选择了我的仓单，然后仓单里边是这个商品的仓单。但是是按照商品大类去维护的仓单，然后等到我摘牌成功以后，然后到合同中心需要办理交收，真正给客户配货时候选择仓单，又选择的是可能需要细化到这个品种。然后这个时候，因为嗯因为仓单系统的品种ID和业务模式的品种ID它并不一样，这就导致了你没办法精确匹配。只有通过这些一些人为的约束，什么商品名称一样才能搞定

我给你用**最简单、最直白、业务人员一听就懂**的方式，把你这个痛点讲透，顺便把问题根源和解决方案一次性说清楚。

## 一、你现在遇到的真实场景（完全还原）
1. 你在 **B2B挂牌系统** 做销售挂牌
2. 挂牌时，你选的是 **仓单**
3. 但仓单里的商品，是按 **商品大类** 维护的
4. 摘牌成功 → 进入 **合同中心/交收环节**
5. 真正配货时，又要求必须选到 **具体品种、细分规格**
6. 问题来了：
    - 仓单系统用的是 **一套品种ID**
    - 挂牌/合同用的是 **另一套品种ID**
    - 两套ID完全不互通、不关联
7. 结果：
**系统无法自动匹配，只能靠“商品名称一样”强行绑定。**

这就是典型的：
**主数据不统一 → 业务链路断裂 → 只能人肉兜底。**

---

## 二、我给你举个超简单的例子，一下就明白
假设：

### 仓单系统里的品种
+ 大类：**螺纹钢**
+ ID：`1001`

### 挂牌/合同系统里的品种
+ 细分品种：**螺纹钢 HRB400E Φ12**
+ ID：`5066`

你挂牌时选仓单，带过来的是：
`大类ID=1001`

到交收配货时，合同要的是：
`细分ID=5066`

系统一看：
**1001 ≠ 5066 → 不认识 → 无法自动匹配。**

最后只能：

> 名字都叫“螺纹钢”，那就当它是同一个吧。
>

这就是你说的：
**靠人为约束、名称一致才能勉强跑通。**

---

## 三、为什么会这样？（根源一句话）
因为你们 **商品/品种没有统一主数据**，
仓单、挂牌、合同各认各的编码，
没有建立 **大类 ****↔**** 细分品种** 的官方关联关系。

系统不是智能的，它只认ID，不认文字。

---

## 四、正确应该怎么设计？（最简单可落地版）
### 1. 建立统一的【品种主数据】
全局只有一套：

+ 一级分类：钢材
+ 二级分类：螺纹钢
+ 三级品种：螺纹钢 HRB400E Φ12
+ **全局唯一ID：SKU_ID**

### 2. 仓单不再只挂大类，而是挂到 **最终SKU**
仓单表结构变成：

+ 仓单号
+ 商品SKU_ID（统一ID）
+ 数量
+ 仓库

### 3. 挂牌时选择仓单 → 自动带出 **统一SKU**
挂牌单里存的也是：

+ SKU_ID（和仓单一致）

### 4. 摘牌生成合同 → 合同里也是同一个 SKU_ID
### 5. 交收配货时
系统直接根据：
**合同SKU_ID = 仓单SKU_ID**
自动筛选可配仓单，一键匹配。

---

## 五、这样一改，你现在的痛苦瞬间消失
1. 不再靠商品名称匹配
2. 不再人为约束
3. 仓单 ↔ 挂牌 ↔ 合同 ↔ 交收
**全程用同一套ID串联**
4. 风控也能真正跑通：
谁卖了什么、多少数量、对应哪张仓单、哪笔合同
全部可追踪、可计算、可风控

---

## 六、你可以直接在复盘里说的总结句
你现在这个问题，标准描述就是：

> 在挂牌交收业务链路中，由于仓单系统、挂牌业务、合同交收使用的商品品种ID体系不统一，仓单按大类维护、业务按细分品种管理，两者缺乏标准映射关系，导致系统无法自动精准匹配仓单与交收品种，只能通过商品名称一致这类人工约束实现关联，业务联动性弱、风险高、效率低。
