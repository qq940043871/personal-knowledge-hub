# 技术知识库排版规范（2026-11 重排版统一标准）

> 本规范适用于 `library/技术/` 下四卷全部文章：17年技术经验总结、飞书·人工智能、飞书·飞天闪客、从0到1设计计算机。
> 目标：标题层级清晰、段落结构分明、关键结论突出、必要处补示意图。
> 铁律：**内容零丢失**——原文的观点、数据、结论、代码、图片，一个都不能少。

## 一、排版规范

### 1.1 标题
- 每篇有且仅有一个 `# ` 一级标题，作为文章题目（用文件名去掉序号前缀后的题名，如 `041-Redis-如何避免单线程模型的阻塞.md` → `# Redis：如何避免单线程模型的阻塞`；标题语言风格与原文一致即可）。
- 正文按内容逻辑划分 `## ` 二级小节，小节多的可在二级下再加 `### `。
- 小节标题必须是**有信息量的短句**（如「线程池参数如何确定」），禁止用「第一部分」「内容」「代码」这类空标题；原文已有信息量标题的保留原样。
- 原文已有正确层级的，保留原层级，只做整洁化（统一空行、修正层级跳跃）。

### 1.2 段落与强调
- 大段口语转写稿/文字墙：拆成 2~5 句一段；删除纯语气词，但**句子主干照抄原文，不重写、不概括**；意思含糊处保留原样。
- 每个二级小节开头，如该节有明确结论，可用一行 `> ` 引用块点题（从原文原句中挑选或极轻度压缩，禁止编造）。
- 关键词、核心结论用 `**加粗**`；连续的要点（3 条及以上）改写成 `- ` 列表；步骤类内容可用有序列表。
- 原文的表格、代码块、图片引用**原样保留**——代码块（``` 围栏）内一个字符都不许动，只允许调整前后空行。
- 命令行/终端输出/配置示例原样保留，不得换行重排。

### 1.3 图片与死链处理
- `images/...` 本地图片引用：**路径和顺序逐字符照抄**，禁止改动（历史教训：改错一个字符图片就丢）。
- `![](https://feishu.cn/file/xxxx)` 这类飞书导出存根是**死链**（无 token 永不渲染）：**直接删除该行**，不留空壳。
- 其他域名（github、cnblogs 等正常外链图片）保留不动。
- 篇幅很短（<15 行）的记录型文章：只补 H1 标题和必要的段落空行，**不要**强行加小节、加图。

### 1.4 禁止事项
- 禁止删减任何观点、案例、数字、代码、命令、URL。
- 禁止添加原文没有的新观点、新数据（导读句只能从原文提炼）。
- 禁止改动文件名。
- 已含 `<svg` 的文章：保留现有 SVG 逐字符不动，只做文字排版；一般不再新增 SVG。

### 1.5 文末元信息
所有文章末尾统一追加一行尾注（README、卷根 00-总纲/总览 不加）。**尾注由收尾脚本统一追加，agent 无需自行添加**，避免重复。

```
---
> 🏷️ 本文属《技术知识库 · <卷名>》，重排于 2026-11。
```

其中 `<卷名>` 为该文件所在一级卷目录名（如 `17年技术经验总结`、`飞书·飞天闪客`）。空行隔开，不与正文混排。

## 二、补图规范（内联 SVG）

### 2.1 什么时候补图
- 文章讲**流程/步骤/生命周期**（如请求处理链、JVM 启动流程、Git 工作流）→ 补 1 张流程图。
- 文章讲**分类/对比/选型**（如 CPU vs GPU、Redis 持久化方式对比、隔离级别）→ 补 1 张结构/对比图。
- 文章讲**层级/架构/组成**（如存储层次、微服务分层、TCP/IP 栈）→ 补 1 张分层/架构图。
- 文章讲**状态流转**（如线程状态机、连接池状态）→ 补 1 张状态机图。
- 纯代码合集、纯配置清单、纯命令备忘、已有大量实图的文章 → **不补**。
- 一篇文章最多 2 张 SVG，宁缺毋滥；预计约 1/2 的文章适合配图。

### 2.2 SVG 模板（严格遵守）
- 插入位置：相关小节末尾或全文导语之后；SVG 前后各空一行。
- 尺寸：`viewBox="0 0 720 H"`，H 按内容 180~420；高度按节点行数计算，节点间留足间距。
- 字体统一：`font-family="'Microsoft YaHei','PingFang SC',sans-serif"`。
- 配色（与库 README 一致）：
  - 普通节点：`fill="#eff6ff" stroke="#2563eb" stroke-width="1.5"`，文字 `#1e293b`
  - 强调节点（核心结论/风险点）：`fill="#fef2f2" stroke="#dc2626"` 或 `fill="#fffbeb" stroke="#d97706"`
  - 结果/正向节点：`fill="#f0fdf4" stroke="#16a34a"`
  - 次要说明文字：`fill="#475569"`
  - 箭头连线：`stroke="#94a3b8" stroke-width="1.5"`，`marker-end` 用灰色三角
- 文字 13~15px，标题类 16px bold；每个节点文字居中（`text-anchor="middle"`）。
- 必须写 `xmlns="http://www.w3.org/2000/svg"`；SVG 内文字必须转义 `<` `>` `&`。
- SVG 上方加一行斜体图题：`*图：xxx（示意）*`。
- 同一篇文章若有多张 SVG，`marker id` 不能重复（加后缀 `arw1` `arw2`）。

## 三、工作流程

1. 逐个处理分配到的文件：Read 全文 → 按本规范重构 → Write 覆写原路径。
2. 拿不准是否该删/改的句子，一律保留原文。
3. 完成后输出逐文件一行报告：`文件名 | H1标题 | 二级小节数 | 补图:0/1/2 | 删死链:N | 备注`。
